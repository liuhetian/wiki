# 收纳分诊的维护记录

这是[收纳](../../skills/collect/index.md)背后的规则调整。执行时读 skill；需要核对来源、改动和边界时再读本页。

## 上游与版本

来源是本 wiki 自己的收纳流程，没有外部仓库、作者或许可证需要吸纳。依据 2026-11-02 的对话重构交接规则，11-06 又按对话把问题和交接拆成先后两步，都没有对应的外部 commit；同日四档命名的来由见[调研项目的记录](project-research.md#explain)。

用户先提出在分诊引用 skill 写作和 agent-io，使交接可以一次复制；随后确认将其他相关规则按任务带入。能力索引和写作规则继续由各自原页维护，收纳页只负责挑选读取路线。

## 改了什么

- 分诊增加查本站已有内容：按来源名、主题与能力检索，读目标索引和相关入口，确定新建、原地扩写、并入或复用维护记录；只做落点检查，不提前完整拆解。
- 交接代码块必须包含三组读取指令：必读规则、已确定要用的能力、按条件读取的参考。确定能用的填实具体页和小节，重复路径只列一次，整张候选依赖表不照抄。
- 覆盖调研共用证据、skill 写作、agent-io、填空与分支、界面仿真与嵌入、明确要求的配图、细讲或写书的待定取舍，以及明确要求的课程。
- 目标板块索引、已有页面和维护记录也写进交接，注明处理方式；新旧入口都使用实际仓库路径，不留下需要下一步猜的泛称。
- skill 页尾新增本维护记录的链接，维护索引和 nav 注册；收纳入口 URL 与来源、想法两个输入控件不变。
- 先问后交接（2026-11-06）：用户说「要求直接出交接文档，但我发现里面经常会问很多问题先，所以我希望改一下流程，有问题就问问题，没问题才出交接文档」。原来要题目和交接一起交，深度没答时交接只能标「待确认」草稿。改成有要用户定的，这一轮只问，不附交接和草稿；没有要问的或答完了，才给分诊理由和交接，决定全部填实。问不问由「哪些问我」表的第三列定，这一列统一写成问或不问：「会不会真的用」「下一个 skill 里的空」两行原来谁定写用户、没说时又写默认值，定为前者不问、后者只问没有默认值的；对上几支先照判法判，判不开才问。同一次按用户确认去掉重复：深度规则只留表里一处，调研项目入口改成链过来；必读规则改指依赖表前三行；「已有 skill 并进去」「写具体路径」「不替用户加配图」各留一处。description 压到 120 字内，Skills 索引的钩子同步。

## 跳过了什么

没有修改既有深度选择：未给意图时先问并等待，有关注点且未另定深度时按粗讲交接。没有把条件参考变成每次必读，没有默认加入精简检查、写作口味、配图或部署，也没有提前调用 agent-io 或增加新的用户确认轮次。

本轮只调整分诊规则及其维护入口，没有重新处理外部来源。能力接口、各档模板和具体写作语法保持在原位置维护，不复制它们的实现。

## 核对方式

检查概要收录、背面 skill 吸纳、带模型实验的粗讲三类交接：分别选择各自需要的执行页；写 skill 带写作规则；明确模型调用带具体接口；仅在可能用到时才留条件参考。资料检索、语法与校验要求沿用已有规则，不新增测试脚本或付费实验。
