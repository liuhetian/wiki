# 地点

地点精度**随流程递进**：方向阶段锁时空锚点，Look 和换装阶段给可拍区域，Shot 阶段才定微点位。前期别替 Shot 把空间锁死，后期也别把已定的具名地点泛化。

## 地点从哪来 { #precedence }

优先级从高到低：

1. 用户明确给的地点
2. 历史时代设定
3. 指定作品的世界设定
4. 原创虚构设定（只在用户明确要原创世界时）
5. 普通现代现实摄影、用户没给地点：[随机一个世界著名真实地点](#fallback)兜底

- 地点是语境，不是让人穿当地民族服装的指令
- 古装题材让所有人身处那个时代正在运转的空间，不换成今天的博物馆、遗址公园、景区或复原街区，除非用户明确要在那里拍现实照片
- 只有字面「海边」「酒店」「街头」「庭院」「古镇」「室内」「户外」「影棚」不算地点

## 第一层：方向阶段只锁时空锚点 { #anchor }

这一步只确认「到底在哪个真实世界、作品世界或原创世界里拍」，不替 Shot List 决定站位。

现代现实地点的最低要求：

- **户外**：城市 + 具体景区、街道、路线或地标；或者城市 + 真实具名的公共场所
- **室内**：优先城市 + 真实具名的酒店、建筑或公共室内；用户要私人公寓又没有可核验的房源，至少锚到一条真实街道或路线，并如实标成概念化私人室内（`conceptual_private_interior`）
- 室内只写到「巴黎第六区」「某城市中心」「某街区」，没有具体街道、具名建筑或景区，不算完成

合格的锚点长这样（这几条是示范，算 [few-shot](../requirements/reference/directions.md#few-shot)，不拿来推荐）：

- 室内：法国巴黎第六区 Saint-Germain-des-Prés 一带的 Haussmann 公寓语境（概念化私人室内）；法国巴黎的 Hôtel Lutetia
- 户外：中国杭州·西湖风景名胜区·孤山 / 北山街一带；日本京都·东山地区·八坂塔周边街区

这一步**不要强制写**：房间号、哪扇窗、哪段走廊、哪级台阶、哪一小段湖岸、人站在哪个转角。

其他时空类型：

- **历史**：确认历史地点或历史审美语境；时代会影响服装、建筑、礼仪时写明朝代和时期。不用提前定每张 Shot 的院落转角或室内节点
- **影视、游戏、动漫、文学作品**：记下作品（`source_work`）、作品里认得出的地点（`in_world_location`），相关时再记时代、章节或世界状态。不要求写到「竹影院落通向回廊的转角」「临栏平台左侧」这种 Shot 级节点
- **原创虚构**：记下世界、城市或区域 + 具名的虚构地点 + 时代或世界状态。必须是明确的虚构时空点，但不用提前锁死微空间，也不得自称是哪部作品的官方场景

## 第二层：Look 和换装阶段加可拍区域 { #zones }

时空锚点确认后，可以在里面补 2–4 个**可拍区域**，比如「酒店公共休息区 / 客房起居区 / 楼梯空间」，或「竹影院落 / 回廊 / 小轩窗内外」。

这些只是区域候选，不是 Shot 的最终落位：不提前写死每张的窗位、门口、走廊段、台阶或岸线节点，除非用户明确要求。

## 第三层：Shot 阶段定微点位 { #micro }

到 Shot List 才由每张 Shot 按构图、动作、出镜人数和叙事，在确认的锚点里自己选 `scene_area`：窗边、楼梯转角、廊柱之间、岸线某段、临栏位置、房间的某个分区。

每张 Shot 同时带两层地点：

1. 从 Look 继承的**完整时空锚点**
2. 本张新定的**具体微点位**

Shot List 是用来加空间精度的：不能只重复一个模糊的地点，也不该被前期没必要冻结的微点位绑住。

## 单向不降级 { #monotonic }

用户选过或接受过的具名场地、街道、景区、作品内地点、历史地点，之后的产物可以保留、可以细化成更宽的可拍区域、可以明确替换并写明理由，**但不能悄悄泛化**。

每处地点都要归类并继承下去：

- 执行地点锚点（`execution_location_anchor`）：打算真去拍的地方
- 参考地点锚点（`reference_location_anchor`）：拿来当视觉和空间参考、不声称是真拍摄地的具名地点
- 作品内地点锚点（`in_world_location_anchor`）：作品、历史或虚构世界里的具名地点

方向卡写过「以上海外滩 W 酒店客房类型空间为参考」，完整 Look 里就仍要写出这个参考锚点；可以说最终执行场地是另一家能合法拍摄的酒店，但不能缩成「精品酒店套房」。禁止的退化：

- 上海外滩 W 酒店客房类型空间（参考锚点） → 精品酒店套房
- 厦门鼓浪屿临海老别墅区域 → 海边民宿
- 《红楼梦》大观园·潇湘馆 → 古风庭院

## 不编造，能核验就核验 { #verify }

- 不为了「具体」而编造门牌、酒店、公寓、房号或场地，再当成事实写出来
- AI 自己推荐真实公共地点（酒店、建筑、景点、街道）时，有网页搜索能力就先核验名字和位置是否真实存在、现在是否还认得出；不能核验就标「待核验」，不把猜测写成事实
- 不假设有拍摄许可或商业许可；用户要求的场地需要许可又不知道有没有时，写「需以实际拍摄许可为准」

现实地点的核验状态只用这四个值（保存工程时脚本按它校验）：

| 值 | 意思 |
|---|---|
| `user_supplied` | 用户给的 |
| `verified_current` | 已核验，现在还在 |
| `known_public_place_needs_current_verification` | 知名公共场所，现状待核验 |
| `conceptual_private_interior` | 概念化私人室内，锚在真实街道上 |

## 没给地点：随机一个世界名胜 { #fallback }

普通现代现实摄影，用户一个地点都没给时，**不为了地点单独追问**，也不降级成「海边 / 酒店 / 街头 / 民宿 / 公寓」：

1. 先判断拍摄类型：室外、室内、私密室内、城市旅行、自然景观
2. 按主题、服装、关系、季节、隐私度，搭一个至少 6 个地点的适配池，尽量来自不同国家和地区
3. 随机选一个，立刻写成具名的地点锚点，并一路保留到完整 Look，除非用户改
4. 用户说「换地点」「再随机」就排除当前地点；别反复落在同几座城市
5. 有网页能力就核验名字和现状，许可条件不确定就写明待核验

- 户外优先著名地标、景区、海岸、历史街区、园林、山、湖或标志性城市空间
- 室内优先具名的地标建筑、标志性酒店、知名公共室内；没有可核验的私人物业时，用锚在著名真实街道或街区上的概念化私人室内
- 私房这类隐私敏感的室内题材优先标志性酒店或建筑的室内，不安排在人流密集的露天景点
- 这条兜底让位于用户明确的地点、历史时代、指定作品和原创世界，那些用自己的真实地点或作品内地点

下面是可以参考的世界著名地点谱系 —— 不是固定白名单，是防止默认地点长期落在少数几座城市：

**城市、街区、建筑外景**

- 法国巴黎：埃菲尔铁塔 / 亚历山大三世桥 / 蒙马特 / 圣日耳曼
- 意大利威尼斯：大运河与圣马可周边
- 英国伦敦：塔桥 / 诺丁山 / Somerset House 周边
- 美国纽约：Brooklyn Bridge / DUMBO / Central Park
- 日本京都：东山 / 八坂塔周边 / 岚山
- 西班牙巴塞罗那：哥特区 / Park Güell 周边
- 捷克布拉格：老城 / 查理大桥周边
- 土耳其伊斯坦布尔：博斯普鲁斯海峡沿岸 / 加拉塔周边

**海岸、湖泊、自然**

- 希腊圣托里尼
- 意大利阿马尔菲海岸 / 科莫湖
- 瑞士卢塞恩湖 / 少女峰地区
- 冰岛 Reynisfjara 黑沙滩
- 土耳其卡帕多奇亚
- 印度尼西亚巴厘岛乌布 / 悬崖海岸
- 澳大利亚悉尼港与 Bondi 海岸

**室内、酒店、建筑语境**：选和题材相容的世界著名城市里的具名酒店、历史建筑、公共室内或文化建筑，比如巴黎的历史酒店、纽约的高层设计酒店、东京的标志性高层酒店、伦敦的历史酒店、威尼斯的宫殿式酒店、上海外滩的历史建筑酒店。具体酒店名由 AI 自己提出时，照[核验规则](#verify)办。

谱系里和示范重合的锚点（巴黎圣日耳曼一带、京都东山八坂塔周边）按 few-shot 处理，不主动推荐。

## 地点卡写什么 { #location-card }

完整 Look 里的地点卡（Location Card）要有：

- 地点模式：`real_world` / `historical_real_world` / `future_landmark` / `source_work` / `original_fictional`
- 执行地点锚点（选了的话）、参考地点锚点（用了的话）
- 作品和作品内地点（适用时）
- 时代、时期、章节或世界状态（相关时）
- 室内还是户外
- 真实公共场所的核验状态
- 2–4 个可拍区域
- 对这套 Look 要紧的环境材质、建筑、天气和空间线索
- 这套服装为什么适合这个地点
