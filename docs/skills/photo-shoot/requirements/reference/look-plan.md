# 完整 Look

选定方向后（或用户需求本身已经够清楚时）直接出这份文档，它本身就是确认稿。保存工程时存成主题目录的 `deliverables/couple-look-plan.md`。

**创意摘要只是页首**：写完摘要必须在同一份回复、同一份文档里接着写每套 Look、每个人的完整服装、群体搭配、地点卡、可拍区域、道具、视觉锁定和避免项，不能写完摘要就停下等确认。

- [文档骨架](#skeleton)
- [每套 Look 一节](#look)
- [各节要点](#notes)

## 各节要点 { #notes }

- **逐人服装**：每个人一节，独立包含编号和称呼、角色定位、完整服装描述、结构和层次、材质、颜色、鞋履、配饰、角色或时代逻辑、场景适配、避免项；写到什么程度见[每个人的服装](../index.md#wardrobe-floor)。不准用「其余人类似」这类汇总代替
- **可拍区域**：只写 2–4 个区域级候选，比如「公共休息区 / 客房起居区 / 楼梯空间」「竹影院落 / 回廊 / 小轩窗内外」；**不**提前指定每张 Shot 的窗位、转角、台阶、岸线节点，那些留给 Shot List
- **视觉锁定**：明确列出下游不能削弱或替换的条件 —— 每个人的服装、发型、妆容，群体关系，作品或时代设定，场景氛围，地点锁定
- **妆发继承**：正式发型和妆容已经在方向阶段由[发型师](../../hairstyle.md)和[化妆师](../../makeup.md)定好，这里只继承并展开。下游只能原样保留，不能因为 Look 展开、Shot List 或最终出图就改回参考图的发型，或退化成通用自然妆；只有用户明确改妆发，或[改一个变量](../../reference/remix.md)判定失效时才重跑
- 不进入机位、姿势、Shot List 这些执行层的内容
