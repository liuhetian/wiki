# 方向卡

第一步必须出齐三张卡让用户挑，AI 不得替用户选定，不得跳过选向直接出图；全家福和其他多人缺总人数、性别构成或关系结构时，先一次补齐缺的再出。A/B/C 只代表方向，不代表模式。

## 格式 { #format }

每个方向一个标题，下面一个独立的 `text` 代码块，方便用户一键复制去别的生图模型出图。花括号里是要填的内容：

````markdown
### A｜{方向名}

```text
时空坐标：{明确的时代 + 真实地点，或已知作品 + 地点}
人物身份：{每个人在这个世界里的身份}
人物关系描述：{情侣和多人必填：关系结构、角色层级、互动基础}
核心场景：{3–5 个具体可拍的空间}
{P01 的称呼}服装：{这个人独立的服装}
{P02 的称呼}服装：{这个人独立的服装}
{P01 的称呼}发型定稿：{发型师给出的具体结果}
{P01 的称呼}妆容定稿：{化妆师给出的具体结果}
{P02 的称呼}发型定稿：{……}
{P02 的称呼}妆容定稿：{……}
色彩 / 光线：{主色关系 + 光源逻辑}
人物状态：{能执行的动作或关系事件}
摄影语言：{景别、机位、构图、镜头观察方式}
出8宫格图片。
```

### B｜{方向名}

（同样结构的代码块）

### C｜{方向名}

（同样结构的代码块）
````

三张卡之后只留这一句：

```text
可直接点击上方任意方案代码块一键复制提示词自行出图；或回复 A / B / C，我直接为你生成该方案的 8 宫格图片；也可以回复“抽卡”。
```

## 写法 { #rules }

- 字段名和值写在同一行，用中文冒号；字段之间不空行；每项写短句，不写解释性的长段落；三张卡之间可以空一行
- 方向标题可以用故事卡名，但时空坐标那一行照样写清地点、时代或作品
- 单人卡可以省掉人物关系描述
- `出8宫格图片。` 不是一个键值字段，是直接接在方案末尾的一句出图指令

### 逐人服装 { #wardrobe-fields }

- 情侣默认两行：`女方服装：……`、`男方服装：……`
- 多人按确认过的角色名或编号每人一行：`P01｜新娘服装：……`；人数超过 2 就继续逐人往下写
- 不准用一个合并的「服装造型」字段代替逐人服装；共享色盘或材质逻辑时，也要逐人写具体服装和差异

### 逐人发型和妆容 { #styling-fields }

- 每张卡展示前先跑[发型师](../../hairstyle.md)，再跑[化妆师](../../makeup.md)
- 每个人至少两行：`{称呼}发型定稿：……`、`{称呼}妆容定稿：……`；情侣可以用「女方」「男方」
- 这是这个方向的正式结果，不是占位词：用户选中后下游出图直接继承，不再设计
- 女性妆容默认白皙柔焦影楼精修；用户明确要求别的时照用户的

### 人物关系描述 { #relationship }

- 情侣和所有多人拍摄必填
- 写关系结构、角色层级和互动基础，不能只写「情侣」「家人」「朋友」；情侣要按当前方向写双方的关系状态、熟悉程度和角色动态
- 多人要覆盖成员关系、角色层级、核心和次核心关系或子群结构
- 不套固定的关系示例，按当前主题动态生成

## 展示前的硬门槛 { #gates }

- A/B：两个现代现实世界的著名真实地点，彼此地域和空间差异明显
- C：古代、未来化的现实地标，或已知作品 + 明确地点
- 三张都通过 [few-shot 隔离](directions.md#few-shot)
- 不拿纯风格卡顶替时空锚点
