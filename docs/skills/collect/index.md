# 收纳

你当前的工作区就是本 wiki 的仓库。这一步只分诊，不建文件、不改文件：有要我定的先问我，等我答完；没有要问的，才交出一份交接 prompt，我改好了交给下一个 agent 照做。

## 先看来源

看到能分诊为止：README、目录结构，有 `SKILL.md` 先读它。只判断它该进哪、有多重，不讲解、不拆设计，那是下一个 skill 的事。记下体量和更新频率：文件数、代码量、最近几个版本隔多久。

## 再查本站已有内容 { #existing }

按来源名、主题和能力搜索本站，再读目标板块索引与最相关的现有页面入口，看到能决定新建、扩写或并入为止。同一项目沿用原目录和入口，已有同来源维护记录的复用。活例：[wenai](../../projects/wenai/index.md)从概要扩为粗讲，入口没有换地址。

把查到的目标索引、已有页面、可并入的 skill 和同来源维护记录的具体路径写进交接，并说明“原地扩写”“并入”或“复用记录”。没有找到就明确写“未找到，按指定路径新建”，不要让下一个 agent 再猜一遍；导航位置同时看 `mkdocs.yml`。这里只核对落点与可复用入口，不提前做下一步的全文调研。

## 分诊：正面、背面分开判 { #tree }

不是在几个板块里挑一个。**正面**是从通用到具体那根轴上的四层，人和 AI 都读，收它讲清了什么；**背面**是 skill，给 AI 照着做，收 agent 能照着做的执行方式。两面各判各的，一个来源可以两边都收，也可以只收一边。来源不算数：自己做的、别人做的一样判。

### 正面：落在轴上哪一层 { #article-line }

```text
它是什么？
│
├─ 整个来源：论坛、人、合集、工具站 ────────→ 收藏夹（轴外），只存链接，按形态进 docs/bookmarks/ 的分类页
├─ 一门学问，为了学会 ──────────────────────→ 笔记，按领域进 notes/ 的分类
│   └─ 视频、图文帖 ────────────────────────→ 照 docs/skills/video-note/index.md
├─ 现成的东西，不用提问题就能挑 ────────────→ Gallery，照 docs/skills/collect/gallery.md
├─ 一个通用问题，几种方案 ──────────────────→ 文章，照 docs/skills/wiki-guide/index.md 写
└─ 一个具体的东西：仓库、软件 ──────────────→ 项目，照 docs/skills/project-research/index.md 的表挑概要、粗讲、细讲或写书
```

对上几支时这样判，还分不开就把候选都摆给我：

- 收藏夹还是进轴：整个来源只存一个链接加一句为什么收，在收藏夹；要写成页面，就按层进轴。一个论坛里拆出几样，各按层落，收藏夹那条补上「拆出过」；单篇帖子不写成页面就不收
- 笔记还是文章：学会一门学问、能自己往下推的是笔记；知道一个问题该怎么办的是文章
- Gallery 还是文章：挑一件不用讲理由，是 Gallery 的一条；要讲几种方案各适合什么，是文章
- 文章还是项目：一个问题、几种方案、换个项目照样成立的是文章，横向对照几个项目、选型也是；一个具体的东西、每个问题只留它那一种的是项目
- 一个仓库，要它的效果还是弄懂它：前者进 Gallery，有上游仓库、能直接用的效果照[收进 Gallery](gallery.md)极简收；后者进项目，按想了解的程度选概要、粗讲、细讲或写书
- 写书看角度：从零复刻、做实验是具体的东西，进项目；领域对比讲一个领域问题的几种解法，进文章

### 背面：agent 能照着做什么 { #skill-line }

```text
有没有 agent 能照着做的执行方式？
│
├─ 来源本身是 skill、插件、提示词合集 ──────→ 照 docs/skills/collect/skill.md 收
├─ 教程、视频、正面讲清的做法 ──────────────→ 照着做一遍，提炼成守则加脚本，新写或并进已有的 skill，照 docs/skills/collect/skill.md 的「教程」一节
├─ 经中转接一家 API ────────────────────────→ docs/skills/agent-io/index.md 加一个能力
└─ skill 要按编号查的参数：风格、画风、版型 ─→ 放进 Gallery，skill 按编号查
```

- 守则进 skill，参数进 Gallery：一段 prompt、一个色号、一种版式是 Gallery 的一条，一套怎么做是 skill
- 已有 skill 管得了的，并进去，不另起一个

### 两面怎么接 { #link }

两边怎么互链照写作规范「内容放哪个板块」末尾两条；维护不是第三面，记录写在哪照本页的[维护记录](#maintenance-record)。

## 哪些问我 { #ask }

| 要定的 | 谁定 | 我没说时 |
|---|---|---|
| 正面、背面各收不收 | 我 | 问：两面都给推荐，收的写落哪、为什么，不收的也说一句为什么 |
| 每面落哪 | 照[判法](#tree)判得开的你定，判不开的我 | 判得开的不问；判不开的问：候选都摆出来，给推荐和理由 |
| 收多深 | 我 | 问：「只是收集概要，还是有特别感兴趣的点」，没答就接着问，不自行选概要或粗讲。只要概要就用概要；我答了关注点、没另说深度的按粗讲，不追加确认；明确要学设计或写书的按指定档位。规模和复杂度只作推荐理由；大型 skill 仓库的背面收多少照[收纳 skill](skill.md#heavy) |
| 侧重哪块、最想知道什么 | 我 | 问，和深度一起问：列两三个关注点候选，加一个「只收概要」 |
| 会不会真的用：部署、接进自己的项目 | 我 | 不问：当不用 |
| 下一个 skill 里的空 | 能从来源定的你填，属于我判断的我 | 属于我判断的：有默认值的不问，照默认填；没有默认值的问 |
| 板块里的位置、文件路径 | 你 | 不问：写进交接，我看交接时改 |

- 要问的一次问完，每题带推荐和一句理由，我答「对」或者改一句就行；推荐不算我答过
- 只问上表几件；下一个 skill 读透来源才问得了的，比如细讲的 baseline 和功能线、写书的目录，留给它自己盘问
- 下一个 skill 多半是一段带填空的 prompt，源文件里是 `<input>`、`<select>` 这些标签，`data-when` 包着的是按某个空取舍的段落。概要、粗讲、细讲、写书里「要不要收纳进本 wiki」这个开关，走到这里一律是「是」

## 交出什么 { #handoff }

看完来源、查过本站，按[上表](#ask)看还有没有要我定的，分两种交：

1. **有要问的**：这一轮只问，照上一节问，不附交接，也不附草稿；我答完再往下走
2. **没有要问的，或者我答完了**：先用几句话说为什么这么分 —— 每面收不收、为什么进这个板块、为什么用这个 skill、为什么收这么深、哪些不收，问过我的不再讲；理由只给我看，不进交接，下一个 agent 照做用不上。再交出**交接 prompt**：放进一个 `text` 代码块，决定全部填实，归你定的照你的判断填，我改完原样贴给下一个 agent。它没看过这次对话，所以写全：
    - 你当前的工作区就是本 wiki 的仓库；按下节组织「必读规则」「已确定要用的能力」「按条件读取的参考」，把读取指令与路径全写在这个代码块里，一次复制即可交接
    - 来源：地址，一句话说它是什么
    - 两面都收的分两节写，各写：照哪一页收（仓库里的路径）、收到哪（落地路径）、收多深和侧重什么、下一个 skill 里的空（「空名：值」）
    - [查过的本站入口](#existing)：目标索引、需要扩写或并入的页面、复用的维护记录和导航分组，给具体路径与处理方式
    - 两边怎么互链，维护记录写在哪
    - 这次特有的收什么、不收什么；下一个 skill、共用规矩和写作规范里写过的不重复

我说「照这个做」，就在这次对话里按交接做。

### 交接要带哪些读取指令 { #dependencies }

**按本次任务挑依赖，不把下面整张表抄进每份交接。** 分诊时确定读取路线，不执行接口或提前读透所有参考；已确定要做的事写具体页与小节，还不能确定的才写“需要做什么时，先读什么”。活例：[wenai 的记忆实验](../../maintenance/projects/wenai.md#experiment)需要调用模型，交接可明确指定本站 DeepSeek 接口，不必再让执行者找服务。

代码块里的读取指令分三组，重复路径只列一次：

1. **必读规则**：下表前三行，本次用得上的都列。
2. **已确定要用的能力**：列这次确实需要调用的能力和对应接口，说明用来做什么。走 agent-io 时先读入口、再读已选接口，有现成脚本优先使用；仅计划实跑、尚不知是否要调用模型的，留到条件参考。
3. **按条件读取的参考**：只列本任务可能遇到的情况及其读取路径；没有相关项写“无”。

| 本次工作需要什么 | 写入交接的读取路径与条件 |
|---|---|
| 任一收纳任务 | [写作规范](../wiki-guide/index.md)、本页[共用规矩](#shared)、选定的收纳或写作执行页；代码块中写实际仓库路径 |
| 概要、粗讲、细讲或写书 | `docs/skills/project-research/index.md` 的[共用证据规则](../project-research/index.md#evidence)，以及选定的具体子 skill |
| 新写或修改 skill | `docs/skills/wiki-guide/skill.md`（[写 skill](../wiki-guide/skill.md)）；外部吸纳还读 `docs/skills/collect/skill.md` |
| 搜索、读媒体、调模型、生成素材 | `docs/skills/agent-io/index.md`（[能力表](../agent-io/index.md)），能选定的进一步给具体接口页；还不能选定的写“用到对应能力时按能力表读接口” |
| 给 prompt 增加填空或选项 | `docs/skills/wiki-guide/reference/components.md` 的[填空](../wiki-guide/reference/components.md#fill)；需要条件段落再读 `docs/skills/wiki-guide/reference/branch.md`（[分支](../wiki-guide/reference/branch.md)） |
| 展示软件界面或嵌入演示 | `docs/skills/wiki-guide/reference/components.md` 的[仿真展示](../wiki-guide/reference/components.md#showcase-demo)或[嵌入交互单页](../wiki-guide/reference/components.md#iframe-demo)，按实际要做的选小节 |
| 用户明确要求配图 | `docs/skills/wiki-guide/reference/infographic.md`（[配图](../wiki-guide/reference/infographic.md)）；没有这项要求，不添加生成配图的任务 |
| 细讲或写书仍有取舍待定 | `docs/skills/grilling.md`（[盘问我](../grilling.md)）；只问尚未确定的 baseline、功能线、侧重或目录，已确认的不再问 |
| 明确写成课程 | `docs/skills/wiki-guide/course.md`（[课程页](../wiki-guide/course.md)）；普通笔记不自动套课程骨架 |

精简检查和写作口味只有用户指定才加入；收尾校验沿用写作规范，不复制整套校验说明。

## 共用规矩 { #shared }

交接之后照哪一页收 —— 收纳 skill、收进 Gallery、调研项目、整理视频为笔记 —— 动手前都先读[写作规范](../wiki-guide/index.md)和这一节。

### 外部材料 { #material }

- **别人的图和视频直接收原件**：本 wiki 自己看、不商用，忠实记录比避嫌要紧，不为避嫌改成自己重新生成；作者和出处写进维护记录或脚注 —— 活例：[二次元平面设计风格](../../gallery/images/linux-do-style/gallery-anime-graphic-design.md)的 23 张配图原样存档
- **外部仓库只取用得上的文件**：进 `assets/` 的只有页面用得上的 —— demo 跑起来要的、正文 `--8<--` 引到的，其余不收、链上游；上游的设计文档、README 不整篇嵌，摘句加脚注；没人引的源码存档 check-links 会拦 —— 活例：[梨园](../../projects/liyuan/index.md)的 `liyuan-src/`。吸纳的 skill 例外，要收齐才能跑，见[收纳 skill](skill.md)
- **读的哪个版本只记一次**：写进维护记录，正文不逐处标版本；不建维护记录的写进脚注

### 维护记录 { #maintenance-record }

页面只写怎么用；从哪来、改了什么写进[维护](../../maintenance/index.md)。一个来源两面都收的，记录只写一篇 —— 活例：[手绘风格出图](../../maintenance/skills/handdraw.md)，skill 和 Gallery 三区的收录写在同一篇。

| 收的是 | 记录写在 | 一篇管 |
|---|---|---|
| skill | `maintenance/skills/<名字>.md`，挂进维护的「Skill 吸纳」 | 一个 skill |
| Gallery | `maintenance/gallery/<名字>.md`，挂进「Gallery 收录」；单条收的并进该类零散收集那篇 | 一个来源；极简收的不建 |
| 粗讲、细讲、项目类写书 | `maintenance/projects/<名字>.md`，挂进「项目」 | 一个项目；独立概要不建，来源和版本放脚注 |

记录写四样：

- **上游**：仓库、作者、许可证，原文里提到的出处也写在这
- **commit**：一句话，钉在哪个 commit、哪天
- **跳过了什么**
- **翻译之外的改动**

项目的记录另加两样：源码存档和行号怎么对上，实验怎么跑、脚本附后。skill 页尾怎么链过来，见[写 skill](../wiki-guide/skill.md#maintenance-record)。
