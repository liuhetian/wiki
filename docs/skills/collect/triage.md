你当前的工作区就是本 wiki 的仓库。这一轮只分诊，不建文件、不改文件：交出一份交接 prompt，我改好了交给下一个 agent 照做。

## 先看来源

看到能分诊为止：README、目录结构，有 `SKILL.md` 先读它。只判断它该进哪、有多重，不讲解、不拆设计，那是下一个 skill 的事。记下体量和更新频率：文件数、代码量、最近几个版本隔多久。

## 分诊：正面、背面分开判 { #tree }

不是在几个板块里挑一个。**正面**是从通用到具体那根轴上的四层，人和 AI 都读，收它讲清了什么；**背面**是 skill，给 AI 照着做，收 agent 能照着做的执行方式。两面各判各的，一个来源可以两边都收，也可以只收一边。来源不算数：自己做的、别人做的一样判。

### 正面：落在轴上哪一层 { #article-line }

```text
它是什么？
│
├─ 外面的站点、论坛、合集，只存链接 ────────→ 收藏夹（轴外），docs/bookmarks/index.md 加一条
├─ 一门学问，为了学会 ──────────────────────→ 笔记，按领域进 notes/ 的分类
│   └─ 视频、图文帖 ────────────────────────→ 照 docs/skills/video-note/index.md
├─ 现成的东西，不用提问题就能挑 ────────────→ Gallery，照 docs/skills/collect/gallery.md
├─ 一个通用问题，几种方案 ──────────────────→ 文章，照 docs/skills/wiki-guide/index.md 写
└─ 一个具体的东西：仓库、软件 ──────────────→ 项目，照 docs/skills/project-research/index.md 的表挑粗讲、细讲或写书
```

对上几支时这样判，还分不开就把候选都摆给我：

- 收藏夹还是进轴：只存一个链接加一句为什么收，在收藏夹；要写成页面，就按层进轴。一个论坛里拆出几样，各按层落
- 笔记还是文章：学会一门学问、能自己往下推的是笔记；知道一个问题该怎么办的是文章
- Gallery 还是文章：挑一件不用讲理由，是 Gallery 的一条；要讲几种方案各适合什么，是文章
- 文章还是项目：一个问题、几种方案、换个项目照样成立的是文章，横向对照几个项目、选型也是；一个具体的东西、每个问题只留它那一种的是项目
- 一个仓库，要它的效果还是弄懂它：前者进 Gallery，有上游仓库、能直接用的效果极简收；后者进项目，粗讲一页或细讲一组
- 写书看角度：从零复刻、做实验是具体的东西，进项目；领域对比讲一个领域问题的几种解法，进文章

### 背面：agent 能照着做什么 { #skill-line }

```text
有没有 agent 能照着做的执行方式？
│
├─ 来源本身是 skill、插件、提示词合集 ──────→ 照 docs/skills/collect/skill.md 收
├─ 教程、视频、正面讲清的做法 ──────────────→ 照着做一遍，提炼成守则加脚本，新写或并进已有的 skill，照 docs/skills/collect/skill.md 的「教程」一节
├─ 经中转接一家 API ────────────────────────→ docs/skills/agent-io/index.md 加一个能力
└─ skill 要按编号查的参数：风格、画风、版型 ─→ 放进 Gallery，skill 按编号查
```

- 守则进 skill，参数进 Gallery：一段 prompt、一个色号、一种版式是 Gallery 的一条，一套怎么做是 skill
- 已有 skill 管得了的，并进去，不另起一个

### 两面怎么接 { #link }

两边怎么互链照写作规范「内容放哪个板块」末尾两条；维护不是第三面，记录写在哪照收纳的[共用规矩](index.md#maintenance-record)。

## 哪些问我 { #ask }

| 要定的 | 谁定 | 我没说时 |
|---|---|---|
| 正面、背面各收不收 | 我 | 两面都给推荐：收的写落哪、为什么，不收的也说一句为什么 |
| 每面落哪 | 只对上一支你定；对上几支，问我 | 给推荐和理由 |
| 收多深 | 我 | 最浅：仓库用粗讲，进项目；脚本重、更新快的 skill 仓库，背面只收入口，能单独用的子 skill、能进 Gallery 的目录由收纳 skill 列给我挑（见[收纳 skill 的「大型 skill 仓库」](skill.md#heavy)），正面配一篇粗讲 |
| 侧重哪块、最想知道什么 | 我 | 你看完列两三个候选，问我挑 |
| 会不会真的用：部署、接进自己的项目 | 我 | 当不用 |
| 下一个 skill 里的空 | 能从来源定的你填，属于我判断的问我 | 照它的默认值 |
| 板块里的位置、文件路径 | 你 | 写进交接，我看交接时改 |

- 一次问完，每题带推荐和一句理由，我答「对」或者改一句就行
- 这一轮只问上表几件；下一个 skill 读透来源才问得了的，比如细讲的 baseline 和功能线、写书的目录，留给它自己盘问。交接里定了的，它不再问
- 一面对上几支的，把候选都摆出来，别自己挑一支往下写
- 下一个 skill 多半是一段带填空的 prompt，源文件里是 `<input>`、`<select>` 这些标签，`data-when` 包着的是按某个空取舍的段落。粗讲、细讲、写书里「要不要收纳进本 wiki」这个开关，走到这里一律是「是」

## 交出什么 { #handoff }

两段，先给我看的，后给下一个 agent 的：

1. **给我看的**：要问的几题，每题带推荐；再用几句话说为什么这么分 —— 每面收不收、为什么进这个板块、为什么用这个 skill、为什么收这么深、哪些不收。理由只给我看，不进交接，下一个 agent 照做用不上
2. **交接 prompt**：放进一个 `text` 代码块，问题按推荐先答好写进去，我改完原样贴给下一个 agent。它没看过这次对话，所以写全：
    - 你当前的工作区就是本 wiki 的仓库，先读 `docs/skills/wiki-guide/index.md` 和 `docs/skills/collect/index.md`（收纳的共用规矩），再读下一个 skill
    - 来源：地址，一句话说它是什么
    - 两面都收的分两节写，各写：照哪一页收（仓库里的路径）、收到哪（落地路径）、收多深和侧重什么、下一个 skill 里的空（「空名：值」）
    - 两边怎么互链，维护记录写在哪
    - 这次特有的收什么、不收什么；下一个 skill、收纳和写作规范里写过的不重复

我说「照这个做」，就在这次对话里按交接做。
