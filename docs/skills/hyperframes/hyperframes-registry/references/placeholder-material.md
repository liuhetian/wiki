# 占位材质

registry 条目附带替身内容：放用户截图的地方是一个矩形，放他们数字的地方是一根柱子，放他们队友头像的地方是一个圆片。这种替身内容就是**占位材质**，而且它是单色的。没有色相，没有彩色色阶，没有从紫到蓝的斜向填充。

之所以有这条规则，是因为占位颜色总是随意定的。一张紫罗兰色的卡片、一个蓝色的 logo 方块、一排彩虹色的头像，都在宣示一个 composition 本身并不具备的品牌；在 250 个条目里反复出现，同样三种随意的色相就成了 catalog 的身份，而不是作者的身份。在这里，颜色想表达的一切，明度都能表达，而且表达得更真实。

## 唯一的规则

> 占位内容不带色相。它由 composition 自身文字颜色（ink）的四个 alpha 台阶叠在 composition 自身底色上构成，外加一条细线。强调色每个 composition 只标记一个元素，而且绝不用于占位内容。

## 色阶

四个填充台阶加一条细线。它们全都是 ink 加一个 alpha，所以在深色主题上色阶会自动反转，不需要第二张表。

| 台阶 | Ink alpha | 用途 |
| ------ | --------- | ---------------------------------------------------------------------------- |
| `ink`  | 100%      | 真实内容：标题、数字、标签。不是占位内容。 |
| `L1`   | 72%       | 主体。图表柱子、实心的 logo 标志、播放图标、最前面的头像。 |
| `L2`   | 45%       | 辅助。对比用的数据序列、排在最前面那个后面的头像、次要图标。 |
| `L3`   | 18%       | 媒体填充和骨架文字线。表示"这里放内容"。 |
| `L4`   | 8%        | 凹陷底板的内部。卡片所在的托盘。 |
| `hair` | 14%       | 每一条 1px 边界。取代原本由渐变边缘承担的分隔作用。 |

按文件里已有的颜色写法来写它们：

```css
/* theme-token primitives (--fg / --surface available) */
background: color-mix(in srgb, var(--fg, #f8fafc) 18%, transparent);

/* fixed-palette ports (local --hf-ink, no theme tokens) */
background: rgba(17, 24, 39, 0.18);
```

**四个台阶，不是八个。** 相邻台阶靠得太近时灰色会发浑，所以每个台阶的 alpha 至少是下一级的 1.6 倍。想要第五个值，就说明需要改的是布局，而不是色板。改为吸附到最近的台阶。

对比度在两种随附的底色上测量（`neutral` 浅色 `#fcfcfd`，`bold` 深色 `#1b1230`）：L1 为 7.7:1 / 8.9:1，L2 为 3.1:1 / 4.4:1，L3 和 L4 按设计低于 3:1。因此**文字绝不低于 L1**，而任何观众需要做比较的图形（一条数据序列、一个状态指示）以 L2 为下限。L3 和 L4 只用于表面。

## 不靠颜色的层次感

按优先级排列。用第一个奏效的。

1. **明度台阶。** 任何东西都不和它的底色处于同一台阶。至少隔开一个完整台阶。光这一条就能解决大部分层叠问题。
2. **细线。** 每个底板边界上加 `1px` 的 `hair`。边框分隔两个表面比渐变干净得多，而且能扛住会吃掉柔和边缘的视频压缩。
3. **留白。** 内边距就是高度。一个内部有 `--space-2` 的底板，完全不需要填充差异，看起来就是凸起的。
4. **纹理，只用最细的颗粒。** 一个 `L3` 及以下、周期 2–4px、无彩色的 `repeating-linear-gradient`。这是明度唯一表达不了的东西：一个平涂的灰色矩形看起来是个空盒子，同一个矩形加上细密的排线，看起来就是一个上面有内容的表面。只用它来标示媒体，别的不用。

阴影是允许的，但必须是无彩色、弥散的：`0 Npx 3Npx rgba(0,0,0,0.18)`。绝不用彩色辉光；辉光就是穿着阴影外衣的强调色。

## 用黑白来表达每一种类型

一个灰色矩形仍然得让人看出它是*屏幕*而不是*图片*。原本由色相勉强承担的意义，改由形状、宽高比、图标和纹理来承担。

| 类型 | 特征 |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 屏幕 / 设备 | 设备宽高比 + `--radius` + `hair` + L3 的扫描线纹理 + 内暗角。外框才是信号；填充是 L3，保持安静。 |
| 视频素材 | 屏幕特征，再加上居中的、L1 圆环里的播放三角。正是这个图标让它成为视频而不是静态屏幕。 |
| 图片 | 4:3 或 3:2 的 L3 底板，带一个 L2 的地平线加圆盘图标，偏向某个角落，绝不居中。偏移才让人看出是"照片"。 |
| 卡片 | L4 底板，`hair` 边框，两条 L3 的骨架线（宽 100% 和 62%）。两条不等长的线就是全部的惯用表达。 |
| 头像 / 人物 | L2 的**圆形**，用底色镂空出姓名首字母。叠放时靠台阶区分（L1 在前，然后 L2、L3），绝不靠色相。 |
| Logo / 品牌 | L1 的**圆角方形**，用底色镂空出标志。所有标志处于同一台阶：一面 logo 墙表达的是"很多、平等"。 |
| 图表数据序列 | 平涂填充。主序列 L1，对比序列 L2，网格线 `hair`。柱子内部绝不用渐变。 |
| 文本块 | L3 的圆角线条，宽度 100 / 86 / 62%。参差不齐的右边缘才让人看出是正文。 |

圆形代表人，圆角方形代表应用或品牌。让这两种形状保持区分，才使它们能处在同一明度台阶上而不产生歧义。

为什么柱子内部不用渐变：从亮到暗的纵向填充会让每根柱子顶部更亮，于是最高的那根柱子恰恰在视线落下去比较高度的地方显得*最淡*。装饰和数据相互矛盾。平涂填充既更朴素，也更诚实。

## 强调色

accent 枚举保留。`green` 走 `--brand`，`blue` 走 `--accent`，`violet` 走 `--accent-2`，和以前完全一样，每个已声明的 `accent` 或 `tone` 变量都照常工作、不作改动。变的是强调色允许落在哪里：

> 强调色每个 composition 最多标记**一个**元素，而且只用在强调色本身*就是*意义的地方：被选中的档位、当前步骤、计数动画最终停下的数字、正在绘制的描边的颜色。占位内容绝不使用强调色。

固定色板的移植版没有主题 token，所以它们通过自己的变量获取强调色，并带一个中性的回退值：

```css
/* was: --hf-accent: #2563eb; */
--hf-accent: var(--accent, #18181b);
```

没有主题时，条目以纯黑白渲染。把它放进一个有主题的 composition，作者的强调色就会落在那一个元素上，别处都没有。当强调色由枚举选择时，查找表映射到 token，绝不映射到十六进制值：`green` 映射到 `var(--brand, <neutral>)`，`blue` 映射到 `var(--accent, <neutral>)`，`violet` 映射到 `var(--accent-2, <neutral>)`。枚举声明的选项和默认值都不变，所以不会有任何挂载出问题。

"一个元素"指的是一个角色，不是一个节点：同一个模拟画面里、三台设备上重复出现的应用标志，仍然算一个元素。

另一个选项是彻底干掉强调色，那更糟。在强调色用得正确的那些场景里，它本来就承载着意义，而且它是作者用来体现自己品牌的唯一抓手；去掉它，就会把那些场景推向明度上的取巧手段，而这件事用一个色相标记一个元素本可以做得更好。问题从来不在于强调色的存在，而在于强调色成了每个占位内容的默认填充。把它限制在一个元素上，就能修好这个问题，而且无需迁移任何变量。

## 保留下来的渐变

禁的是**承载色相的填充**，不是这个 CSS 函数本身。下面这些是材质，不是占位内容，把它们压平会破坏条目存在的意义：

- **物理表面** —— 设备边框、拉丝金属、玻璃、屏幕的内暗角。
- **光泽和扫光** —— 驱动着扫过元素的 `linear-gradient(90deg, transparent, rgba(255,255,255,0.75), transparent)`。那是运动，不是装饰。
- **遮罩和暗角** —— 为了让文字在媒体上有足够对比度而用的 `rgba(0,0,0,α)` 渐变。
- **以渐变为主体的效果** —— 极光、液态玻璃、色差、颗粒场、shader 转场。渐变就是产品本身。

这四类都是无彩色的，或者有物理上的依据。如果一个渐变两者都不是，它就是占位糊弄，必须去掉。
