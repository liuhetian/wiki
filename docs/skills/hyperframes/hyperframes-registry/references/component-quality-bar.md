# Component 质量门槛

catalog 里的 component 必须达到什么程度，我们才会继续发布它。这里的每一条标准都来自在这个分支上发现并核实过的缺陷，而不是来自个人品味。

registry component 是一个动效原语，作者把它安装进自己的 composition 并随之发布。catalog 页面是营销；安装下来的文件才是产品。因此下面的每条标准都针对**条目自己的 `<name>.html`、单独挂载**来评估，绝不针对 `demo.html`，也绝不针对 catalog 页面，因为这两者都带着作者拿不到的脚手架。

在审核、打分或砍掉任何东西之前先读这份文档。它的存在，是为了让好几个人并行审核时，对同一个条目得出同样的结论。

## 唯一的规则

> 一个条目要配得上它的位置，必须满足：作者安装的那个文件，单独挂载在它设计时所针对的底色上，渲染出了它名字所承诺的主体，并且按它描述所说的方式运动。凡是不满足这一点、而且无法修成一个其他条目尚未实现的东西的，一律移除。

## 审核如何进行

分两轮，按这个顺序。机械轮不花成本，几秒钟就能跑完所有条目；视觉轮要花一个浏览器和一双眼睛，所以只花在机械轮判定不了的东西上。机械信号只是**候选**，绝不是结论。

| 轮次 | 成本 | 判定内容 |
| -------------- | -------------- | ---------------------------------------------------------------------------------------- |
| **机械轮** | grep 和哈希 | 重复、缺 timeline、禁用的十六进制色值、空标记、名不副实、无界变量 |
| **视觉轮** | 渲染和肉眼 | 能否渲染出东西、是否实现了自己的描述、是否清晰可读、是否确定性 |

`hyperframes check` 不是视觉闸门。什么都渲染不出来的 composition 它也会放行：一张空白的画面不会产生错误、警告或布局问题，因为空渲染也是合法的渲染。下面任何一条标准都不能只依赖 `check`。

### 挂载用的测试外壳（harness）

一个正常工作的条目有三种方式会得出错误结论，三种都是 harness 的锅。按下面的方式搭外壳，否则审核会凭空造出缺陷。

1. **两种形态的条目，两种挂载方式。** 如果文件去掉 HTML 注释后包含 `data-composition-id`，它就是 sub-composition：在一个 clip 上用 `data-composition-src="./<name>.html"` 挂载它。如果不包含，它就是片段：把它内联粘贴进一个 `class="clip"` 的 div 里。把 sub-composition 内联进来，等于在文档里嵌套文档，会渲染成全黑，看起来和一个坏掉的条目一模一样。
2. **用条目自己的底色。** 从它的 `demo.html` 的 body 规则里取背景。一个文字颜色默认为 `#18181b` 的片段，在它自己的 `#f7f7f8` 上是 16:1 的醒目标题，放到深色舞台上就成了 1.5:1、看不见的一团污迹。舞台不能作为证据。
3. **加载 GSAP 并注册一个暂停的根 timeline**，然后用 `hyperframes snapshot . --at 0.05,1.2,2.5,4.0 --no-end` 截图，查看拼版图（contact sheet）。

一个条目自身的 `data-duration` 比外壳短时，最后几帧会是空白的。那是算术问题，不是缺陷。

## 致命：移除该条目

致命的意思是缺陷之下没有任何值得保留的东西：除非改写成另一个条目，否则没有任何修改能修好它，或者修好之后得到的东西 catalog 里已经有了。必须引用所列的证据；没有证据的致命结论不算数。

**F1. 没有实现自己的描述。** 标记里找不到任何与条目名称和描述所指主体相关的痕迹。不是"渲染得很差"，而是"这个东西在文件里根本不存在"。`ecosystem-constellation`、`hero-device-assemble` 和 `terminal-to-browser-deploy` 是同一个文件，装着空的卡片 div，只是标题不同。*检查*：读标记，然后把名字换成任何别的条目的名字。如果文件里没有任何东西需要跟着改，那这个名字只是贴在一个通用外壳上的标签。*证据*：所称的主体没有对应元素（星座图里没有节点，终端部署里没有终端）。

**F2. 冗余重复。** 与另一个保留下来的条目有相同的**动效指纹**和相同的**标记骨架**。指纹是把选择器中性化之后的 gsap 调用列表，保留属性、时长和 ease；骨架是去掉 class 和文字之后的标签序列。目前有一个擦除效果以相同的属性、时长和 easing 发布了八次；一个逐词错开（word-stagger）发布了七次。*证据*：两个哈希都与某个同组条目一致，而且那个同组条目在下面的决胜规则中胜出。

**F3. 什么都渲染不出来。** 在条目正确挂载于自己的底色上、并且应用了它的配方的情况下，画面是空白的，或者所称的主体从未出现。*证据*：四帧空白画面，加上原因，而且原因在条目本身而不在 harness：缺了一个同级素材文件、控制台里有 `ReferenceError`、主体从未进入 viewport。如果是帧捕获的瑕疵、在实时页面里渲染正常，那就是误报，所以记录之前先在真实页面上确认。

**F4. 描述说的是另一个条目。** 画面显示承诺的事件从未发生：一个擦除始终没有露出第二块面板，一个图表一条数据序列都没画出来。这不是措辞上的出入。

**F5. 无法做到可 seek。** 第 N 帧确实依赖第 N-1 帧，既没有闭式解，也没有有界的重放，而要让它可 seek 就会把它变成另一种效果。很少见。大多数累加器都有简单的改写方式，所以只有在确定没有改写方式之后才动用这一条；用带种子、从索引推导的值替换 `Math.random()` 属于 X7，不属于 F5。*证据*：经由不同的 seek 路径到达同一时间点，得到的两张截图不同。

## 可修复：保留并修复

确实是缺陷，但这个条目有其他东西覆盖不了的存在理由，而且修复工作量有限。记录具体的修复方法，绝不能只写"需要打磨"。

**X1. 没有自己的 timeline。** 没有 `__timelines` 注册，所以安装下来的成品渲染出来是一帧静止画面，而 catalog 页面看起来却没问题，因为生成器会把 demo 的 timeline 移植到预览里。213 个新 component 中有 97 个处于这种状态。*修复*：把末尾的 `Timeline integration:` 配方折进一个真正的 `<script>`，构建一个暂停的 timeline 并注册它。单元素条目大约需要 10 到 15 分钟。只有当完全没有可折进来的运动时才*升级为致命*，而那通常也意味着 F1。

**X2. 名字声称用了代码里没有的技术。** grep 代码区域，绝不要 grep 文档头部：头部的说明文字里满是你要找的那些词，会在一个根本没有该技术的条目上报出匹配。
| 名字模式 | 必须包含 |
| -------------------------------- | -------------------------------------------------- |
| `spring-*` | `elastic`、`back.`、`bounce` 或自定义的 spring ease |
| `mask-*`, `*-mask*` | `mask` 或 `clip-path` |
| `frosted*`, `*glass*` | `backdrop-filter` |
| `*3d*`, `*depth*`, `*orbit*`, `*camera*` | `perspective`、`rotateX`、`rotateY`、`translateZ` |
| `*-draw`, `*-trace`, `*stroke*` | `stroke-dash` 或 `pathLength` |
*修复*：补上这项技术，或者给条目改名。改名往往才是诚实的修法。

**X3. 不清晰。** 在 1920x1080 下、在它自己的底色上：文字对比度低于 4.5:1，或者主体最小的有意义特征小于约 24px。*修复*：按 `placeholder-material.md` 调一个明度台阶。文字绝不能低于 L1。

**X4. 占位渐变。** 用紫色和蓝色的色板来顶替内容。*修复*：改用单色色阶。整个 catalog 已经改过一遍了，所以新出现的实例属于回归，不是遗留缺陷。

**X5. 写死的文字颜色，没有主题 token。** 条目自己的文字或主体用了字面颜色值，没有 `var(--...)` 回退链，所以作者把它放到相反的主题上时它就消失了。*修复*：让它走主题 token，把字面值作为回退值。

**X6. 没有自己的标记。** 文件只有一个 `<style>` 和一个 `<script>`，别的什么都没有，所以挂载后渲染出来是一个空盒子。*修复*：附带示例标记，或者在 `registry-item.json` 里声明它是一个附着型片段（attachment snippet），并给 demo 一个宿主元素。

**X7. 未加种子的随机性。** 散布位置从 `Math.random()` 推导，而不是从元素索引推导。*修复*：改为从索引推导。

**X8. 声明的范围做不到。** 一个数值变量没有 `min`/`max`，于是控件会提供条目无法表达的值，或者一个它永远回不去的默认值。*修复*：声明真实的范围，或者用数字输入框代替滑块。

## 重复时保留哪一个

一组是指在 F2 中两个哈希都相同的条目集合。恰好保留一个，按以下顺序选出：

1. **名字描述了共享动效实际在做什么的那个。** 如果一组里有一个成员是定向擦除，其余成员都是借用它的，就保留这个定向擦除。
2. **其次是带有主体专属标记的那个。** 指的是更多只有对那个名字才说得通的元素，而不是单纯更多的元素。
3. **再其次是已经在 `origin/main` 上的那个。** 移除一个已发布的条目会让安装失败。
4. **绝不选一个名字声称了共享实现并不具备的东西的成员。** `frosted-glass-wipe` 没有 `backdrop-filter`，`spring-scale-in` 没有 spring，`mask-reveal-up` 没有 mask，所以这三个都不能当保留者。这样的成员同时属于 F2 和 X2，而且 X2 无法在不破坏整组的情况下修复。如果没有一个成员是名副其实的，就保留最朴素的名字。

**如果一组里每个成员都不满足 F1，整组移除。** 不要为了让数字好看而保留一个幸存者。十二个名字共用一个空卡片外壳，是一个坏条目，不是十二个；保留其中一个，就是保留了这个坏条目。

相同的动效配上真正不同的主体，不算重复。柱状图、折线图和仪表盘填充可以共用同一个错开（stagger）；主体才是条目本身。

## 绝不移除

保护是按标准逐条给的，不是一揽子豁免。受保护的条目仍然要接受其他每一行的检验。

**N1. 承载意义的颜色**只豁免 X4。`chromatic-aberration-wipe`（RGB 分离就是效果本身）、`confetti`（多色就是庆祝感）、`matrix-decode`（绿色是它的身份）、`mesh-gradient-bg`（渐变就是主体）、`multi-device-splay`。`us-map` 的渐变是顺序型分级统计图（choropleth）色阶，那是承载数据的颜色。

**N2. 对真实产品的描绘**豁免 X4 和 F1。Figma 模拟界面里的 Figma logo 不是糊弄；`logo-brand-close` 里的 HyperFrames 文字标志就是主体。评判的是占位内容，而不是被描绘的产品。

**N3. 有意为之的静止**豁免 X1。一个描述里并未承诺运动的条目不算违反 X1。样式片段或被动的 overlay 可以一动不动。

**N4. 环境布景**豁免 F3。一个充当背景而不是镜头的条目，不会因为安静而被判 F3。帧间测得的 PSNR 可以把两者区分开：布景得分在 45 或以上，真正在动的东西得分在 17 到 24。对照描述来评判。

**N5. 静止状态就是配方的 `from` 状态**的条目豁免 F3。`confetti` 附带的 `.particle` span 在 timeline 把它们散开之前都处于 opacity 0。静止不等于死掉。

**N6. 附着型片段**豁免 F3。文字拆分器按设计就没有标记。按 X6 评级。

**N7. 已经在 `origin/main` 上的 36 个条目**不在审核范围内。

## 机械预检轮

| 信号 | 做法 | 对应 |
| ------------------- | ------------------------------------------------------------------------------------- | ------- |
| 没有 timeline | 对每个 composition 执行 `grep -L __timelines` | X1      |
| 重复 | 动效指纹与标记骨架两个哈希，两两比对 | F2      |
| 空外壳 | 标记骨架与一个无关的条目相同，或者只有 `<h3>` + `<p>` + 通用面板 | F1      |
| 完全没有标记 | 去掉注释、style 和 script 之后的文件元素数为 0 | X6      |
| 占位色板 | grep 那六个禁用的十六进制色值 | X4      |
| 名不副实 | 用 X2 的表格，只在代码区域里 grep | X2      |
| 无界数值 | 读 `registry-item.json` 里的 `min`/`max` | X8      |
| 非确定性 | grep `Math.random`、`Date.now`、`performance.now`、`requestAnimationFrame` | X7, F5  |

## 视觉轮：给出结论前必做

从 **composition**（而不是 demo）按上面的 harness 规则挂载，在整个时长内至少渲染四帧，并且亲眼看过。然后，对于任何没有拿到干净分数的条目，在记录之前先到真实的 catalog 页面上确认。

每个条目要记录：它违反了哪些标准、你看到的证据、是致命还是可修复。没看过的条目不算通过。

## 校准

用这份评分标准给十个条目打了分，帧都渲染出来并看过。其中三个反过来修正了评分标准，而不是被标准修正。

| 条目 | 预期 | 画面实际显示 | 结论 |
| ---------------------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------- | ------------------ |
| `ecosystem-constellation`    | 致命 | 一个侧栏，三个药丸形按钮和三块空白的白色面板。没有节点，没有连线。四个时间点完全一样。 | **移除** F1, F2, F4 |
| `terminal-to-browser-deploy` | 致命 | 与上一个像素级一致，只有 `<h3>` 和一行副标题不同。没有终端，没有浏览器。 | **移除** F1, F2, F4 |
| `frosted-glass-wipe`         | 致命 | 一张写着 "Before" 的卡片，一直静止不动；"After" 面板始终被裁掉。配方与 `directional-wipe` 字节级相同。 | **移除** F2, F4, X2 |
| `char-slam-explode`          | 通过 | 0.05 秒时字母散开，到 1.2 秒组合成 "Impact"，然后保持。真正的逐字符运动。 | **保留**           |
| `echo-trail`                 | 通过 | 卡片从左向右移动，身后拖着逐渐衰减的模糊回声拖尾。在它自己的浅色底上清晰可读。 | **保留**           |
| `logo-brand-close`           | 通过 | "H" 演变成完整的文字标志，随后标语和 URL 依次落位。有层次，清晰可读。 | **保留**           |
| `blur-in`                    | 临界 | 静止，但这个静止就是正确的静止状态：标题清晰可读，实现独一无二，文字颜色用了主题 token。 | **保留**，X1       |
| `spring-scale-in`            | 临界 | 在它自己的 `#f7f7f8` 上清晰可读。ease 是 `power3.out`，哪里都没有 spring。和另外六个条目共用配方。 | **移除** F2, X2     |
| `confetti`                   | 临界 | 有卡片和网格，看不到粒子。源码附带的 `.particle` span 由配方从 opacity 0 散开。 | **保留**，X1       |
| `bottom-up-letters`          | 临界 | 四帧空白。这个文件是一个拆分器，完全没有标记。 | **保留**，X6       |

校准迫使做出的三处修正，全都是误删：

- `spring-scale-in` 最初被判为 X3，对比度约 1.5:1。那是 harness 的深色舞台造成的，不是条目本身的问题。于是有了"用条目自己的底色"。
- `confetti` 最初被判为 F3。它的静止状态就是配方的 `from` 状态。于是有了 N5。
- `char-slam-explode` 最初因为四帧全黑被判为 F3。它是一个 sub-composition，却被内联了。于是有了两种形态的规则。

一份会砍掉正常工作条目的评分标准就是错的，哪怕那个结论很省事。

## 检查清单

每个条目按顺序过一遍。遇到第一个致命项就停。

- [ ] 按它的形态用正确的方式挂载，在它自己的底色上，加载了 GSAP 和一个暂停的根 timeline。
- [ ] F1：标记里包含所称的主体。
- [ ] F2：动效指纹和标记骨架没有同时与某个保留者相同。
- [ ] F3：应用配方后它能渲染出东西，或者它受 N3 到 N6 的保护。
- [ ] F4：画面显示了描述所承诺的事件。
- [ ] F5：第 N 帧由 N 计算得出。
- [ ] X1 到 X8 已记录，并附上具体修法。
- [ ] 结论引用了该标准所要求的证据，而不是一个印象。
