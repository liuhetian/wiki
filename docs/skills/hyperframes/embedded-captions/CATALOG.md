# 目录（THE CATALOG）—— 一个前端，背后三个引擎

这是本 skill 唯一的选择界面。**用户从这张表里选一个风格（IDENTITY）；其他一切（引擎、编译器、编写文件）都通过查表得出 —— 绝不要问用户（或问你自己）「Standard 还是 Cinematic 还是 Theme？」** 那些是后端名称；一个产品即使有好几个引擎，也只有一种 UX。

路由流程（取代任何模式决策）：

1. 探测素材（按 SKILL.md 里的决策闸门 + 预检探测）。
2. 按**内容语域 + 用户自己的措辞 + 场景约束**，从这张表里列出 2–3 个候选风格。
3. 推荐其中一个，附一行理由；由用户来选。
4. 编写该风格的文件（最后一列），然后用它所属引擎的管线渲染。完成 —— 自始至终不抛出任何类别问题。

## 短名单启发法（风格层面，而不是类别层面）

- **「每个词都要被读到 / accessibility / 教程·新闻」** → rail 或 panel 载体：`anchor`、`ordnance`、`terminal`（天然都是逐字照录）。
- **「嵌进场景 / 电影感 / 高级」** → 那十个 column-flow 风格；按语域 + 场景亮度选（明亮 → `ink`；暖色暗场景 → `cream`；时尚 → `editorial`；……）。明亮 + 必须读到 → `anchor`。
- **「炸 / 特效 / 酷炫 / 像 AE」** → `ordnance`、`stomp`、`terminal`、`loud` —— 按什么应该爆开来选：一个词（`ordnance`）、整个画面（`stomp`）、一次解码（`terminal`）、每一拍（`loud`）。
- **点名的世界观** → 直接命中：控制台/终端 → `terminal`；霓虹/招牌 → `neonsign`；诗/星尘/记忆 → `stardust`；军事/重击 → `ordnance`；预言/未来/悬念揭示 → `lastpage`；
- **场景约束最后一票否决**：luma > 180 会否决 cream/screen 的 column 外观（→ `ink` 或某个 rail/panel 载体）；黄昏 / 暗场景会解锁 `neon`/`neonsign`。
- **拿不准** → `anchor`（保守的默认：词能读到，场景安全，零炫技）。例外：如果需求里原话就是「嵌进场景 / embed into the scene / 电影感」，这个信号压过保守默认 —— 走 column-flow（按语域 + luma 选），不要用 rail。

值得了解的相邻对（正是这几对让旧的模式问题难以回答 —— 按它们的差别来推荐，不要纠结类别）：`loud` vs `ordnance`（打击乐式文字 vs 带 plate 反应的主题化世界）· `neon` vs `neonsign`（霓虹风格的字幕 vs 一块正在被书写的招牌）· `cream` vs `stardust`（温暖的嵌入式流 vs 带语义消散的累积之诗）· `terminal` vs `glitch`（一个带打字日志 + 解码的控制台世界 vs 加在普通字幕上的信号损坏风格）· `stomp` vs `loud`（每一拍都接管正中央的画面 vs 仍与主体共享画面的高能文字）。

## 规则

- 风格是**与引擎锁定的** —— 不能交叉组合。开启一个新组合（例如把另一套 DNA 放到 rail 下）是一次验证事件：渲染 → 用户审阅 → 翻转该 DNA 的 `deliveries.rail` 标志（见 dna/README.md）。
- 新风格按它所属家族的 registry 规则加入（经典风格看 dna/README.md，主题化风格看 themes/README.md —— 门槛是「任何输入，零手动修补」）。
- 各引擎的内部机制（Standard/Cinematic/Theme 编译器、闸门、图层）记录在它们各自的文件里；本目录是唯一的路由界面。
