# THEME 模式 —— 组合而成的视觉宪章

Theme 模式是第三个编译器（`scripts/make-theme.cjs`），与 Standard 和 Cinematic 并列。它之所以存在，是因为「模式」原本是一捆相互正交的维度，却假装成一个开关。theme DNA 从各个 registry 中组合出自己的身份，而这些 registry 在编译器里只实现一次 —— **paradigm 是代码的单位；DNA 是身份的单位**。新的外观只是一个 JSON 文件；只有真正全新的 paradigm/setpiece（很少见）才需要动编译器。

```
theme DNA = body PARADIGM   how the transcript surface lives
          × body LAYER      fg-alpha (rail.html channel) | bg-embed
          × hero SETPIECE   the climax choreography
          × front FX        flash / rings / sparks / scanband / crowdflash / paflash (fg, over subject)
          × PLATE budget    charge-dim (in-page) + punch/shake/grain (_postfx.sh)
          × LINKAGES        declarative theme interactions
```

回头看，Standard 和 Cinematic 只是这个空间里的两个固定点。Standard 现已退役（RETIRED，2026-06-12）：它所占的 rail×嵌入高潮这个点，由 `anchor` theme 承接（rail paradigm × settle setpiece —— 安静的默认选项）。Cinematic 仍是一个独立的编译器；暂时不要把它重新实现成 theme。

## 统一路线图（strangler fig 绞杀者模式 —— 先统一接口，后统一引擎）

面向用户的模型已经统一了（SKILL.md Step 0）：一份外观（LOOKS）目录；经典外观选择一种呈现方式（DELIVERY：rail | column），主题外观自带绑定的呈现方式。「Standard/Cinematic」是呈现方式 / 编译器的名字，不是模式。剩下的各个阶段，每一个都要等确有需要才启动 —— 绝不只为了整洁而重写：

- **Phase 2 —— 统一的编写 schema。** `lines`/`minors`/`hero` 在 standard.json 和 theme.json 之间已有约 90% 是共用的；做一个路由，把单一的 `caption.json` 翻译成各引擎专用的文件，就能消除最后一处用户可见的接缝。cinematic.json 的 blocks/planes 是个异类 —— 映射共有字段，引擎专有字段原样透传。
- **Phase 3 —— 引擎收敛。** 只有在某件事逼得不得不做时（例如某个经典 DNA 想要 plate 预算或某个 setpiece），才把一种经典呈现方式移植进 make-theme。验收标准：在 cap_multi 回归场景上与旧编译器做盲测 A/B —— 只有在难以分辨或更好时才更换引擎。在那之前，旧编译器是 8 轮验证过的排版能力的参考实现（lockup/orbit、多高潮、比例锁定、逐平面可读性、遮挡裁决）—— 这套机制是护城河，不是技术债。

inline setpiece（`hero.inline: true`）活在正文 paradigm 内部 —— hero 词留在 `lines` 里。嵌入式 setpiece 独占这个词：把它排除在 `lines` 之外（rail↔高潮交接），只有 `panel` + `redact-until-hero` 例外，这种情况下这些词在日志里显示为 `█████`，直到 decode 锁定。

setpiece 还可以额外返回 `fgCss/fgHtml/fgJs` —— 这些部件会被合并进 fg alpha 页面（rail.html），用于必须浮在 matte 之上的陈设（例如绝不能被遮挡的逐字标签），而 setpiece 的布景仍嵌在主体背后。

## Linkage（联动）

- `redact-until-hero` —— panel 日志把 hero 词显示为方块；锁定时解除涂黑
- `corrupt-on-last-word` —— 在最后一个词上 panel 抖动 + 色相偏移
- `disperse-on-last-word` —— 每个可见的 poem 字母都散回尘埃
- `field-is-the-apex` ——（lastpage）模糊的未来实例场在 apex 时刻移焦变清晰：原来每一道淡淡的线一直都是那个 apex 词；主实例保持，其余的重新模糊并消亡

## 继承的硬规则（不得放宽）

- 确定性：暂停的 GSAP 挂在 `window.__timelines["main"]` 上，只用带种子的 PRNG，用 set 链 / 关键帧，不用 Math.random/Date.now/CSS-keyframes
- 80 ms 词同步（时间来自 transcript.json，经由严格匹配器得出；任何未被覆盖的转录词都是编译错误（ERROR）—— 逐字完整性）
- apex 独占画面：在 hero 窗口期间，fg 陈设必须避开 setpiece 的矩形区域，或者让位（`body.yield`）
- plate 冲击/震动始终在合成之后做（`_postfx.sh`），让主体 + 文字 + plate 作为同一张拍摄画面一起移动（matte 永不失步）

## SVG 坑（已经交过学费，不要再重新发现一遍）

- dash 图案在每个子路径上都会重新开始 → 用依次的逐笔画路径，绝不对多笔画的词用一个贯穿的 dashoffset
- round linecap 在 dashoffset=len 时会渲染出一个点 → 每一笔在轮到它之前都要隐藏
- inline-block 的尾随空格会被折叠 → 词间距用 margin，不用文本空格
- SVG 字体字形的 y 轴朝上 → 转换时要翻转（gen-stroke-path.py 会做）
- 绝不要对裸的 SVG 子元素做 gsap x/y/scale：它会走 `_parseTransform`/getBBox，而零面积的形状（扇形套件里的细条）会触发 GSAP 的 bbox hack → 在注入了 gsap 的上下文（preview-frames、renderer）里对一个 null 的 docElement 调用 `appendChild`。SVG 部件的抖动只用 `attr:{transform:"translate(...)"}`；缩放/逼近要放在 HTML 包裹 div 上。细节：div 里的根 `<svg>` 的 ownerSVGElement 为 null → GSAP 把它归类为 HTML（CSS transform，不调用 getBBox），所以在 svg 根上做 scale/skew 是安全的 —— 但把同样的做法照搬到内部的 `<g>` 上，就落进了致命的那一类。attr transform 不能 TWEEN —— 用按帧量化的 step 链（在 24fps 下屏幕上看起来完全一样）

## Timeline 所有权规则（源自审计，不得放宽）

- 任一时刻，每个（target, property）只能有一个所有者。带时长的 tween 在结束前每个 tick 都会重新渲染 —— 在那个时间窗内对同一属性做的任何 set/tween，都会在一帧之后被视觉上覆盖掉（1 帧残影、闪回）。已知的形态：让位压暗 vs 行退场；让位恢复 vs powercut set 链；词间隔 < 0.22s 时的逐词行 y 弹跳。rail 发射器对这些做了防护（弹跳所有权追踪器，压暗钳制为 ≥ 行进入时刻，只有在退场前有 ≥0.3s 余量时才恢复 —— 否则该行以压暗状态退场，这是有意设计）。
- 反转的钳制：`Math.max(lo, Math.min(hi, x))` 在 lo > hi 时会悄悄钉死在 lo。当 lockup 比画面还宽时，要把它居中（x = W/2），而不是钳制 —— 装饰性的出血必须对称。
- overflow 闸门只测量带直接文本节点的元素 —— 用 SVG 绘制的 setpiece（mask 文字 + 矩形）对它来说是不可见的。不要把它的「ok」当作 svg lockup 合格的证明；这类要看预览帧来判断。

## theme.json —— 完整 schema

```json
{ "dna": "<themes/*.json name>",            // required
  "lines": [["word","word",...], ...],       // required — verbatim transcript tokens, in order,
                                             //   INCLUDING punctuation ("size.", "noise.")
  "minors": ["word", ...],                   // optional — theme's inline emphasis treatment
  "hero": { "match": "word or phrase",       // required — exact transcript tokens (case-insensitive,
                                             //   punctuation-stripped match); first occurrence wins
            "text": "DISPLAY FORM",          // optional display override
            "out": 5.9, "exitAt": 3.3 },     // optional window overrides (seconds)
  "width": 1280, "height": 720,              // optional, default 1280x720 (theme DNAs are tuned
                                             //   for 16:9; vertical needs a DNA variant)
  "fps": 24,                                 // optional — matte.fps is AUTHORITATIVE when present
  "panelHeader": "..." }                     // optional (panel paradigm)
```

场景感知（继承自现有的排版系统）：存在 `safe-zones.json` 时，编译器会把 hero setpiece 重新锚定到实测的遮挡带（`heroBands.profile`，遮挡率 18–55%，取最接近该 setpiece 偏好高度的那条）和 `heroAnchor.centerXPct` 上，按实际的词对 hero 字号做宽度适配，并把 panel/poem 的陈设停靠在 `subject.clearerSide`。优先级：显式的 `theme.json` 值 > 场景自动 > DNA 兜底。

预期内（无害）的日志噪声：fg 层页面加载时的 `[Browser:REQUESTFAILED] GET source.mp4 net::ERR_ABORTED`、滚轮字形的 overflow lint 行，以及 `media_missing_data_start` —— 全都只是表面问题；只要 render-theme.sh 以 0 退出并打印出闸门汇总，渲染就是好的。

## 编写一个项目（用户要写的就只有这些）

`<project>/theme.json`：

```json
{
  "dna": "ordnance",
  "lines": [
    ["The", "stars", "were", "only", "limited"],
    ["by", "the", "pixel", "size."],
    ["It's"],
    ["what", "you", "can", "actually"],
    ["recover", "from", "the", "noise."]
  ],
  "minors": ["stars"],
  "hero": { "match": "remarkable" }
}
```

- `lines` 必须逐字、按顺序遵循转录稿（否则编译报错）；每个转录词都必须被 `lines` ∪ `hero.match` 覆盖 —— 上面的例子在 `lines` 里省掉了「remarkable」，正是因为 `hero.match` 覆盖了它（它插在 `["It's"]` 和 `["what",...]` 之间）
- 嵌入式 setpiece 要把 hero 词排除在 `lines` 之外；inline setpiece 以及 panel+redact 则要保留
- `takeover`：每一行是一张卡片（CARD）—— 按段落节拍分组（1–2 个词），而不是按字幕长度；`panel` 超过约 5 行会自动滚动（终端式滚动）
- ordnance 的「charge」是边缘暗角 + rail 让位（画面中心按设计保持干净）—— 要看画面四角来判断，而不是看中心
- `minors`：会获得该 theme 行内强调处理的词
- 先预览：`node scripts/make-theme.cjs <project>`，然后 `node scripts/preview-frames.cjs <project> <t1> <t2> ...`（Visual QA）
- 然后：`bash scripts/render-theme.sh <project>` → **`final_fx.mp4`**（这是交付物；`final.mp4` 是 plate 反应之前的版本）

前置条件与其他模式相同 —— `prepare.sh` 的输出：transcript.json、frames_fg/、matte.fps、safe-zones.json（场景感知）、source.mp4。frames_bg/ 只有 preview-frames.cjs 需要，渲染不需要。

## 新增一个 theme DNA

复制一个 `themes/*.json`，修改身份字段。你只能组合已有的 paradigm/setpiece/linkage 名称 —— 如果你想要的外观需要新机制，那就是一次 registry 贡献（本文件 + make-theme.cjs），要像引擎改动一样评审。需要逐词视觉调参才能交付的 DNA 会被拒绝：**任意输入，零手工修补**才是验收标准（draw-on 的教训）。
