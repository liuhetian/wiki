# overwhelm-surround — 压迫 / 围拢

**intent**（意图）：靠堆积来传达压迫感。可辨认的主体先组装起来，密度标记散落进来，放大「看看有多少」，然后中央主体变形成观众自己的头像，元素从所有（ALL）方向围拢过来 —— 画面给人的感觉是被包围，而不是被推近。情绪弧线是从认出到幽闭。

**roles served**（适用角色）

- Problem（来自 `problem-mockup-overwhelm`）：当痛点段落节拍必须先展示「工具太多 / 要顾的面太多」，然后再把**观众放进其中**时 —— 字面意义上替换主体（产品 → 人），随后是一种有侵入感的围拢。当痛点是「你被淹没了」而不是「这个指标很糟」（那是 `dataviz-countup`）时用它。
- Problem（来自 `desktop-clutter-accumulation`）：当压迫来自一个**工作区**而不是工具数量时 —— 实时窗口、便利贴和警告 toast 不断堆积，直到画面混乱地塞满，这一拍的收尾不是围拢，而是把杂物推到一边、抛出问题。当痛点落在文字上（「当你要在 Y 上花好几个月的时候，你怎么可能 X……？」），而不是落在一个被包围的头像上时，用这个变体。

**duration**（时长）：6–9s（杂物推开引出问题的变体约 10s）

**shot structure**（镜头结构）（一张 `[bg]` 画布；先是可辨认的界面，然后揭示出下面的观众头像，再然后是径向围拢的人群）

- **Scene 1 (0.0–~1.6s) —— 可辨认的组装。** 三个 `[product mockups / surfaces]` 组装成观众熟悉的东西 —— 错落缩放进入，**中间**那个是完整尺寸，两侧的较小（约 0.86）。每个都带着低振幅的漂浮，让它们感觉像实时的语境，而不是一张静态拼贴。镜头静止。
- **Scene 2 (~1.6–3.0s) —— 密度放大。** `[platform icons / logos]` 在 mockup 周围散落进来（错落），纯粹用作**密度标记** —— 表达「看看要顾的面有多大」，而不是带动画的仪表。
- **Scene 3 (~3.0–4.6s) —— 变形（标志性动作）。** 中间（CENTER）的 mockup 发生变形：它的内容淡出，容器改变形状，观众的 `[avatar]` 在**下面**显露出来 —— 字面意义上替换主体，产品 → 人。
- **Scene 4 (~4.6–end) —— 围拢。** `[task bubbles / demands]` 从所有（ALL）方向朝头像围拢过来（径向错落进入）。头像**保持不动**，气泡步步侵入 —— 幽闭感来自被包围，绝不是来自镜头推进。在拥挤的状态上定住。
- **变体 —— 杂物推开引出问题**（取代 Scenes 3–4，并反转镜头契约 —— 见镜头修饰）：堆积在一个**缓慢、稳定的拉远**下进行 —— `[sticky notes]` 弹性地弹入，`[dashboard / editor windows]` 弹出并上滑，一摞 `[alert toasts]` 从一侧边缘滑入，内部内容持续打字 / 日志滚动，作为实时的密度，窗口相互重叠，直到画面混乱地塞满。随后镜头反转（REVERSES），变成一次快速推进，**把杂物推到画面边缘**，在中央腾出负空间，一个 `[two-part serif question]` 在那里逐词搭建（第 1 行原地替换成第 2 行）；一个 `[cursor]` 从画外滑入，停在文字下方；一个非常缓慢的向前蠕动，然后保持。没有变形，没有头像 —— 问题本身就是收束。

**motion vocabulary**（运动词汇）：错落缩放进入的组装；保留静息缩放值的低振幅漂浮；作为密度标记的图标散落；内容淡出 → 容器变形 → 揭示下方锚点的变形；从所有方位径向围拢进入；保持拥挤的结束状态。杂物推开变体：堆积期间缓慢稳定的拉远；反转成快速推进；杂物被推到画面边缘，腾出中央负空间；窗口内持续的实时打字 / 日志滚动，作为氛围密度；toast 堆叠滑入；逐词搭建的衬线文字，带原地整行替换；光标滑入后停住；非常缓慢的向前蠕动 + 保持。

**rule mapping**（规则映射）

- 错落的 mockup + 图标进场（平滑落定到各自的静息缩放值）→ `spring-pop-entrance`（平滑落定的语气），由 `gsap-effects` 支撑
- 作为密度标记的平台图标（位置预先算好，只动缩放 / 不透明度 —— 不做（NOT）内部部件动画）→ `svg-icon-enrichment`（只用它的 DOM 契约）
- 中间 mockup → 头像的变形（HF 禁止 tween `width`/`height` → 用 `scaleX`/`scaleY` 驱动形状变化，锚点 = 渲染在下面的头像图层）→ `card-morph-anchor`
- 气泡径向围拢（位置用 `cos`/`sin` 一次算好，错落进入）→ `gsap-effects`（径向布局）+ `spring-pop-entrance`（每个气泡的到场）
- 背景 mockup / 图标上的低振幅漂浮 → `sine-wave-loop`（低振幅语气 —— 叠加在每个元素静息缩放值之上的细微抖动，绝不是一个会 tween 回起点的 `fromTo` yoyo）
- （变体）堆积期间拉远 → 快速推进 → 缓慢向前蠕动 → `multi-phase-camera`（在同一个 world wrapper 上依次运行后拉 / 推进 / 漂移几个阶段；反向平移的数学在 `viewport-change` 里）
- （变体）推进落下时杂物被推到边缘 → `center-outward-expansion`（指向边缘静息位置的向外向量），与镜头推进放在同一时间线位置触发，让推开读起来是由推进引起的（CAUSED）（`reactive-displacement` 语气）
- （变体）衬线问题逐词搭建 → `gsap-effects`（错落的逐词揭示）；第 1 行 → 第 2 行的原地替换 → `discrete-text-sequence`
- （变体）窗口内的实时打字 → `gsap-effects`（打字机）；持续的内部日志滚动 —— 组合方式：通过 `gsap-effects` 对内容做循环 translateY（带遮罩）
- （变体）光标滑入后停住 → `cursor-click-ripple`（只用接近的部分 —— 不点击）

**camera modifier**（镜头修饰）：镜头静止 —— 围拢必须读作世界在挤压主体，所以画面保持不动；推进会把「被包围」变成「被推近」，扼杀幽闭感。杂物推开引出问题的变体是被认可的例外：在那里镜头就是（IS）讲故事的人（通过 `multi-phase-camera` 拉远 ↔ 推进），幽闭感来自堆积，而不是包围 —— 绝不要在同一个镜头里混用这两种收尾方式。
