# 运动模糊 —— 任何动画元素上的快门拖影

## 给任何东西加模糊之前先读这一部分

模糊不是润色。它是被摄物体穿过画面时真实快门留下的拖影，所以只有当物体穿过的画面距离足够大、足以产生拖影时，它读起来才是对的。把它加到从来就不够快的运动上，读起来就是一次柔糊、廉价的渲染：眼睛期待看到边缘的地方，看到的却是一团糊。

不要模糊：

| 情形 | 原因 | 改为 |
| --- | --- | --- |
| 每帧移动不到约一个元素宽度 | 各个副本堆叠在元素自身的轮廓之内，所以结果是一个更软的元素，而不是拖影 | 保持清晰 |
| 淡变、颜色变化、模糊入场、滤镜节拍 | 没有任何东西作用到 `transform` 上，所以既没有可积分的轨迹，也没有可画的拖影 | 保持清晰 |
| 那一刻需要被读的文字 | 被拖影的词就是读不了的词，这通常与 brief 的要求背道而驰 | 模糊接近的过程，清晰落地，停留 |
| 缓慢漂移、视差图层、呼吸循环 | 低于半像素死区时它无论如何都会渲染得很清晰；高于死区时看起来像个错误 | 保持清晰 |
| 整个场景，或者一个包含许多元素的容器 | 代价是整棵子树的副本，而且一个从不移动的容器不会让里面的任何东西产生拖影 | 把它指向那个真正在动的元素 |

只模糊那些「猛然」的节拍：重击（slam）、甩动（whip）、位置上的硬切、旋转、缩放冲击。一个 composition 里一到三个，而不是每个 tween 都加。

## 两条路线，它们不可互换

| 路线 | 它是什么 | 何时使用 |
| --- | --- | --- |
| `motion-blur` registry component | 在页面里合成的 DOM 快门：沿元素采样轨迹排布的 N+1 个加法混合副本 | 你希望拖影在预览里可见，只作用于选定的元素，逐元素编写 |
| 引擎的 `motionBlur` 渲染选项 | 渲染器对整帧的真实子帧采样做积分 | 你希望所有移动的东西都有拖影，包括 canvas、视频和带 transform 的祖先元素，并且只出现在最终渲染里 |

component 只对你标记的元素、只对 `transform` 能表达的运动加拖影。引擎给整帧加拖影。component 是 agent 编写时用的那一个；引擎选项是渲染时的决定，在预览里什么也看不到。

## 约定：一个属性

把 component 的 snippet 粘贴进 composition，然后标记元素：

```html
<div id="root" data-composition-id="hero" data-duration="4" data-fps="30">
  <div id="slam" data-hf-motion-blur></div>
  <div id="title" data-hf-motion-blur='{"shutterAngle": 360}'></div>
</div>
```

不需要调用任何东西，也不需要操心顺序。被标记的元素会在它所属 composition 的 timeline 注册后立即被挂上，而且加载后大约八秒内还会轮询 timeline 注册表，所以异步挂载的 composition 也会被捕获。元素使用的是它最近的、带 `data-composition-id` 属性的祖先所注册的那个 timeline，所以 sub-composition 里的目标会跟随那个 sub-composition。

空属性表示使用默认值。其他任何值都必须能解析为一个 JSON 对象，所以键需要用双引号。解析出来是别的东西的值 —— `null` 或一个裸数字 —— 会发出警告并被跳过，而不是悄悄当作默认值处理。

`attachMotionBlur(target, timeline, options)` 用于在那个时间窗口之后才创建的元素。它有顺序约定：要在所有 tween 之后调用，这样 timeline 的最终时长才是已知的；而弄错了也不会有任何提示。对于已经在文档里的标记，用属性。

## 选项

| 选项 | 默认值 | 含义 |
| --- | --- | --- |
| `shutterAngle` | 720 | 快门在一个帧间隔内打开的角度（度）。720 是两帧，按一段真实的 After Effects 导出测得。360 是一帧。0 关闭拖影 |
| `shutterPhase` | -360 | 窗口起点相对帧时刻偏移的角度（度）。-360 让窗口以该帧为中心 |
| `samplesPerFrame` | 16 | 窗口被分成的子区间数，所以副本数是这个值加一，每个副本的不透明度是这个值分之一。最大 64 |
| `fps` | 目标自身 composition 根节点的 `data-fps`，否则为 30 | composition 帧率。用 fps 覆盖值渲染时要显式传入 |
| `sharp` | 1 | 1 会在拖影之上把元素本身清晰地画出来。0 会在它移动时隐藏它，只留下快门平均：一个没有帧时刻边缘的柔和模糊。它通过一个标记属性来隐藏，从不动元素自身的 visibility，所以 autoAlpha 仍然有效（元素上内联的 `visibility: visible !important` 会胜出） |

不属于这五个之一的键，以及不是有限数字的值，都会被点名拒绝，而不是当作默认值读取。`{"shutterAngle": "720deg"}` 是一次拒绝，而不是一个 720 度的快门。

没有轴向，没有强度，也没有半径。拖影就是积分出来的轨迹；它的长度是速度乘以快门时间，不是一个可以随意设定的参数。传了 `axis`、`blurMax` 或 `blurScale` 的模板带的是这个 snippet 的一个较旧分支，这些选项在当前版本里不起任何作用。

## 失败模式全都是静默的

下面每一种都会渲染出一个看起来合理的清晰元素，除了注明的地方，什么也不报：

| 症状 | 原因 | 修复 |
| --- | --- | --- |
| 控制台警告没有 composition 为某元素注册 timeline | 该元素不在任何 `data-composition-id` 之内，或者那个 composition 从未注册 timeline | 把它放进 composition 的根节点里，或者注册 timeline |
| 控制台警告属性不是 JSON | 单引号、键没加引号、末尾多了逗号 | 用双引号的 JSON，或者用空属性取默认值 |
| 控制台警告属性不是 JSON 对象 | `null`、裸数字、带引号的字符串、数组 | 用对象，或者用空属性取默认值 |
| 控制台警告属性里的选项名不存在 | 键拼错了，例如 `samplesperframe` | 使用上面五个名字之一，区分大小写 |
| 控制台警告属性的某个选项需要数字 | 带引号或带单位后缀的值，例如 `"720deg"` | 用裸 JSON 数字 |
| 控制台警告无法模糊位于另一个目标内部的目标 | 一个元素和它的某个祖先都带了这个属性 | 只标记其中一个，即在动的那个 |
| 控制台警告一次调用无法模糊不同帧率的 composition | 一次 `attachMotionBlur` 调用指定了两个 `data-fps` 不同的 composition 中的元素 | 每个 composition 一次调用 |
| 控制台警告某元素注册了第二个 timeline | 同一个 `data-composition-id` 键被用不同的 timeline 注册了两次；副本仍然跟随第一个 | 每个 composition 只注册一次 |
| 没有拖影，也没有警告 | 这个节拍动画的是 `left`、`top`、`width` 或 `height`；snippet 读取的是解析后的 `transform` | 动画 `x`、`y`、`scale`、`rotation` |
| 容器的子元素上没有拖影 | 被标记的元素自己不动；动的是它的子元素 | 标记那些在动的元素 |
| 拖影落后于元素 | 实际在移动的是一个带 transform 的祖先元素 | 让元素自己移动，或者走引擎路线 |
| 模糊只出现在第一帧，或在预览里从不出现 | 宿主从不 seek 这个 timeline | HyperFrames 每一帧都会 seek；一个没人 seek 的暂停 timeline 什么也显示不出来 |
| 旧父元素里留下了一道拖影 | 挂上之后目标被换了父元素；副本组留在它被插入的位置，永远不会移动 | 不要给加了模糊的元素换父元素。改为动画 `x`/`y`，或者在移动之后再挂上 |
| 挂上之后某个选择器不再匹配 | 副本保留了元素的 class，因为 class 规则是唯一能给副本的伪元素加样式的东西 | 用 id 或引用来定位元素，绝不用副本也带着的 class |

## 代价

每个目标的代价是它整棵子树的 N+1 个副本。这些副本在挂上时和尺寸变化时会重新计算样式，每一帧都要重新 transform，而且每帧要 seek timeline N+1 次来采样轨迹。在默认的 16 下，每个目标每帧就是 17 个副本、17 次 seek。三个被标记的元素没问题。三十个就是另一种量级的渲染了。

先降 `samplesPerFrame`，再考虑去掉效果：8 能让代价减半，而在快速节拍上阶梯仍然是平滑的。

## 这些数字，方便你和它们较真

默认值是对照一段 1920x1080、30 fps、平移文字的 After Effects 导出测出来的，不是拍脑袋选的。在那段导出里，最外侧的拖尾副本恰好位于上一帧的位置，最外侧的领先副本恰好位于下一帧的位置，两侧各有 8 个均匀分布的副本：窗口为两帧，相位为负一帧，16 个子区间。一个笔画上的阶梯每级变化为清晰文字强度的 0.063 ± 0.002，每个副本固定 1/16，朝窗口边缘没有衰减。三角形加权与同一段导出对照要差 1.6 dB。

以那段导出为参考，逐节拍的 PSNR，清晰渲染对比本 component：平移 +3.38 dB，缩放 +0.62，绕 X 旋转 +0.43，绕 Y 旋转 +0.84，绕 Z 旋转 +1.15。只缩放或只旋转的节拍也会产生拖影，这是早先的 SVG 滤镜阶段做不到的。
