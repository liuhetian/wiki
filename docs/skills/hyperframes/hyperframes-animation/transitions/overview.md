# 场景转场

转场告诉观众两个场景之间是什么关系。交叉淡化说的是"这还在继续"。推移滑动说的是"下一个要点"。模糊交叉淡化说的是"随我漂流"。选择与内容在情绪上（而不只是技术上）所做之事相匹配的转场。

## 多场景 composition 的动画规则

对每一个多场景 composition，这些规则都没有商量余地：

1. **每个 composition 都要用转场。** 没有例外。没有转场的场景感觉像跳切。
2. **每个场景都要用入场动画。** 元素要以动画方式**进入**——不透明度、位置、缩放等。任何场景都不应该一下子完整地蹦到屏幕上。用 `gsap.fromTo()`（而不是 `gsap.from()`），让起始状态是明确的：`from()` 是动画*到*当前 CSS 的，所以把它和 CSS `opacity: 0` 搭配就是一个 0→0 的空操作，元素永远不会出现（见 `/hyperframes-core` → sub-composition）。
3. **离场动画是被禁止的**，最后一个场景除外。**不要**在转场触发之前用 `gsap.to()` 把元素动画移出。转场**本身就是**离场。转场开始时，离场场景的内容必须完全可见——视觉上的交接由转场负责。
4. **最后一个场景的例外：** 最后一个场景**可以**把元素淡出（例如在 composition 结尾淡出到黑场）。这是唯一允许离场动画的场景。

```js
// ❌ BANNED — fading the outgoing scene out, then the next scene just runs its entrance.
//    This is a jump cut with a dip, not a transition.
tl.to("#s1", { opacity: 0, duration: 0.4 }, 4.0);
tl.from("#s2 .headline", { y: 40, opacity: 0 }, 4.4);

// ✅ CORRECT — outgoing and incoming animate AT THE SAME TIME T; the motion IS the handoff.
const T = 4.0;
tl.to("#s1", { yPercent: -100, filter: "blur(8px)", duration: 0.5, ease: "power3.in" }, T);
tl.fromTo("#s2", { yPercent: 100 }, { yPercent: 0, duration: 0.5, ease: "power3.out" }, T);
```

> **读完这个文件你还没做完。** 这份概览告诉你的是用*哪种*转场、*什么时候*用。在写任何转场之前，你**必须**打开本目录下的 **`catalog.md`**，获取 GSAP 代码以及每个转场都要遵守的硬规则——*摆好新场景 → 让离场场景动起来 → 交换 → 让入场场景动起来 → 清理 overlay*——再加上各类别的 `css-*.md` 文件里的细节。只凭这份概览去写转场，最后交付的就会是上面那个 ❌ 模式。

## 能量 → 主转场

| 能量                                   | CSS 主转场                  | 着色器主转场                       | 点缀                         | 时长  | 缓动                 |
| ---------------------------------------- | ---------------------------- | ------------------------------------ | ------------------------------ | --------- | ---------------------- |
| **平静**（养生、品牌故事、奢侈品） | 模糊交叉淡化、焦点转移   | cross-warp morph（交叉扭曲变形）、thermal distortion（热扭曲） | 漏光、圆形光圈        | 0.5-0.8s  | `sine.inOut`、`power1` |
| **中等**（企业、SaaS、讲解）  | 推移滑动、错落色块 | whip pan（甩镜）、cinematic zoom（电影感变焦）             | 挤压、垂直推移         | 0.3-0.5s  | `power2`、`power3`     |
| **高**（宣传片、体育、音乐、发布） | 穿越变焦、过曝   | ridged burn（脊状灼烧）、glitch（故障）、chromatic split（色差分离） | 错落色块、重力坠落 | 0.15-0.3s | `power4`、`expo`       |

挑**一个**主转场（占 60-70% 的场景切换）+ 1-2 个点缀。绝不要每个场景都换一种不同的转场。

## 情绪 → 转场类型

想一想转场*传达*了什么，而不只是它看起来像什么。

| 情绪                     | 转场                                                                                                                          | 为什么有效                                                                                |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------- |
| **温暖 / 亲切**      | 漏光、模糊交叉淡化、焦点转移、胶片灼烧 · **着色器：** thermal distortion（热扭曲）、light leak（漏光）、cross-warp morph（交叉扭曲变形）                     | 柔和的边缘、暖色的晕染。没有任何尖锐或机械的东西。                                 |
| **冷峻 / 临床感**      | 挤压、缩小退出、百叶窗、快门、网格溶解 · **着色器：** gravitational lens（引力透镜）                                                   | 内容被机械地变换——压扁、缩小、切片、网格化。                      |
| **编辑 / 杂志感** | 推移滑动、垂直推移、对角分割、快门 · **着色器：** whip pan（甩镜）                                                            | 像翻页或切分版面。干净的方向性运动。                        |
| **科技 / 未来感**    | 网格溶解、错落色块、百叶窗、色差 · **着色器：** glitch（故障）、chromatic split（色差分离）                                  | 网格溶解是核心的"数据"转场。着色器 glitch 增加了色调分离 + 扫描线。 |
| **紧张 / 锋利**         | 故障、VHS、色差、波纹 · **着色器：** ridged burn（脊状灼烧）、glitch（故障）、domain warp（域扭曲）                                             | 不稳定、失真、数字崩坏。ridged burn 增加了尖锐的闪电裂纹状边缘。   |
| **俏皮 / 有趣**        | 弹性推移、3D 翻转、圆形光圈、圆形变形、时钟擦除 · **着色器：** ripple waves（波纹）、swirl vortex（漩涡）                                | 过冲、回弹、旋转、扩张。swirl vortex 增加了有机的螺旋扭曲。        |
| **戏剧性 / 电影感** | 穿越变焦、缩小退出、重力坠落、过曝、色彩过渡到黑场 · **着色器：** cinematic zoom（电影感变焦）、gravitational lens（引力透镜）、domain warp（域扭曲） | 缩放、重量感、光线的极端。着色器转场增加了逐像素的纵深。                      |
| **高端 / 奢华**     | 焦点转移、模糊交叉淡化、色彩过渡到黑场 · **着色器：** cross-warp morph（交叉扭曲变形）、thermal distortion（热扭曲）                                    | 克制。cross-warp morph 让两个场景有机地流入彼此。                  |
| **复古 / 模拟感**       | 胶片灼烧、漏光、VHS、时钟擦除 · **着色器：** light leak（漏光）                                                                      | 有机的不完美。暖色渗色、扫描线错位。                            |

## 叙事位置

| 位置                   | 用法                                                                        | 原因                                                   |
| -------------------------- | -------------------------------------------------------------------------- | ----------------------------------------------------- |
| **开场**                | 你最有辨识度的转场。匹配情绪。0.4-0.6s                 | 为整部作品定下视觉语言。        |
| **相关要点之间** | 你的主转场。保持一致。0.3s                                  | 不要分散注意力——内容还在继续。           |
| **话题切换**           | 与主转场不同的东西。错落色块、快门、挤压。 | 传达"新章节"——观众的大脑会重置。    |
| **高潮 / hero 揭示**   | 你最大胆的点缀。最快或最戏剧化的。                             | 这是回报时刻——把你最好的转场花在这里。 |
| **收尾放缓**              | 回到柔和。模糊交叉淡化、交叉淡化。0.5-0.7s                      | 让观众在高潮之后松一口气。               |
| **片尾**                  | 最慢、最简单。交叉淡化、色彩过渡到黑场。0.6-1.0s                 | 收束。不要在结尾引入新的能量。       |

## 在 CSS 里行不通的转场

避免：星形光圈、移轴、镜头光晕、铰链/开门。原因见 catalog.md。

## CSS 与着色器

CSS 转场用不透明度、transform、clip-path 和 filter 对场景容器做动画。着色器转场在一块 WebGL canvas 上逐像素地合成两个场景的纹理——它们能以 CSS 做不到的方式扭曲、溶解和变形。

**两者都是一等选项。** 着色器由 `@hyperframes/shader-transitions` 包提供——从这个包导入，而不是自己写原始 GLSL。CSS 转场搭起来更简单。根据你想要的效果来选，而不是根据哪个更省事。

**支持混用。** 在同一个 composition 里，你可以让一些转场用 WebGL 着色器，另一些用 CSS 交叉淡化。在任意一条 `TransitionConfig` 条目上省略 `shader` 字段，就会得到一个平滑的不透明度交叉淡化，而不是 WebGL 效果：

```js
var tl = HyperShader.init({
  bgColor: "#000",
  accentColor: "#6366f1",
  scenes: ["s1", "s2", "s3", "s4"],
  transitions: [
    { time: 4.0, shader: "sdf-iris", duration: 0.7 }, // WebGL shader
    { time: 8.5, duration: 0.8 }, // no shader → CSS crossfade
    { time: 13.0, shader: "domain-warp", duration: 0.6 }, // WebGL shader
  ],
});
```

不论转场类型是什么，HyperShader 都管理所有场景的可见性。让它来创建 timeline（不要往 `init()` 里传 `timeline:`），调用之后再把你的段落节拍动画加到返回的 `tl` 上。

## 与着色器兼容的 CSS 规则

着色器转场通过 html2canvas 把 DOM 场景抓取成 WebGL 纹理。canvas 2D 渲染管线和 CSS 并不完全一致。遵守这些规则，避免在转场边界出现可见的瑕疵：

1. **渐变里不要用 `transparent` 关键字。** Canvas 会把 `transparent` 插值成 `rgba(0,0,0,0)`（alpha 为零的黑色），产生暗边。始终使用目标颜色加零 alpha：用 `rgba(200,117,51,0)`，不要用 `transparent`。
2. **比 4px 更细的元素上不要用渐变背景。** 在 1-2px 的元素上，canvas 无法还原 CSS 的渐变渲染。细的点缀线用纯色 `background-color`。
3. **抓取时可见的元素上不要用 CSS 变量（`var()`）。** html2canvas 无法可靠地解析自定义属性。在内联样式里使用字面颜色值。
4. **用 `data-no-capture` 标记无法抓取的装饰元素。** 抓取函数会跳过它们。它们存在于实时 DOM 中，但不出现在着色器纹理里。用于无法遵守上述规则的元素。
5. **渐变不透明度不要低于 0.15。** 不透明度低于 10% 的渐变元素在 canvas 和 CSS 里渲染得不一样。提高到 0.15 以上，或者改用亮度相当的纯色。
6. **每个 `.scene` div 都必须有明确的 `background-color`，并且在 `init()` 配置里把同一个颜色作为 `bgColor` 传入。** 这个包通过 html2canvas 抓取场景元素。`.scene` 上的 CSS `background-color` 和 `bgColor` 配置必须一致。缺了任何一个，纹理都会渲染成黑色。

这些规则只适用于使用着色器转场的 composition。纯 CSS 的 composition 没有这些限制。

## 视觉图案警告

避免会产生可见重复几何图案的转场——瓦片网格、六边形格子、均匀的点阵、等间距的圆形斑点。不管背后的数学多巧妙，它们看起来都廉价又做作。有机噪声（FBM、域扭曲）是好的，因为它不规则。几何重复是坏的，因为眼睛会立刻看出网格。
