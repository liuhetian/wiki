# 故事设计 —— 无人出镜讲解视频

在 Step 3 用这份参考来为无人出镜讲解视频写 `STORYBOARD.md` 和 `SCRIPT.md` —— 这类视频讲一个话题、概念、操作方法、清单或叙事，全部基于文字构建，**没有产品、没有网站、也没有抓取来的素材**。

本文件定义的是故事：视频教什么、按什么顺序教、每一帧为什么存在。它不定义布局、视觉效果、动画或最终的 markdown schema。确切的文件语法遵循 `../../hyperframes/references/storyboard-format.md` 和 `../../hyperframes/references/script-format.md`。

## 先读

动笔之前先读这些输入：

1. `hyperframes.json` —— 锁定的 brief：角度、时长、画面比例、语言。
2. `frame.md` —— 调性、情绪、设计系统和语域。
3. `capture/extracted/visible-text.txt` —— 文章 / 笔记 / 话题 / brief（**信息**的来源）。
4. `user_script.txt` 和 `VO_MODE`，在用户粘贴了脚本时。

这里没有 `asset-descriptions.md`，也没有 `capture/assets/` 可看 —— 这是无人出镜的视频。每一个视觉元素都在下游（Steps 4-5）自创；你在这里的工作是**叙事**，不是一份视觉素材清单。

## 输出

创建两个文件：

- `STORYBOARD.md` —— 教学计划，每个段落节拍一帧。
- `SCRIPT.md` —— 锁定的旁白，只针对有口播的帧。

分镜里的每一帧都必须包含分镜格式参考里要求的字段，外加下面的叙事元数据。

## 核心规则

一篇文章是信息倾倒。一支视频是一次有引导的理解过程。

不要沿用段落顺序。把源文本重新排序、合并、删减、压缩成一条清晰的教学序列。剥掉枝节；把主干露出来。**最常见的失败就是按原顺序复述文章 —— 不要这样做。** 输入文本是信息的来源，不是故事模板。

## Step 3 方法

### 1. 提炼教学真相

从 brief 和文本中识别出：

- 受众 —— 视频在对谁说话，他们已经知道（或不知道）什么。
- 缺口或利害 —— 这段讲解要解决的困惑、问题或"为什么要在乎"。
- 论点 —— 观众看完应该带走的那个一句话想法。
- 主干 —— 层层推向论点的 3-6 个想法（机制 / 步骤 / 条目 / 段落节拍）。
- 证据 —— 为它落地的具体数字、例子、对比或演算案例。
- 落点 —— 收获，或者号召观众去思考 / 尝试 / 行动。

围绕论点写分镜，而不是围绕文章的章节写。

### 2. 让语域匹配 `frame.md`

把 `frame.md` 当作一份软性指引 —— 视觉系统调的是**语气**，不是结构：

| `frame.md` 信号 | 对故事的影响 |
| --- | --- |
| 温暖、手作感、像笔记 | 朴素、深思熟虑、不浮夸；有人情味 |
| 大胆、海报感、断言式 | 短促有力的段落节拍，自信的论断 |
| 友好、精致、现代 | 平易近人的直接称呼，更轻松 |
| 文学性、技术但有人味 | 有思考、精确；适合代码 / 开发者内容 |

教学真相决定弧线。视觉系统调整语气。

### 3. 选一种讲解结构

挑**一种**结构（或者明确说出一个复合结构）。不要把不同结构的阶段拼接在一起 —— 每种结构都是一条完整的理解路径。

| 结构 | "它是……" | 当内容载荷是……时使用 | 主体形状 |
| --- | --- | --- | --- |
| `concept-explainer` | "X 是什么，为什么重要" | 一个受众半懂不懂的想法 / 术语 / 现象 | 说出概念 → 一层一层揭示机制 → 落到含义上 |
| `how-to-process` | "这是怎么做 / X 是怎么运作的"，有顺序的步骤 | 一个有清晰起点→终点的流程或机制 | 在一个一致的视觉舞台上走 3-6 步，每步一个动作 |
| `listicle` | "关于 X 的 N 件事" | 一组平行、地位相当的条目（技巧、错误、理由） | hook → N 个大致相当的条目 → 收尾；三段式最有力 |
| `story-explainer` | 通过一条叙事弧线来教 | 案例研究、历史、警示故事 | 铺垫 → 张力 → 转折 → 解决 → 教训；教训可以推而广之 |

**怎么选：** 要理解一个想法 → concept；一个有顺序的流程 → how-to；平行、地位相当的条目 → listicle；一个具体的叙事 / 案例 → story。

**复合结构**是在一条外层弧线里叠一个内层节奏 —— 例如 `concept-explainer with process`（在机制阶段里放有顺序的步骤）、`story-explainer with how-to`。在 frontmatter 里把 `arc` 设为所选的结构（或 `<outer> with <inner>`）。下游的视觉阶段会读它来把握节奏：内层节奏是 process，意味着在一致的舞台上接缝更紧、帧更短。

### 4. 搭建帧序列

每一帧都需要一个清晰的任务。避免只是在说"更多细节"或"另一个要点"的帧。

为每一帧定义以下内容（使用分镜格式的字段，并在该帧的元数据 + 正文里加上这些叙事补充）：

- `type` —— `hook | pain_point | product_intro | feature_showcase | benefit_highlight | social_proof | branding | cta` 之一。这个枚举与下游视觉层共用，用于把握节奏；按下面的映射把它**改作**教学用途。
- `persuasion` —— 一种**有名字的**修辞 / 清晰化技法（见目录），而不是"讲解这个想法"。
- `beat` —— 目标感受（见词汇）。
- `scene` —— 一句话的视觉想法，不是详细的构图。
- `voiceover` —— 口播的引导文字；无声帧留空。
- `transition_in` —— 一个 registry 转场名（见"转场"）。
- `blueprint` *（可选候选）* —— 查阅 `../../hyperframes-animation/blueprints-index.md` 里的"角色→蓝图"菜单；当某个经过验证的形状契合这一拍时，标上它的 id（只是标记，不是承诺 —— Step 4 会确认或推翻）。然后**按那个蓝图所暗示的形状来写 `voiceover`**，让这句台词在 Step 4 运行之前就已经适合揭示。哪些段落节拍存在仍由教学真相决定 —— 绝不为了套某个形状去凭空添加、删掉或扭曲一拍；没有合适的就省略 `blueprint`，平实地写这句台词。

在每一帧下面的正文里写明：

- `narrativeRole` —— 这个场景在讲解中的**任务**（例如"把复利具象化成一个雪球"，而不是"展示一张图表"）。
- `keyMessage` —— 看完这一帧观众应该理解的那一件事（一句话）。

### type 枚举的改作（共用枚举 → 讲解视频的角色）

这个枚举与下游视觉层共用；把你的讲解角色映射到它上面，让下游的节奏与这一帧的任务相匹配：

| 你想要的讲解角色 | 使用的 `type` | 为什么用这个值 |
| --- | --- | --- |
| Hook / 好奇缺口 | `hook` | 杠杆最高的开头 3-5 秒。 |
| 痛点 / 问题 / 为什么要在乎 | `pain_point` | 讲解要解决的摩擦或缺口。 |
| 说出核心概念 | `product_intro` | "介绍主角" —— 这里的主角是那个**想法**。 |
| 机制 / 步骤 / 条目 | `feature_showcase` | 主体的一个单元 —— 流程中的一步、一个机制、一个条目。 |
| 含义 / 回报 / "那又怎样" | `benefit_highlight` | 理解之后的后果或价值。 |
| 证据 / 例子 / 数据点 | `social_proof` | 一个具体的落地支点：一个数字、一个演算例子、一个对比。 |
| 论点 / 收获 / 原则 | `branding` | 哲理性的落点 —— 可推而广之的想法，那一句话。 |
| 号召思考 / 尝试 / 行动 | `cta` | 收尾的请求 —— 试一试、留意它、质疑它。 |

主体通常是一串 `feature_showcase`（步骤 / 机制 / 条目），穿插 `benefit_highlight`（含义）和 `social_proof`（例子 / 数据）。至少应该有一个 `feature_showcase` 或 `product_intro`（每支讲解视频都有一个主体和一个被说出名字的想法）。

## Hook 策略

为开头 3-5 秒挑一种开场策略。对讲解视频来说，hook 要打开一个认知缺口或者亮出利害：

| 策略 | 什么时候用 | 示例 |
| --- | --- | --- |
| 惊人的统计数字 | 一个可信的数字能量化利害。 | "人类制造过的塑料里，90% 从未被回收过。" |
| 反问 | 立刻制造一个认知缺口。 | "为什么年纪越大，时间好像过得越快？" |
| 反直觉的论断 | 真相与普遍认知相反。 | "给高速公路多加几条车道，反而会让交通更堵。" |
| 认同痛点 | 受众已经感受到了这种困惑。 | "人人都说'分散投资就好' —— 却没人说这到底什么意思。" |
| 直观的隐喻 | 想法很抽象，需要变得具体。 | "你的注意力是一盏聚光灯，各个 App 都在抢它的开关。" |
| 宣告概念 | 术语本身就是主题；让它好记。 | "这个现象有个名字：旁观者效应。" |
| 直接称呼 | 受众定义得很清楚。 | "如果你曾经照着菜谱做到一半气得撂挑子 —— 这条视频就是给你的。" |
| 想象 / 情境 | 用一个思想实验框住整支视频。 | "想象一下，钱如果不花掉就会贬值。" |
| 利害 / 后果 | "为什么现在要在乎"是一项真实的代价或风险。 | "这一步做错，整批就全毁了。" |

hook 必须制造好奇、张力或利害。不要用一个泛泛的定义开场。按 `../../hyperframes-creative/references/story-spine.md` 的说法：hook 要说观众的语言（理解之后的回报，绝不是源文本的章节标题），并且论点（`message`）要在第 2 拍之前落地 —— 之后的讲解都是它的证据。

## 清晰化 / 修辞技法目录

`persuasion` 是一个**有名字的技法** —— 这一帧如何让想法落地、变得清晰 —— 而不是一个模糊的意图。同时用到好几种时可以组合（例如"类比 + 渐进揭示"）。

| 类别 | 技法 |
| --- | --- |
| **具象化** | 类比 / 隐喻 · 具象化（抽象 → 可触摸的物体）· 用真实数字演算的例子 · 锚定在一个熟悉的参照物上 |
| **按顺序揭示** | 渐进揭示（一次一个术语 / 一层）· 逐步搭建（简单 → 一般情况）· 路标提示（"首先……然后……最后"） |
| **对比** | 前后对照 · 普遍认知 vs 现实 · 两个选项的比较 · 反例（这里是它失效的情形） |
| **结构** | 三段式 · 编号列举 · 问题→答案配对 · 先框后填（先说出形状，再往里填内容） |
| **证据** | 统计证明 · 引用 / 出处 · 演示（展示机制运转起来）· 因果链（A → B → C） |
| **记忆与落点** | 回扣（回到 hook 的画面）· 提炼（压缩成一句话）· 新造术语 / 助记口诀 · 推而广之（具体 → 原则） |

目录里没有合适的技法时，就地命名一个新的并解释它的机制（例如"减法式框定：先说这个概念*不是*什么，以此来定义它"）。绝不写泛泛的"讲解这个想法"。

## 情绪节拍

`beat` 是一个词或一个简短的复合短语（例如"好奇与清晰"）。避免泛泛的"积极" / "感兴趣"。讲解视频沿着一条理解弧线走：

- **负向低谷** —— *打开缺口*（hook / pain_point）：好奇 · 困惑 · 惊讶 · 张力 · 担忧 · 怀疑 · 认出 · 被吸引
- **转折点** —— *定向*（product_intro / 说出概念）：清晰 · 找到方向 · 期待 · 专注
- **搭建** —— *搭建理解*（feature_showcase / benefit_highlight / social_proof）：理解 · "啊哈" · 自信 · 着迷 · 预见 · 势头 · 信服 · 愉悦 · 不安（用于一个注意事项）· 掌握
- **解决** —— *落地*（branding / cta / 结尾）：清晰 · 满足 · 决心 · 受启发 · 必然感 · "现在我懂了"

复合节拍往往最有力，例如"惊讶 + 认出"、"理解 + 愉悦"。

## 主体是一个序列，不是单独一帧

一支讲解视频的核心几乎总是**在一个一致的视觉舞台上的 3-6 个主体帧**，每一帧推进一个机制 / 步骤 / 条目 / 层次，层层累积地搭建理解。一个孤立的主体帧很少能教会什么。

- **concept-explainer：** 说出概念（`product_intro`）→ 一层一层揭示机制（一串 `feature_showcase`，穿插用 `benefit_highlight` 讲"那又怎样"、用 `social_proof` 给一个落地的例子）。
- **how-to-process：** 每一步一个 `feature_showcase`，有顺序，在同一个舞台上。把被操作的对象带过相邻的步骤（见"跨帧连续性"）。
- **listicle：** 每个条目一个 `feature_showcase`；条目是平行的，所以它们之间默认用 `cut` / `push-slide`。
- **story-explainer：** 帧跟随各个段落节拍（铺垫 / 张力 / 转折 / 解决 / 教训）；type 按表格映射（张力用 `pain_point`，教训用 `branding`）。

## 跨帧连续性（不按 worker 分组）

这个框架是**每个 worker 构建一帧** —— 没有那种把几帧交给同一个 worker 的"连续运行"。一串帧要读起来像一个连续镜头，靠的是两个分镜层面的杠杆，两个都归你管：

1. **一致的舞台** —— 连续的主体帧共用同一个构图想法（同一张图示在生长、同一条数轴、同一张桌面），并在每一帧的 `scene` 里写明，这样 Step 4 和各个 worker 能保持舞台稳定。
2. **一致的转场** —— 为一个序列挑一种接缝类型（有顺序的步骤通常用 `push-slide <DIR>`，柔和的层次揭示用 `crossfade`），并在整串里重复使用，让这些帧感觉像一股流，而不是一张张分开的幻灯片。

当某个元素确实要在两个想法之间*变形*时（一个图示节点变成一根图表柱、一个公式变成它的结果），把它保留在**一帧之内**，作为一个展开类的段落节拍（入场 → 变形 → 收住），而不是把它拆到一个接缝的两边 —— 这个运动归 worker 管。在这一帧的 `scene` / 叙事里注明这个意图；Step 4 会把它变成一个带时间码的镜头序列（把候选的 `blueprint` 实例化）。

## 转场

`transition_in` 里只能用 registry 的转场名：

`cut | crossfade | blur-crossfade | push-slide LEFT | push-slide RIGHT | push-slide UP | push-slide DOWN | zoom-through | squeeze`

为整支视频挑 2-3 种转场类型并重复使用。第 1 帧用 `cut` 作为占位（它之前没有帧）。让接缝与叙事匹配：有顺序的步骤 → 一致的 `push-slide`；柔和的层次揭示或氛围转换 → `crossfade` / `blur-crossfade`；推进到一个细节或往回拉 → `zoom-through`；干净利落地换话题或换到新的清单条目 → `cut`。

## 无人出镜的视觉 —— 没有素材清单

每一个视觉元素都在下游根据每一帧的 `narrativeRole` / `keyMessage` / `scene` 自创 —— 字体排版、抽象图形、图示、数据可视化都是一等公民。因此：

- **不要**写一行 `asset_candidates`，把打算做的图示或字体排版描述得好像它们是文件一样。视觉意图写在 `scene` + `narrativeRole` 里；视觉阶段会读这些。
- **唯一**的真实素材是用户提供、已经放在 `public/<basename>` 的图片。这时加一行 `asset_candidates: public/<basename> — <≤25 words: what it is>`。绝不凭空编造路径，也绝不引用 `capture/`。

## 脚本规则

### 如果没有粘贴来的脚本

逐帧写紧凑的旁白：

- 每个有口播的帧 1-2 句；通常 6-20 个词。
- 具体、有人味；是在教，不是把文章念出来。
- **把每句台词写成一个个分立的提示点，而不是一口气不停顿的长句。** Step 5 会*在旁白说到*屏幕上每个元素时再揭示它（反 PowerPoint 的机制）。一句短语边界清晰的台词 —— "先是雪球 —— 然后是山坡 —— 然后是速度" —— 白送给镜头它的揭示节奏；一个长长的从句则让这一帧无从卡点。
- **强**（具象化）："复利不是加法，是一个雪球 —— 每滚一圈都会带上上一圈的雪，然后再多滚一些。"
- **弱**（复述文章）："这项发表于 2019 年的研究考察了三个队列，发现……" —— 这是在念，不是在讲解。

避免："解锁……的力量"、"无缝体验"、长串的名词短语罗列、只是充当填充过渡的帧（"或者……"）。

**无声帧是允许的，在讲解视频里也很常见** —— 一张图示自己拼装起来、一个演算例子动起来、转折前一拍停住的张力。把 `voiceover` 留空，并且不把这一帧写进 `SCRIPT.md`；这时 `narrativeRole` + `persuasion` 必须承载脚本没说出来的东西。

### 如果 `VO_MODE = restructure`

把 `user_script.txt` 当作素材。改写、重排、合并或删减，以契合所选的结构和目标时长。

### 如果 `VO_MODE = verbatim`

不要改写用户的原话。按句子或段落边界把脚本切成帧大小的块（可以在一个自然的从句边界处拆开长句，但不要改字）。最终时长以提供的脚本为准。

## 音乐与静音

分镜顶部的 YAML 块带有一个 `music:` 字段 —— 音频步骤据此检索 BGM 情绪（例如 `music: confident minimal tech underscore`）。省略它时会依次回退到 `message:` → `arc:` → 一个中性默认值，所以除非显式关闭，BGM 都会播放。

- **`music: none`** —— 关闭 BGM（如果有旁白，旁白照常）。
- **`music: none` + 没有 `SCRIPT.md` + 没有 `sfx:` 提示点或宿主音频** —— 标准的**完全静音标记**：没有旁白、没有 BGM、没有音效（SFX）。`audio.mjs` 什么都不生成，音频步骤被干净地跳过。当用户要求做一支静音 / 不要音乐的视频时，严格使用这个写法。

## 帧模板

使用核心分镜格式要求的确切字段。下面是每一帧应该满足的叙事形状：

```md
## Frame N — Short name

- scene: one clear visual idea
- voiceover: "spoken guide text, or empty"
- duration: rough estimate in seconds
- transition_in: crossfade
- status: outline
- src: compositions/frames/NN-short-name.html
- type: feature_showcase
- persuasion: Progressive disclosure
- beat: comprehension
```

## 最终检查清单

在请用户批准之前，核对：

- 说出了一种讲解结构（只有明确命名时才用复合结构）；序列由叙事驱动，而不是由段落顺序驱动。
- 开场用了一种有名字的 hook 策略。
- 每一帧只有一个任务；主体是层层累积搭建的（一串 `feature_showcase` / `benefit_highlight` / `product_intro`），而不是单独一个孤立的主体帧。
