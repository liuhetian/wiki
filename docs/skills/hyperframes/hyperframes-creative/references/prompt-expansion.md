# Prompt 扩写

每个 composition 都要运行。扩写不是为了把一个短 prompt 拉长 —— 而是把用户的意图落实到设计规范（`frame.md` 或 `design.md`）和 `house-style.md` 上，产出一份所有下游 agent 都会以同样方式理解的一致的中间产物。

在设计方向确立之后（Step 1）运行。扩写消费设计规范（`frame.md` 或 `design.md`，如果存在），产出的内容引用其中的精确取值。

## 前置准备

生成之前先读：

- 设计规范 —— `frame.md` → `design.md` → `DESIGN.md`（读第一个存在的）—— 提取品牌颜色、字体、情绪和约束。扩写引用这些精确取值（hex 色值、字体名）；不发明新的。
- `references/beat-direction.md` —— 逐拍规划格式（概念、情绪、编排动词、转场、纵深层次、节奏）。扩写按这个格式输出每个场景。
- `references/video-composition.md` —— 视频媒介关于密度、尺寸和色彩存在感的规则。扩写会自动应用这些规则。
- `house-style.md` —— 它关于背景层（2-5 个装饰元素）、颜色、运动、字体排印的规则适用于每个场景。扩写写出的内容要符合这些规则。

如果还不存在设计规范（`frame.md` 或 `design.md`），先运行 Step 1（设计系统）。没有设计上下文的扩写只会产出泛泛的场景拆解，后面的 agent 会无视它。

## 为什么始终要运行

**扩写绝不是原样透传。** 每一个用户 prompt —— 不管写得多详细 —— 都只是一颗*种子*。扩写的工作是把它充实成一份完整成型的逐场景制作规格，让场景子 agent 可以直接照着搭建。

即使是一份详细的 7 场景 brief，也缺少只有扩写才会补上的东西：

- **每个场景的氛围层**（house-style 要求 2–5 个：径向辉光、幽灵文字、细线、颗粒、主题装饰）—— 用户的 prompt 几乎从不列出这些；扩写把它们加上。
- **每个装饰元素的次级运动** —— 呼吸、游移、脉动、环绕。没有氛围运动的装饰元素显得死板。
- **让场景显得真实的微细节** —— 套准标记、刻度指示、等宽字体的坐标标签、字体排印上的点缀、背景里的代码片段、网格图案。用户想不到要提的东西。
- **对象层面的转场编排** —— 不是「交叉淡化」，而是「X 向外扩张并变成 Y」。具体的时长、ease，以及变形的来源 / 目标。
- **每个场景内部的节奏拍点** —— 张力在哪里积累，在哪里停留让观众喘口气，强调词落在哪里。
- 来自设计规范的**精确 hex 值、字体排印参数、ease 选择** —— 不留任何模糊之处让场景子 agent 去猜。

面对一个详细的 prompt，扩写的工作不是概括或透传 —— 而是**把用户写下的东西变得更丰富**。用户的内容保留；氛围、氛围运动和微细节叠加在上面。这正是一个「符合 brief 的场景」和一个「显得鲜活的场景」之间的差别。

单遍生成的 composition 和多场景流水线生成的 composition 之间的质量差距，就来自这一步。扩写把丰富度前置，让每个场景子 agent 都从一份丰富的 brief 出发搭建，而不是从一份简短的 brief 出发。

**不要跳过。不要透传。** 单场景 composition 和微不足道的修改是仅有的例外。

## 生成什么

扩写成一份完整的制作 prompt，包含以下几节：

1. **标题 + 风格块** —— 引用设计规范里精确的 hex 值、字体名和情绪。**不要**发明色板 —— 照引设计里给出的。

2. **节奏声明** —— 在展开任何场景之前，先给场景节奏命名。例如：`hook-PUNCH-breathe-CTA` 或 `slow-build-BUILD-PEAK-breathe-CTA`。各视频类型的节奏模板见 `references/beat-direction.md`。

3. **全局规则** —— 视差层次、微运动要求、转场风格、主转场 + 强调转场。让能量匹配情绪（平静 → 缓慢的 ease，高能 → 利落的 ease）。

4. **逐场景节拍** —— 每个场景都用 beat-direction 的格式：
   - **概念** —— 用 2-3 句话说清核心想法。什么视觉**世界**（WORLD）？什么隐喻？观众应该**感受**（FEEL）到什么？
   - **情绪导向** —— 文化 / 设计上的参照，而不是 hex 色值。（「包豪斯色彩研究」、「电影片头」、「编辑式的沉静」）
   - **纵深层次** —— 按概念需要安排 BG 处理、MG 内容，以及 FG 强调或结构细节。用 `video-composition.md` 来决定密度；不要硬凑元素数量，也不要为了凑数编造内容。
   - **动画编排** —— 每个元素一个具体动词。高：SLAMS、CRASHES。中：CASCADE、SLIDES。低：floats、types on、counts up。每个元素都要有一个动词。如果你说不出这个动词，说明这个元素还没设计好。
   - **出场转场** —— shader 或 CSS，写明具体类型和参数。不是「交叉淡化」，而是「blur crossfade，0.4s，power2.inOut」。

5. **反复出现的母题** —— 来自品牌色板、贯穿各场景的视觉线索。

6. **负面 prompt** —— 要避免什么，如果有设计规范就参考它的约束。

## 输出

把扩写后的 prompt 写到项目目录下的 `.hyperframes/expanded-prompt.md`。**不要**把它倒进对话里 —— 它会有几百行。

告诉用户：

> 「我已经把你的 prompt 扩写成了一份完整的制作拆解。在这里查看：`.hyperframes/expanded-prompt.md`
>
> 它包含 [N] 个场景，共 [duration] 秒，写明了具体的视觉元素、转场和节奏。想改什么都可以直接改，准备好继续时告诉我。」

只有在用户批准或说继续之后，才进入搭建。
