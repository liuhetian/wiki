# 分镜配方 —— 像发布影片那样规划一支视频

凡是运行要基于分镜做规划的地方都适用（`brief-contract.md` 里的 `storyboard: yes`）。本文件掌管**如何制作分镜**：里面放什么，以及用户审阅的那一个 HTML 页面。`review-loop.md` 掌管什么时候问用户；`storyboard-format.md` 掌管脚本解析的 `STORYBOARD.md` 文件；`story-spine.md` 掌管故事的顺序。这套方法提炼自已发布的几支发布影片的分镜（一个页头、一条有名字的主干、一张节拍清单、一张样张、一轮审阅）以及它们的交接文档对分镜的描述，外加几条规则（停住的帧、幻灯片 / 屏保禁令、字幕避让区）—— 这几条即使在某支发布影片里没有出现，也在更广泛的分镜语料里一贯出现。这里没有任何东西是 Studio 的功能：分镜由 agent 写，用户在对话里和浏览器里阅读。

## 1. 先摆出决定，再写任何一拍

message、受众、弧线和格式放在 `STORYBOARD.md` 的 frontmatter 里（`storyboard-format.md`）；其余的放在第一个 `## Frame` 标题之上的各个小节里。帧包（packet）会截取从一个帧标题到下一个帧标题之间的全部内容，所以放在最后一帧之后的小节会漏进那一帧的帧包里。在对话的提案里重复前三项：

- **Message**：一句话，写成一个论断，而不是一个话题（「关闭并不是终点」，而不是「关于检查器」）。
- **受众与弧线**：谁在看，以及用一行话命名的弧线（痛点 → 转折 → 证据 → logo，或者工作流自己的原型）。
- **格式**：画幅比例、目标时长、要不要旁白、要不要音乐。字幕避让区（有字幕时内容放在上方约 83% 的区域内）。
- **主干**：串起每一拍的那一个手法，现在就命名，而不是在搭建过程中才发现（一个常驻的窗口、一个终于发出声音的静音按钮、一个引领每次转场的背景）。
- **品牌，取自抓取**：按角色列出色板并附 hex，三个字体角色（display、无衬线、mono）及其字号，圆角和 easing，每个 token 注明出处。从真实的网站或产品里取，绝不凭记忆；它们存放在 `frame.md` 里。
- **禁令**：一份简短的、针对本视频的「不要」清单（不要辉光、不要左右并排的讲解版式、不要伪造的产品 UI、不要静态的结尾卡）。点名要避免的两种运动失败：幻灯片（每一拍都是一张新卡片）和屏保（什么都没说的运动）。
- **停住的帧**：刻意分配一拍，什么都不动，让台词落地。

## 2. 节拍清单

一个想法一拍，每拍一个焦点。给每一拍起一个简短的语义化名字，它同时也会是这一拍的 composition 文件名。

| 字段       | 规则                                                                                                                                    |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 标题     | `NN — Name (start–end, ~dur)`，用绝对时间。把各拍时长加起来并写明总时长；用算术核对它是否符合目标时长。 |
| 拍长 | 1.5–3.5 秒。需要读的一拍给约 3 秒；只负责交接的一拍给 1.5–2 秒；一句 5–7 个词的台词给 2–2.5 秒。               |
| 画面上   | 可见的内容，用具体的措辞描述（对象、数量、位置），画面上的每个字都用引号原文写出。                 |
| 旁白   | 逐字写出；无声影片写 `onscreen`。揭示要落在点名它的那个词或节拍提示上。                                         |
| Hero 道具   | 持续存在的那个对象，以及它回归的那一拍（呼应）。呼应拍要写明它回应的是前面哪一拍。               |
| 运动      | 从一个小词汇表里挑出的、有名字的动作，带 easing 和时长。这一拍开始后 0.2 秒内必须出现第一个可见运动。                  |
| 出场接缝    | 通往下一拍的、有名字的转场及其方向。整部影片只用一条方向规则（默认向左）。             |
| 音频提示   | 音效或音乐提示及其时间点（影片有声音时）。                                                                       |
| 约束  | 每一个可能流于平庸的拍子，至少写一条明确的「不要……」。                                                                            |
| 为什么         | 这一拍在故事里的职责，追溯到 message。追溯不到的一拍就删掉。                                           |

真实的产品证据就得是真实的：一张抓取的截图、真实的命令输出，或者一个占住位置、带标注的占位拍。绝不要去近似模仿所发布产品的 UI：用它的抓取或录屏，只重建抓取无法动起来的部分，或者从它自己的设计源（`/figma`）重建。作为背景展示的第三方工具，要根据抓取忠实地重建。影片描绘真实事物的地方，加一行真实性说明，讲清楚哪些是真实的。

让分镜变得具体的工艺手法，在 `docs/prompting/storyboards.mdx`（喘息、呼应、双色纪律）和 `docs/prompting/motion.mdx`（hero 道具、累积）里有带示例的讲解；按名字使用它们。

## 3. `storyboard.html`：用户审阅的页面

根据 `STORYBOARD.md`，在项目根目录写一个自包含的 HTML 文件 `storyboard.html`。告诉用户路径，并请他们在浏览器里打开。它是审阅界面，必须漂亮到足以让人据此评判这部影片。

- **页头**：带版本号（`v1`）的标题、一行导语，以及一个标明分辨率、时长和拍数的标签。
- **网格**：三列 16:9 的格子（`aspect-ratio: 16 / 9`、`container-type: inline-size`，尺寸用 `cqw`，让样张和搭建结果一致），按时间顺序排列，有分幕时归在幕标题条下面。
- **每个格子**带 `id="frame-NN"`（搭建时从这里读取版式），用真实的字体和品牌色、写上真实的文字，画出这一拍的关键时刻，面板、图表和媒体用简单的形状表示，焦点上用一个强调色。然后是一行标签（左边 `NN · NAME`，右边 `id · start–end`），一段说明先动什么、接缝朝哪个方向走的备注（粗体引导语，一两句话），以及一个写着接缝名字的小标签。
- **两个收尾格子**：一张接缝图（所有接缝排在一条带上）和一个 token 格子（色板、字体角色、禁令）。
- **不要运动，不要脚本，不要外部素材。** 字体用本地 `@font-face` 或系统字体栈；图片内联或用相对路径。它必须能从 `file://` 打开。

一张草图每个格子几十行 HTML；整张样张几分钟就能完成。草图的保真度正是关键所在：审阅者针对的是摆放位置、层级和文案，这也是为什么后面的搭建只给版式「穿衣服」，而绝不重画它。

## 4. 审阅轮

1. 先呈现对话里的提案（`story-spine.md` § 3），再给出样张。
2. 把用户的意见逐字记录在 `## Changes from v1` 下，把未解决的问题记录在 `## Still open` 下（都放在第一帧之上），然后升版本号，并且**只修改被点名的那几拍**。
3. 重复，直到用户说版式已锁定，然后把锁定的内容列在 `## Locked` 下（放在第一帧之上，理由同 § 1）。锁定之后才开始搭建。
4. 搭建落地之后，以 composition 为准：根据 `index.html`（有旁白时再加上转写稿）重新生成时间表，并更新 `STORYBOARD.md` 和 `storyboard.html` 使之一致，因为每一支发布影片都偏离过它的分镜。写明最终时长。

在被要求之前不要渲染。
