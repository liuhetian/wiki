# 效果 registry

每一种效果、它的参数以及每个参数的可用范围。超出范围的值会在读取时被钳制，所以任何能解析的东西都可以安全地实现。**AUTO** 标记的是自动化 lane 可以驱动的参数；没有标记的都不能随时间变化（见底部的说明）。

由 `@hyperframes/core/audio-fx` 里的 `HF_AUDIO_FX` 生成，它是唯一事实来源——如果这张表和代码不一致，以代码为准。

## 滤波器——一条 track 可以占据哪些频率

| 效果      | 参数                                                                                                   |
| ----------- | ----------------------------------------------------------------------------------------------------------- |
| `highpass`  | `frequency` 20–20000 Hz（300，对数）**AUTO** · `q` 0.1–20（0.707，对数）**AUTO** · `poles` `1`\|`2`（2）       |
| `lowpass`   | `frequency` 100–20000 Hz（8000，对数）**AUTO** · `q` 0.1–20（0.707，对数）**AUTO** · `poles` `1`\|`2`（2）     |
| `peaking`   | `frequency` 20–20000 Hz（1000，对数）**AUTO** · `gain` −40–40 dB（0）**AUTO** · `q` 0.1–20（1，对数）**AUTO** |
| `lowshelf`  | `frequency` 20–2000 Hz（200，对数）**AUTO** · `gain` −40–40 dB（0）**AUTO**                                  |
| `highshelf` | `frequency` 500–20000 Hz（4000，对数）**AUTO** · `gain` −40–40 dB（0）**AUTO**                               |

`q` 是带宽——越高越窄。`poles` 是斜率：`2` 是常见的 biquad（12 dB/oct），`1` 更平缓（6 dB/oct）。搁架滤波器没有 `q`：Web Audio 规范对它们不使用这个值，所以就算有这个控件也什么都不会改变。

## 动态——电平随时间如何变化

| 效果       | 参数                                                                                                                                                                      |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `gain`       | `gain` −60–12 dB（0）**AUTO**                                                                                                                                                  |
| `compressor` | `threshold` −60–0 dB（−24）· `ratio` 1–20（4）· `attack` 0.01–2000 ms（20，对数）· `release` 0.01–9000 ms（250，对数）· `knee` 1–8（2.83）· `makeup` 0–36 dB（0）· `mix` 0–1（1） |
| `limiter`    | `limit` −24–0 dB（−1）· `attack` 0.1–80 ms（5）· `release` 1–8000 ms（50，对数）· `level_out` −24–24 dB（0）                                                                     |
| `gate`       | `threshold` −80–0 dB（−35）· `range` −80–0 dB（−24）· `ratio` 1–20（10）· `attack` 0.01–9000 ms（1，对数）· `release` 0.01–9000 ms（100，对数）· `knee` 1–8（2.83）               |

`gain` 上的衰减最低到 −60 dB，提升止于 +12：它是一个用来腾出空间的电平级，而一条能加 40 dB 的效果链在这有用之前很早就会削波了。`knee` 为 1 是一个硬拐角，更高的值会平缓地过渡进去。`mix` 低于 1 会把干声信号混回来（并行压缩）。`range` 是 gate 关闭时向下拉多少——一个一路拉到静音的 gate 听起来像个开关。

## 非线性——改变波形的形状

| 效果     | 参数                                                                                                                                                                  |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `saturate` | `type` `tanh`\|`atan`\|`cubic`\|`exp`\|`alg`\|`quintic`\|`sin`\|`erf`\|`hard`（tanh）· `threshold` −40–0 dB（−6）· `output` −24–24 dB（0）**AUTO** · `oversample` 1–8×（4） |
| `bitcrush` | `bits` 1–32（8）· `samples` 1–250×（1）· `mix` 0–1（1）                                                                                                                     |

`tanh` 是最温和的曲线，`hard` 则是彻底的削波。更高的 `oversample` 消耗更多 CPU，同时压低混叠。`samples` 把每个采样重复 N 次——一种粗糙的降采样，lo-fi 的质感就是从这里来的。

| `reverb` | `size` 0.05–1（0.7）· `damping` 0–1（0.5）· `wet` 0–1（0.35）**AUTO** · `dry` 0–1（0.7）**AUTO**                                                                    |
| `chorus` | `delay` 1–100 ms（7）**AUTO** · `depth` 0–10 ms（2）**AUTO** · `speed` 0.01–10 Hz（1）**AUTO** · `mix` 0–1（0.5）**AUTO**                                           |
| `phaser` | `in_gain` 0–1（0.4）**AUTO** · `out_gain` 0–2（0.74）**AUTO** · `delay` 0.1–5 ms（3）· `decay` 0–0.99（0.4）· `speed` 0.1–2 Hz（0.5）**AUTO** · `type` `0`\|`1`（0） |

混响卷积的是一个*生成出来的*脉冲，而预览和渲染生成的是同一个——所以无需附带脉冲文件，一个房间就是可复现的。更高的 `damping` 会让尾音的高频衰减得更快，这就是让一个大房间听起来像软装房间的原因。`feedback` 接近其范围上限时尾音非常长；它被限定在 1 以下，因为到 1 时尾音永远不会衰减。

## 为什么有些参数不能被自动化

自动化以原生 `AudioParam` 斜坡和曲线的形式一次性交给音频线程，这正是它能保持采样级精确、并且在预览和渲染之间完全一致的原因。因此，一个参数只有在背后有 `AudioParam` 时才能被自动化。有三类没有：

- **worklet 处理器选项**——`compressor`、`limiter`、`gate` 和 `bitcrush` 是整体配置的 AudioWorklet，所以**它们的参数一个都不能自动化**。
- **WaveShaper 曲线**——`saturate` 的 `type`、`threshold` 和 `oversample` 会重建曲线；只有它的 `output` 级是一个真正的 param。
- **卷积脉冲**——`reverb` 的 `size` 和 `damping` 会重新生成脉冲；`wet`/`dry` 是增益级，可以正常自动化。

要让其中某个效果随时间表现不同，改为自动化它周围的一个 `gain` 级：compressor 前面某个 `gain` 上的一条 lane 会改变 compressor 被推动的力度，这就是自动化它的 threshold 本来能做到的大部分事情。
