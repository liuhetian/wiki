# HyperFrames Studio 约定

Studio 为每个顶层元素画一行 timeline。遵循下面规则的项目，打开后是一条简短、易读的 timeline；不遵循的，打开后是一堵用户没法编辑的无标签行组成的墙。这些是关于要构建什么的约定。至于如何修改一个 clip，请遵循 `/hyperframes-core` 的 `references/creator-editing-recipes.md`，绝不要为同一种编辑自创另一种做法。

## 0. 动手之前先对话

打开文件之前先读消息。判断它要求的是什么：

| 对方 | 你 |
| ------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 点名了一个改动，不管措辞多客气（"把标题放大点"、"能把第三个场景剪掉吗？"） | 去改。 |
| 对已构建的片子给出一条感受类意见（"开头感觉一顿一顿的"、"时长不够"） | 找到原因，改动那个可以度量的东西，说明这条意见指的是什么、动了什么，并按 `/hyperframes-creative` 的 `references/storyboard-recipe.md` § 4 记录下来。 |
| 问了一个问题，没有点名任何改动（"标题为什么会跳？"） | 回答它。什么都不改。 |
| 说什么都别改、先等等、"只是想想"、"我们聊聊" | 不改任何文件，哪怕是你注意到的一个修复。用文字提出来。 |
| 为这部片子带来一个想法，但没有具体改动（"我想让结尾感觉更宏大"） | 提出改动方案，并把它加进计划（见下文）。不改任何 composition 文件。 |
| 要求做一部新片 | 做计划（§ 5）。 |
| 批准了一个计划（"开做"、"go"） | 构建已批准的内容。 |

一条既提了问题又点名了改动的消息，既给回答也做改动。只有当你判断不出它是否在要求什么时，它才算一次对话：答错的代价是一条消息；建错的代价是一次长时间运行加一轮意见。

对话式的回复：

- 先回答，用平实的话，几句话说完。
- 只问那些答案会改变片子的问题，每个问题都附上推荐答案及其取舍（"30 秒适合信息流；60 秒能给演示留出空间"）。
- 当有一个想法需要成形时：如果是新片，按 `/hyperframes` 的 `references/pitch-round.md` 给出方向；如果是关于这部片子的想法，针对所提到的部分给出两三个选项。推荐其中一个。
- 结尾说明下一步，以及启动它的那个词（"说 build 我就开始"）。

把计划保存在项目里，而不只是聊天里：下一条消息可能开启一个看不到这次会话的新会话。按 `/hyperframes-creative` 的 `references/storyboard-recipe.md` § 4 记录一轮的方式，把它加进 STORYBOARD.md；绝不覆盖已锁定的帧。如果对方要求你什么都别改，就什么都不写：把计划放在回复里，并提出可以帮忙保存。

## 1. 每个场景都是一个 sub-composition

根 composition 只容纳带时间的宿主、媒体和音频。任何带嵌套结构的场景（一个包含子元素的 div、一个带副标题的标题、一张图表）都是一个独立文件，用 `data-composition-src` 加载，接入方式见 `/hyperframes-core` 的 `references/sub-compositions.md`。

留在根里的嵌套标记不会成为独立的一行。它会藏在一个不透明的行里，没法逐部分裁剪或移动。

编写时要当作有一条结构 lint 会拒绝任何违规。

## 2. 一条字幕 track

- 所有字幕都在同一条 track 上：一个单独的 sub-composition 宿主（一个 `data-track-index`），标记为 `data-track-kind="captions"`，按顺序承载每一个字幕组。
- 绝不每个字幕组占一行，也绝不把字幕和其他种类的元素混在同一条 track 上。
- 逐词时间规则不变：见 `/embedded-captions` 和 `caption_*` lint 规则。

## 3. 每条 track 只放一种元素

按种类分组，让每一行都是用户可以作为一组来选中、静音或拖动的一样东西。

| 种类 | `data-track-kind`      |
| --------------------------------------- | ---------------------- |
| 底层视频 / A-roll | `video`（来自标签） |
| 场景、overlay、图形 | `graphics`             |
| 字幕 | `captions`             |
| 音频（旁白、音乐、音效） | `audio`（来自标签） |

把 `data-track-kind` 放在 sub-composition 宿主上。视频和音频的种类来自标签本身，所以 `<video>` 和 `<audio>` 不需要这个属性。给每种元素分配自己的 `data-track-index`；这个数字只用于显示，绝不会改变哪个渲染在上层。层叠请用 CSS。

## 4. 安全区

任何标尺或安全框 overlay 都放在预览面板里，绝不放在 composition 内部，所以不要往 HTML 里加参考线元素。两种画幅（横屏和竖屏）使用同样两个安全框，即 Premiere 的默认值。预览开关会把它们画出来，并在每条边的中点画一个刻度。来源：`packages/studio/src/utils/previewSafeMargins.ts` 中的 `ACTION_SAFE_PERCENT` 和 `TITLE_SAFE_PERCENT`。

| 框 | 占画面比例 | 每条边的内缩 |
| ----------- | ------------------ | ------------------- |
| 动作安全区（Action-safe） | 90%                | 5%                  |
| 标题安全区（Title-safe） | 80%                | 10%                 |

- 安全边距：所有可见内容都留在动作安全框（90%）以内，字幕和关键内容留在标题安全框（80%）以内。
- 双联和 50/50 布局中，每一半的内容都留在标题安全框以内。

## 5. 一部新片：计划、分镜、构建

hyperframes-launches[^hyperframes-launches] 里的片子都是按这个顺序做出来的。每一步都有负责的文档；照着它来，不要在这里复述。

| 步骤 | 负责文档 |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1. Brief      | `/hyperframes` 的 `references/intent-interview.md`。在一个已有项目内部，只有同一部片子的后续版本才留在这里：一个新版本或一个精简剪辑，工作流和画幅不变。问它的必答项问题，跳过 `hyperframes init`，绝不覆盖 BRIEF.md 或 STORYBOARD.md，在两者里各加一个带日期的新章节，并在回复里说明。工作流或画幅不同的片子要开一个新项目，回复里也要说明这一点。 |
| 2. 方向 | `/hyperframes` 的 `references/pitch-round.md` |
| 3. 分镜 | `/hyperframes-creative` 的 `references/storyboard-recipe.md` |
| 4. 构建 | brief 路由到的工作流（`/hyperframes` § 2）及其自己的 references |
| 5. 意见 | `/hyperframes` 的 `references/review-loop.md` |

对于产品发布片，这些发布片额外补充的做法如下。当工作流选定的叙事弧另有规定时，以叙事弧为准。

- **被发布的产品用真实画面。** 在 brief 中索要一段录屏，除非工作流自己会抓取（从 URL 抓取一个网站），并在录屏到位之前用一个带标签的占位符占住它的位置。绝不要模仿被发布产品的 UI。作为背景出现的第三方工具（聊天应用、编辑器）则根据一次抓取忠实地重建。
- **一个世界。** 同一个窗口或画布贯穿各个段落节拍。逐帧拖过每一个切点：任何持续存在的东西都不能跳。
- **光标和滚动的内容。** 光标，或者被窗口自己滚出去的内容，要从窗口或画面边缘离开，而不是在画面中间淡出。元素和文字的替换，如果工作流有 `cut-catalog.md`，就按它来。
- **以命令或网址收尾，** logo 落在仍在运动的画面里。
- **每个版本都说明时长。** 超出目标时长是对方来决定的，不是你。

## 检查你的成果

运行 `hyperframes check`（它会运行 lint），修复每一条发现的问题。然后在 Studio 里打开项目，检查 timeline 是否显示一行底层视频、每个场景宿主一行、一行字幕以及若干音频行。
