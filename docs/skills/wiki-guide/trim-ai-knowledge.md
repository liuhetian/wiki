# 精简检查：删掉 AI 本来就会的

给 AI 读的文档里，AI 本来就会的内容只是噪音，会把真正的决策和坑淹掉。下面是一段检查 prompt。**它不是规范，不会自动生效**，要用的时候在对话里引用这一页。

- 适合：搭建记录、接入说明、运维手册，写的是「我们的环境 + 我们的选择」
- 不适合：本身就在整理通用知识的文章，比如 [LeetCode 热题 100](../../notes/leetcode/index.md)、统计笔记、课程。这类文章的价值就是把通用知识用自己的话重写一遍

```text
逐段检查这篇文档，每段只问一个问题：这是我们自己的，还是 AI 本来就会的？

保留：
- 我们的决策：选了什么、没选什么，一句话理由
- 我们的环境：地址、路径、文件放在哪、变量名、版本要求
- 我们踩过的坑：现象和避开的办法，一条一行
- 还没做的事

删掉：
- 通用原理和背景（协议怎么工作、某个工具为什么好）
- 安装、升级、常规配置的步骤：写一句版本要求就够
- 官方文档里有的用法、参数表、SDK 示例：给官方文档链接
- 能直接从配置文件读出来的逐行解释
- 验收过程、测试记录、实测输出
- 已经发生过、以后用不上的历史

另外：
- 用官方用法、改两个值就能解决的，不写封装脚本
- 只有维护者需要的内容（选型实测、上游来源）挪进单独的维护记录，正文最后一行链过去，注明出问题再看

先列出「删 / 留 / 挪」清单给我确认，确认后再改。
```
