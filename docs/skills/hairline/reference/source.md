# 从现成的 SVG 起

`read.mjs` 写了两个文件：`hairline-<name>-source.png` 是 SVG 的样子（墨色浅时垫深底，卡片的墨色那一行会说明）；`hairline-<name>-source.txt` 是卡片：它的 viewBox、title 和 id，墨迹的外框，每个上色形状一行，写它的外框、中心、颜色，以及它和所在或相接的形状的关系。分几段画的路径 —— 比如一个文字标志的几个字母合在一个 `<path>` 里 —— 每段一行，各标 `part 2 of 9`。先看图，再读卡片，然后在写任何概念之前按顺序回答下面这些。

**SVG 给的是身份，不是路径。图形用实体重新搭，保留来源的比例，用引擎的风格。绝不描路径。** 用户认得出自己的物件，靠的是它的部件和比例，不是它的坐标。

1. **物件是什么？** 一个词，读卡片之前从图上定。然后拿 `title`、id 和卡片核对。图和卡片对不上时，图说了算：id 是作者打的字，图是作者画的东西。
2. **哪几个部件让它成为那个物件？** 两三个，每个指向卡片上的行：`#1 机身，#3 和 #4 尾翼，#5 火焰`。这就是[从想法到概念](concepts.md)的第 2 步「找让它露馅的特征」，现在有了证据。留着这份清单：图形照它画，看样（[看样](look.md)第 14 项）拿静止姿态对照它检查。
3. **哪些比例必须保留？** 墨迹外框的宽高比，再加部件之间最要紧的两三个关系：尾翼在底部，每片宽是机身的三分之一；火焰在下面，高是机身的三分之一。这些就是进 `rings` 和 `prism` 的数。别的都由你用引擎的方式决定。
4. **什么是装饰？** 阴影、辉光、双重轮廓、卡片数出来的那些小形状，任何为了颜色才在那里的东西。它们不进来。一个图形只有一种笔画、四种粗细（规则 04）：SVG 用颜色说的，图形用一个亮标记说。
5. **物件怎么回应？** 请求里点名了手势，它就定了：概念保留它，彼此在物件的形态和读数上不同。没点名，就问一只手会对这个物件做什么。[从想法到概念](concepts.md)里的「六种已验证的反应」那张表就是菜单，每个概念从里面取一种不同的反应。

然后照[入口](../index.md)第 1 步写概念，全都用同一个物件、同样的部件。

## 卡片说不了的

- **深度。** SVG 是平的。什么立着、什么躺着由你决定：火箭立在尾翼上，卡片躺在托盘里。静止姿态（规则 05）就是这个决定露出来的地方。
- **哪个部件回应。** 卡片列出部件；它不知道手会去够哪一个。优先选那个回应部件同时也是让物件露馅的部件的概念。
- **它是谁的。** 属于别人的标志，发不发布由对方定：交付时说明，像[从想法到概念](concepts.md)的「从标志画」说的那样。

## 没有浏览器时

卡片只剩 viewBox、title、id、计数和没读到的东西，也没有图。剩下的去读 SVG 自己的文字：每个形状的属性给出的外框足够判断比例。交付时用这句话说明，来源**没有在浏览器里看过**。
