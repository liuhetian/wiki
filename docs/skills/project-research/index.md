# 调研项目

按读完要做到哪一步选一个子 skill。四档都能单独运行，不要求逐档完成；篇幅只作参考，主要按解释深度区分。

| 我想…… | 用 | 默认产出 |
|---|---|---|
| 知道是什么，判断是否继续看 | [概要项目](gist.md) | 三四段、400 字以内，定位、主路径和分工 |
| 看懂主要功能怎么工作 | [粗讲项目](explain.md) | 几千字，按功能分节，展示机制、具体材料和效果 |
| 学懂设计及取舍，迁移机制 | [细讲项目](dissect.md) | 从 baseline 的问题出发，沿功能线拆源码与验证 |
| 系统复刻、对比或实验研究 | [写书](book.md) | 按学习目标组织章节 |

收外部来源先走[收纳分诊](../collect/index.md#ask)：没说深度时必须问“只是收集概要，还是有特别感兴趣的点”，等待回答。用户回答有关注点而未指定深度时按粗讲交接，不再确认；已明确指定的直接沿用。规模和复杂度只作推荐理由，不替用户决定。

概要的原来理解、粗讲覆盖的功能和关注点都可以做细讲的起点，但细讲仍要核对 baseline 与功能线；写书沿用已有的术语、源码和实验材料，缺的再补。概要、粗讲、细讲在同一项目目录升级，入口 URL 不变。

## 共用证据规则 { #evidence }

执行任何一档前先读本节；文体和篇幅按所选子 skill。以下规则只在用到对应材料时适用：

- **原文、改写、构造示例、实测输出分别标明**：源码或 prompt 原文给文件与行号，过滤或改写说明改了哪些部分，自己设计的数据结构不写成上游已有格式。活例：[wenai](../../projects/wenai/index.md)分别展示原文恢复要求、过滤后的 prompt、手工记忆示意和模型实际生成的文件。
- **具体机制用具体材料说明**：代码项目展示源码，skill 展示 prompt 和引用文件，配置型项目展示配置与输入输出；只存被页面使用的文件，按[写作规范](../wiki-guide/index.md#rules)用 snippet 引真身。活例：[wenai 的文件记忆](../../projects/wenai/index.md)同时展示接续文件和真实回复。
- **实跑优先用原项目实现**：直接调用或原样抽取它的函数；构造输入过同一个实现时标明输入来源。自行编写的机制演示只说明机制，不充当原项目验证。活例：[wenai 的实验记录](../../maintenance/projects/wenai.md#experiment)明确是本站脚本读写文件，不是执行上游会话引擎。
- **说明实际验证范围**：没有执行的写未实跑；一次模型样本不推为可靠性结论，脚本与原始输入输出可复查。模型调用先读已有的[Agent 基础能力](../agent-io/index.md)，按需选择接口。活例：[wenai 的对照](../../maintenance/projects/wenai.md#experiment)只验证提供记忆对本样本的帮助，不验证补记和去重。
- **版本与实验设置集中记录**：独立概要只在脚注记出处和版本；粗讲、细讲和项目类写书建立维护记录，正文保留机制与效果；写书的“做实验”角度仍按该模板把实验设计写进正文。一个来源两面都收时复用一篇记录，位置照[收纳的维护记录](../collect/index.md#maintenance-record)。活例：[wenai 的维护记录](../../maintenance/projects/wenai.md)汇总版本、过滤范围、脚本和用量。
