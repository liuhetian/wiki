# 调研项目

读别人的仓库，难的不是读完，是读完能说清它在干什么、哪部分值得学。按要做到哪一步挑一个子 skill，读那一页照做；每个都是一段完整的 prompt，人用的话在那一页点复制按钮，整页粘进对话框。

| 我想…… | 用 | 要准备什么 |
|---|---|---|
| 几句话弄懂一个仓库或项目在干什么 | [粗讲项目](gist.md) | 仓库地址或本地路径；模型要能读代码 |
| 拆解学习一个项目的设计，写成论文骨架的一组文档 | [细讲项目](dissect.md) | 仓库地址或本地路径；模型要能读代码，最好能跑 |
| 从零复刻一个迷你版、对比同领域几个项目、或做实验量出功能管多少用，写成一本书 | [写书](book.md) | 仓库地址或本地路径，最好先有细讲的成品当底稿；从零复刻和做实验要能跑代码 |

- **三个的产出不同**：粗讲讲给你听，三四段话、400 字以内，知道它是什么、解决什么问题就够；细讲写成一组文档，从领域和 baseline 写到可以搬走的设计，要学它的设计时用；写书的章节按读者读完能干什么排，先选角度：从零复刻读完能自己造一个迷你版，领域对比读完能看清一个领域的几种解法，做实验读完知道哪些功能真管用
- **一步接一步，也能单独用**：拿不准值不值得深挖，先粗讲；粗讲时填的「我原来以为它是」，细讲里直接当 baseline；细讲的 baseline、功能线、术语表、源码存档，写书拿来当底稿。没跑上一步，下一步自己补个最小版
