# 边缘函数的限制

都是线上实测出来的，本地和测试里复现不了。实测于 2026-11，平台构建用的 edgeone CLI 是 1.7.2。活例：[牛牛便利贴](../../../projects/clipboard/dev.md)。

## 请求怎么走

最前面站着的是平台的路由，不是你的代码：

```text
请求
 └─ 平台的路由
     ├─ 路径上有静态文件 → 平台直接返回（前端页面、脚本、样式、文档页）
     └─ 没有静态文件     → 按路径找 edge-functions/ 下对得上的函数文件
                            ├─ 找到了 → 交给函数（比如里面的 Hono）
                            └─ 找不到 → edgeone.json 的 rewrites，没有就 404
edgeone.json 的 redirects（301）和 headers 在两条路上都生效
```

习惯了 FastAPI 挂 `StaticFiles` 的，差别在这几处：

| | FastAPI + StaticFiles | EdgeOne Makers |
|---|---|---|
| 最前面是谁 | 你的进程 | 平台的路由 |
| 静态文件谁给 | 你的进程读磁盘返回 | 平台直接给，你的代码不参与 |
| 后端代码什么时候跑 | 一直在跑 | 有请求落到函数才启动，跑完就没了 |
| 能不能给静态文件加认证 | 加个中间件就行 | 不能，请求不经过你；要锁就照[全站上锁](site-lock.md) |

所以认证写在函数里，只锁得住函数给的数据，锁不住页面和前端代码。

**函数按文件夹分配请求**：`edge-functions/api/[[default]].js` 只收得到 `/api/...`，别的路径就算没有静态文件也到不了它。动手前先定放几个函数：**函数之间共用代码就是一个服务，只放一个入口**，放在最顶层的 `edge-functions/[[default]].js`，函数里再按路径分；完全独立、互不引用的才分文件夹放多个。顶层入口实测：

- **有静态文件的路径照样由平台直接给**，不进函数、不算调用：页面、脚本、`redirects` 里的 301 都是
- **没有静态文件的路径全部进函数**，排在 `rewrites` 前面：单页应用靠 `/* → /index.html` 回首页的那条规则走不到了，删掉，由函数自己回首页
- **函数读不到本站的静态文件**：首页在构建时打进函数包，先构建前端、再打函数包

## 失败要留下记录

接口偶尔回 5xx，先找根因、改根因，改完用改前的测法复测。**自动重试可以留，但每一次失败都要记下来、报到人看得见的地方**，重试救回来的那次也要记。只重试不记，报错就被盖住了，根因一直在拖慢每个请求，也再没人发现。下面的 545 就是这么拖下来的：一开始归因成「读太多超了额度」，靠下一次同步重试顶着，实际是函数包太大。

- **在最底层记**：前端所有接口调用都过同一个 `fetch` 包装，记在自动重试的下面
- **记 5xx 和网络不通**，4xx 是正常的拒绝，不记；页面自己取消的请求也不记
- **先存本机，下一次请求成功时再报**：545 由平台直接返回，函数里的代码看不到，只有浏览器能报

## 冷启动与函数包

- **545（响应体 `Error return from script`）是冷启动被平台掐掉**。认法：不碰存储的接口一样出，同一批节点上几 KB 的小函数一次不出
- **函数包要小**：冷启动的 CPU 花在解析和执行函数包上。实测 641 KB 时，模拟打开页面（静默 30 秒再并发 6 个请求）最多 24% 失败；压到 291 KB 后同样测法 0/72，冷启动那批请求快 60～90 ms。平台按什么标准掐看不到，文档写的是一次执行 CPU 200 ms
- **包里的代码超过 350 KB 就让构建失败**：esbuild 开 `metafile: true`，按依赖统计 `bytesInOutput`，失败时列出最大的几项；打进包里的文字不算。上线后才发现包变大，只能再等一次 545
- **zod 写成 `import * as z from 'zod'`**：写成 `import { z }`，esbuild 把整个命名空间连同几十种语言的报错文案打进来，443 KB；改了以后 94 KB
- **打进包里的大段文字不拖累**：100 KB 的文档原文拿掉，冷启动没有变化
- **同一个包别放成两个入口**：平台把 `edge-functions/` 下每个入口各自重新打包，再拼进同一个脚本，冷启动每份都要解析。同一个包放 `/api/`、`/wiki/` 两个入口，本机照平台的方式模拟，冷启动 CPU 从 42 ms 涨到 53 ms
- **`edgeone.json` 的 rewrite 转不到函数**：把 `/wiki/*.md` 转给 `/api/` 那个入口，规则命中了，但它只去找静态文件，找不到就回平台自己的 404 页
- **每个请求都把命中的入口整包的顶层代码重跑一遍**：模块顶层的变量活不过一个请求。`fetch` 是平台按请求给的，建好的 app 不能挂在 `globalThis` 上跨请求复用
- **平台按字面扫描函数入口**：压缩后的 `export{X as onRequest}` 认不出来，打包后改写成 `export async function onRequest(context){…}`。平台的函数包上限是 5 MB
- **构建前清空 `edge-functions/`**：留在里面的旧文件也会被部署成入口

## 额度与运行时

- **一次执行大约只能发 62 个请求**（实测 62～64 浮动），读一个 Blob 对象算一个，超了存储报错。一次要读多少、顺手做几件事，都从这个数倒推；读不完的分批，由页面或定时任务接着调
- **新建的 store 没凭据时并发读，每个读各换一次凭据**，一个对象算两个请求：先单独读一个，再并发
- **存储偶尔个别请求 504**，和读多少个无关：别在读失败时做不可逆的事
- **函数请求自己的域名被平台回 404，请求本站的静态文件回 502**：函数没法自己接力，也读不到静态文件
- **运行时的 `URL`、`URLSearchParams` 不全**（不能遍历），aws4fetch 这类签名库跑不起来，COS 签名要手写
- **一次读不下几 MB 以上的响应**（报 OverSize）：每次取 4 MB 再拼
- **定时任务最小间隔一天**
- **云函数没有请求额度的限制**，但实测每个请求慢一倍、冷启动 2～3 秒、往外回数据只有约 170 KB/s

## 路由与静态文件

- **静态文件盖住函数**：同一路径有静态文件，请求就不再走函数
- **`/x` 不带斜杠时平台直接给页面、不跳转**，页面里的相对地址全部解析错：每页在 `edgeone.json` 写一条 301
- **`edgeone.json` 的 `headers` 规则会盖掉函数自己设的响应头**：`Cache-Control` 两处写成一样

照 [wiki 部署约定](../../subwiki/index.md#site)在 Makers 上挂 wiki，就是上面几条的组合：页面是静态文件；`.md` 不上传，原文打进函数包，由顶层的那一个入口按路径返回；[占位符](../../subwiki/live.md)背后的接口在进程内调。
