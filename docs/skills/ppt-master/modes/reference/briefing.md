# 简报（briefing）

中立的信息传递。把事实朴素、完整地摆出来，按扫读和查找来组织 —— 没有要论证的论点，没有要讲的故事，没有要建立的课程，也没有场面。适合进度汇报、参考资料、产品目录、会议材料包、常见问题、数据参考。

## 叙事骨架

**有意没有论点**：这套 deck 是告知，不是论证。素材本来就只是「事实是这样」时，不要硬造一个结论先行的论点（那是[金字塔](pyramid.md)），也不要硬造一个转折（那是[叙事](narrative.md)）。

**主题式标题，不是断言**：页面标题平实地点出主题（「三季度各团队人数」「支持的文件格式」）—— 方便查找胜过有说服力的发现。这是有意和金字塔的断言式标题反着来。

**每页的核心信息写覆盖范围，不写论断**：规划每页讲什么时，写这一页摆出了什么（「三季度各团队的人数」），而不是它证明了什么（「人数正在向研发集中」）。在别的模式下这一栏读作断言，在简报模式下它只说明范围。

**完整胜过挑选**：放进受众要扫读的整套参考信息，而不只是支持某个观点的那几条。覆盖面就是价值所在。

**并列、均等地处理**：同级的条目用同样的形状和分量，方便对照和定位；除非真的不同，不把哪一条拔高到同级之上。

**分好区方便导航**：把相关的事实归组，给组贴标签，顺序可预期（按时间、按类别、按字母），让读者能直接跳到要找的地方。

## 页面结构倾向

- 表格、定义列表、状态卡片、参考网格、仪表盘 —— 便于扫读的结构，胜过主视觉构图
- 一个分区之内层级均等；同级页面之间版面一致，让视线总知道往哪看
- 某个数字真的要紧时（一个总数、一个状态标记、一个例外），把它亮出来 —— 但别编一个内容里没有的「包袱」

表格和由数值驱动的图表可以套现成的模板，其他结构到画页面时按内容现搭，仪表盘可以把它们组合起来。这个模式决定这一页要完整、中立地告知，不决定像素位置。

## 演讲备注口吻

平稳、据实、朴素。说清这页展示了什么，不制造张力，也不追问「所以呢」。没有反问，没有悬念 —— 一段听的人能跟上、也能跳着听的清楚播报。数字照实说。

## 页面骨架示例

```text
标题：「三季度各工作流的交付情况」        ← 主题标签，不是论断
正文：状态表 —— 工作流 | 负责人 | 状态 | 截止 —— 各行分量相同
备注：「三个工作流按计划推进，支付这一条在集成上有风险。」（朴素播报）
```
