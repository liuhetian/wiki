# 金字塔（pyramid）

结论先行的论证。先给答案，再用结构化的证据支撑它 —— 每个论点都得挣到自己的位置，数据要放进上下文，但不编造对照。给想先听结果、再看过程的受众：高管、董事会、投资人、决策者。

## 叙事骨架

**结论先行**：页面标题就是结论，不是标签。正文在它下面展开支撑论据。

SCQA 开场，金字塔主体：

| 阶段 | 作用 | 放在哪 |
|---|---|---|
| Situation 情境 | 建立共同的背景 | 开头几页 |
| Complication 冲突 | 张力或问题 | 前面几页 |
| Question 疑问 | 要解决的那个隐含问题 | 过渡 |
| Answer 答案 | 建议本身，用结构化证据展开；素材支持时用 MECE | 主体页 |

**断言式标题** —— 写发现，不写话题：

| 弱（话题） | 强（断言） |
|---|---|
| 「市场概况」 | 「国内市场同比增长 23%，跑赢全球平均」 |
| 「挑战」 | 「三个结构性矛盾卡住规模化落地」 |
| 「我们的方案」 | 「三步走：聚焦、扩张、规模化」 |

**数据放进上下文**：某个对照能改变决策时，给数字配上一个站得住的对照；否则直接说它的相关性或含义。绝不为了套这个模式去编造上一期数据、基准、竞争对手、目标或排名。

**结构化拆解**：拆驱动因素、细分或选项时，让各个分支真正不同，并覆盖决策需要的部分。真实存在的重叠或承认的缺口照实保留，别硬拼出一个完美的 MECE 划分。

## 页面结构倾向

- 标题（结论）→ 简短的要点 → 下面是支撑证据
- 每个主体页围绕一个和决策相关的问题，给出清楚的结论；几个辅助子问题关系要紧时可以同页
- 拆解页（驱动因素树、MECE 拆分、2×2 矩阵）承担分析的重量
- 每个数据页都标来源

页面结构是倾向，不是坐标模版：卡片、树、指标、2×2 这些结构到画页面时按内容现搭，数据图表和表格可以套现成的模板。这个模式决定每页讲什么论点，不决定像素位置。

## 演讲备注口吻

结论驱动：每页备注先说要点，再用连贯的话讲一小组事实。沉稳、有权威感。对照能实质性讲清要点时，给数字配一个站得住的对照（「23%，几乎是行业 12% 的两倍」）；否则直接讲它意味着什么。口语读起来更顺时，百分比写成文字。

## 页面骨架示例

```text
标题：    「增长的引擎已经从拉新换成了留存」   ← 结论
要点：    一行 ——「获客成本同比上涨 40%，复购却贡献了 60% 的收入增长」
正文：    支撑论据，数据放进上下文
页脚：    来源：…… | 页码
```
