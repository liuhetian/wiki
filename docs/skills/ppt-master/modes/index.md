# 沟通模式

沟通模式是一套 deck 的叙事加说服骨架：论点怎么组织、怎么一页页往前推。一套 deck 只用一种，它决定页面顺序、标题口吻、页面结构倾向和演讲备注的语气。它不是[视觉风格](../../../gallery/images/ppt-master/index.md#visual-styles)：沟通模式管「怎么讲」，视觉风格管「长什么样」，两者分开选，任意模式配任意风格 —— 一套金字塔 deck 可以做成瑞士极简，也可以做成深色科技。

选定一种之后，读它的那一篇，照着排页面、写标题和演讲备注。

## 五种模式

| 模式 | 叙事骨架 | 典型场合 |
|---|---|---|
| [金字塔（pyramid）](reference/pyramid.md) | 结论先行；论证有结构；有用时给数据配上站得住的对照 | 决策支持、分析、战略、董事会和高管汇报 |
| [叙事（narrative）](reference/narrative.md) | 故事弧 —— 情境 → 张力 → 化解；悬念和转折 | 路演、案例、品牌历程、融资 |
| [教学（instructional）](reference/instructional.md) | 拆解概念；一步一步；并列展开 | 培训、教程、讲解、知识分享 |
| [展演（showcase）](reference/showcase.md) | 视觉领衔的冲击；大图、大数字；情绪节奏 | 发布会、品牌亮相、活动和宣传 deck |
| [简报（briefing）](reference/briefing.md) | 中立、完整、便于扫读；主题式标题，分量均等，没有论点 | 进度汇报、参考资料、产品目录、会议材料包、常见问题 |

- **五种是论证策略，不是沟通目的的分类**：一份 PPT 可以同时要传达、对齐、请求决策，这种复合意图用一段话写清楚（见[规划 deck](../strategist.md)），再从这里挑一种最能把整套内容讲出去的骨架
- **模式是一副镜头，不压过明确要保留的结构**：用户给的普通大纲只是参考，模式可以重新分组、调顺序、改标题，但保住其中的事实和关系；只有用户把大纲当成最终的页面计划，或者明说要保留顺序、标题、措辞时，才照原样保留。用户没给结构，就由模式来搭结构。想少动结构，选简报，它强加的骨架最少

## 怎么选

这是参考，不是约束：把受众、要达成什么、受众听完要有什么变化、核心信息、使用场合和会后怎么用、素材本身的质地，以及用户自己写的大纲放在一起看。目录列的是五种完整的论证策略，不分高下，也不按主题关键词对号入座。几种目的并存时，看主体页面的论证主线往哪走，别看封面，也别看意图里第一个出现的词。

拿不准时，对照下面几组相邻模式的结构差别：

| 在这两个之间犹豫 | 选前一个，当…… | 选后一个，当…… |
|---|---|---|
| 金字塔 / 简报 | 必须落到一个建议上 —— 结论先行，数据往决策上靠 | 必须完整告知、不做论证 —— 主题式标题，分量均等 |
| 叙事 / 金字塔 | 论点靠故事弧落地，从张力走到化解 | 论点先当结论摆出来，再给支撑 |
| 叙事 / 展演 | 论证随着故事推进 | 存在感领衔 —— 文案简短，视觉焦点清楚 |
| 教学 / 简报 | 目标是一步步建立理解 | 目标是摆出一份能扫读的完整参考 |

「做成发布会那种」是在要沟通模式，不是要视觉风格：它指展演的节奏（一个清楚的主要想法、主视觉尺度的处理、逐步揭晓的节奏），外面套哪种视觉风格看品牌 —— 瑞士极简干净，深色科技有戏剧性，玻璃拟态显高级。不要去找一种「发布会风格」，有意没有这一种。

## 一套 deck 只用一种

- 内容结构真的是混合的，就选主体页面的模式，让个别页面在它之内变化
- 确实需要混合时，写一段自定义的讲法：说清楚这套 deck 按什么节奏推进，可以借用五种里的任何部分，也可以原样用其中一种。它仍是一种讲法，不是几种并用
