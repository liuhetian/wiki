# 规划 deck

一页还没画之前，先把这套 deck 定下来：讲给谁、讲完要他们怎样、怎么讲、长什么样、每页干什么。按下面九项顺序过一遍，产出一份规划交给画页面的一方 —— [PPT Master](index.md) 的上游流水线、[滚动 deck](../writing/deck.md)、HTML 页面都行。

- 每一项都给用户一个推荐，用户确认了再往下走；用户已经说定的（色值、字体、页数、风格、提纲）照用，不再推荐
- 推荐写成能照做的判断，不写「现代、简洁、专业」这种词
- 用户清空的项保持空，表示没有额外约束，不要偷偷填回推荐值
- 用户说直接做、或者不在线时，按推荐一次定完，规划开头列一张表写清替用户定了什么；第四项的三个方案只展开选中的那个，另外两个用一张对比表交代

## 一、沟通契约：六个问题 { #contract }

| 问题 | 回答什么 |
|---|---|
| 受众 | 到底讲给谁听，他们已经知道什么、在乎什么 |
| 沟通意图 | 这次要完成什么；可以有几个目的，写清先后和轻重 |
| 受众的变化 | 怎样算讲成了 —— 受众会知道、理解、相信、决定或去做什么 |
| 核心信息 | 别的都忘了，也必须留下的论断、决策请求或行动 |
| 使用场合 | 主场是什么：有人讲、自己读、两者兼有（哪个为主），还是录好自动播放（没有现场讲者，靠旁白、计时、转场）；还有什么次要用途、场合和时长限制 |
| 会后用途 | 文件之后要支撑什么：复盘、审批、审计、归档、交接、复用，或者都不需要 |

- **意图是开放的**：告知、解释、说服、决策、对齐、教学、汇报问责、动员、记录交接只是提示，不是勾选框；几个目的的关系用一句话写出来（「先汇报进度、先亮风险，再拿到决策」）
- **契约不是沟通模式**：意图说要带来什么改变，模式是组织论证的一种方式，第四项才选

意图里提到的每个目的，都要在大纲里落成一项义务：

| 意图 | 大纲必须做到 |
|---|---|
| 告知 | 相关事实，加上足以说明它为什么重要的背景 |
| 解释 | 机制、关系、因果或含义能被一步步追下来 |
| 说服 | 论断 + 证据 + 重要的反对意见或替代方案 |
| 决策 | 明确的决策请求 + 选项 + 标准 + 取舍 + 拖延的后果 |
| 对齐 | 共同的框架 + 优先级 + 负责人 + 下一步 |
| 教学 | 前置知识 + 顺序 + 实际演练或理解检查 |
| 汇报问责 | 基线 + 进展 + 偏差 + 证据 + 风险 + 责任人 |
| 动员 | 紧迫性 + 能动性 + 具体行动 + 马上能做的下一步 |
| 记录交接 | 背景 + 决定 + 状态 + 负责人 + 未决事项 + 可追溯的出处 |

## 二、画幅 { #canvas }

| 画幅 | id | 尺寸（px） | 比例 | 用途 |
|---|---|---|---|---|
| PPT 16:9 | `ppt169` | 1280×720 | 16:9 | 商务汇报、会议、现代设备 |
| PPT 4:3 | `ppt43` | 1024×768 | 4:3 | 老投影仪、学术报告 |
| 小红书 | `xiaohongshu` | 1242×1660 | 3:4 | 图文分享、知识帖 |
| 社交方图 | `moments` | 1080×1080 | 1:1 | 方形海报、品牌展示 |
| 竖屏 | `story` | 1080×1920 | 9:16 | 竖版故事、短视频封面 |
| 公众号头图 | `wechat` | 900×383 | 2.35:1 | 公众号文章封面 |
| 横幅 | `banner` | 1920×1080 | 16:9 | 网页横幅、数字屏 |
| A4 | `a4` | 1240×1754 | 1:√2 | 印刷海报、传单 |

- 画幅本身不规定标题栏、版式和固定装饰，只给真实存在的遮挡留位置
- 竖屏的手机控件压在上下两端：有意义的文字、标识、行动号召默认放在 y=120 到 1740 之间，图片和纹理可以出血

## 三、阅读方式、页数和取材 { #reading }

阅读方式管信息怎么承载，不管沟通意图：

| 阅读方式 | 主载体 | 页面写法 | 粒度与节奏 | 演讲备注 |
|---|---|---|---|---|
| 近读 | 页面本身，像文档 | 完整的论断、短段落、图注、表格和必要细节；真正并列或有序的才用列表 | 页少而满，偏密集 | 补充背景，不能替页面补逻辑 |
| 均衡（默认） | 页面 + 讲者 | 一页一个主论断，配简明解释、结构化证据或必要的列表 | 中等粒度，节奏有张有弛 | 解读和过渡 |
| 演讲 | 讲者 + 画面 | 一页一个论断，关键词或短语，一张大图或一个大数字；不堆段落，也不把段落压成碎片 | 页多而疏，偏锚点和留白 | 承担解释、过渡和细节 |

- **从受众、场合、会后用途推**：异步审阅、参考资料、审批、审计、会后留存偏近读；讲者主导的投影、大会场、发布会、课堂偏演讲；混合评审、路演偏均衡，现场投影和会后留存都重要时也选均衡
- **选了演讲照样能留存**：靠演讲备注、附录页、图注和标明出处，不把页面塞满
- 同一份材料、同一份契约做成演讲版和近读版，差的是页面写法、页数、文字量、画面负担、密度、节奏和备注，不只是字号；不写演讲备注时，所有必要的意思都要留在页面上
- **页数**：先给一个一眼能判断的窄范围，契约定了再从素材量、受众变化、场合和阅读方式定一个准数；用户说「严格」「1:1」就锁死。逐页清单定稿后页数和顺序不再变，要改就回到这一步
- **取材自由度**：从贴近原文（跟着原文结构和措辞走，只为清楚做微调）、均衡（按选定的沟通模式重新组织成叙事，实质内容一样不少）到自由（重组、重构、扩展、建立联系、自己设计结构和过渡）。用户没说就按均衡
- **事实必须有出处**：再自由也只是展开素材里有的，绝不许补外部事实、数字和论断。缺了就先去查；演示用的指标、比率、目标、路线图数字标明是示例数据，和有出处的数字分清楚
- **每块内容按关系选形式**：因果、论证、解读、叙事连贯用段落；真正并列、有序、可枚举的才用列表或编号，不因为字多或模板有列表位就拆成要点。演讲模式下提炼成一句论断，解释挪进演讲备注
- 素材里的公式原样记下来，链接记下确切的文字和地址，不猜

## 四、沟通模式 + 视觉风格 { #style }

两层各选一个，互相独立，任何组合都行：

- **沟通模式 = 怎么讲**：金字塔、叙事、教学、展演、简报五种论证骨架，见[沟通模式](modes/index.md)
- **视觉风格 = 长什么样**：形状语言、装饰密度、留白节奏、字体性格、质感层次，18 种，见 Gallery 的 [PPT 视觉风格](../../gallery/images/ppt-master/index.md#visual-styles)

**先想整体方案，再去目录里找依据**：从契约和素材出发，写出三个完整、贴合这个项目的方案，再去两份目录里找对应的条目。

- 三个方案要是真正不同的设计：差别落在这套 deck 真正需要的部分上，模式、风格、画风、配色、字体、图标都可以相同；只换名字、换说明、换引用条数不算不同
- 不硬凑「保守 / 折中 / 大胆」三档，也不故意走极端
- 用户、模板已经定死的部分，三个方案都照用，差别放在还开放的部分；什么都定死了，就三个一样，并说明这一点
- 目录里没有合适的，可以自己写一种，写成能照做的描述：形状语言、构图、密度、留白、字体、质感，写它用什么（容器、图标、色块、阴影、渐变、图片处理、形状），不写成一串禁止项。「扁平、现代、干净、简约、极简」不算描述

**选视觉风格比这五个维度**，话题、行业关键词不直接决定风格 —— 同一个主题，沟通任务变了，视觉体系也可以不同：

| 维度 | 拿什么比 |
|---|---|
| 形状与空间 | 轮廓语言、网格方式、留白、边界强弱 |
| 信息质感 | 稀疏存在感、杂志式层级、密集证据，还是手作感表达 |
| 承载物融合 | 这套体系能不能容纳这些页面真实要放的照片、插画、图表、表格和形状 |
| 字体性格 | 可编辑文字在构图里扮演什么角色，和具体用哪款字体无关 |
| 使用与留存 | 观看距离、投影和打印表现、复用、之后要怎么改 |

- 先看素材、品牌、沟通任务有没有更具体的边、角、开口、角度、轮廓或层叠逻辑，没有再退回线条、矩形、圆和椭圆当主形状语言
- 视觉风格不带色值，只管第五项定的颜色怎么用；它也不决定放不放图、图从哪来
- 风格条目里的「配套画风」只是审美相近的一个选项，要不要用，对照这套 deck 实际的配图任务再定
- 落到后面几项的例子：展演 + 深色科技 → 深色底上只用一个发光强调色，干净的无衬线标题配等宽字，极简的发光图标，配图用数字仪表盘画风

## 五、配色 { #color }

- **用户给的就是定论**：色值、品牌色、「用公司的蓝」这类口头说法都照用
- **定六个角色**：背景色、次背景色、主色、强调色、次强调色、正文色；再派生次要文字和分割线两档中性色。不许交出空配色
- **比例和对比度**：60-30-10 起步；正文对比度至少 4.5:1（WCAG AA）；色相多少由编码需要、风格和素材自带的颜色决定
- **参考色只作参考**：金融商务海军蓝 `#003366`、科技亮蓝 `#1565C0`、医疗青 `#00796B`、政务红 `#C41E3A`；正向 `#2E7D32 → #4CAF50 → #81C784`、警示 `#F57C00 → #FFA726 → #FFD54F`、负向 `#C62828 → #EF5350 → #E57373`。都不是默认值；品牌色以品牌方给的为准，不凭记忆
- **正向、警示、负向**三种语义色在规划里定好，页面上的浅色、深色、透明度、渐变和光影由画页面的一方派生
- **按风格补中性色**：叠面板和图表的风格（数据新闻、瑞士极简）加面板底色和比分割线更浅的网格线；字压在图片或深色底上的风格（摄影编辑风、玻璃拟态、深色科技）加遮罩色；印刷感、手绘填色的风格（黑板、小刊）加一档比底色深一级的块面色。只给有固定含义的角色定色，一次性的色调留给页面

## 六、字体 { #type }

- **用户、模板给的字体照用**
- **默认目标是 Windows 上的 PowerPoint**：写目标机器上装了的具体字体，作者自己电脑上装了什么不算；一套最多四种；品牌字体、网络字体要用户确认目标机器装了才能当主字体，否则导出用安全字体，原字体只留作参考
- **一种文字只写一个具体字体**：不写一串备选；中文 deck 里也排西文时，中西文各写一个配成对，比如 `SimSun, Cambria`
- **别混用几乎一样的字体**：微软雅黑 ↔ 苹方、宋体 ↔ 华文宋体、Arial ↔ Helvetica ↔ Segoe UI、Times ↔ Times New Roman
- **对比或协调二选一**：换字体、换字重、换比例形成对比，或者一套字体用到底；三个方案里对比和协调各至少出现一次；标题带性格、正文可以中性，标题和正文用同一款要有理由。微软雅黑、Arial 是中性的那一档，不是自动的标题首选 —— 风格要性格的地方用中性无衬线做标题，就是该避免的失败

PowerPoint 安全字体（只是参考，不是白名单）：

| 文字 | 字体 |
|---|---|
| 简体中文 | 黑体类 微软雅黑、黑体；宋体类 宋体、仿宋、楷体。苹方、华文黑体、华文宋体只是 macOS 上的预览替身，不能写成正式字体 |
| 繁体中文 | 微软正黑体；衬线 新细明体、标楷体 |
| 日文 / 韩文 | Yu Gothic、Meiryo、Yu Mincho / Malgun Gothic、Batang |
| 西文无衬线 | Arial、Calibri、Segoe UI、Verdana、Trebuchet MS |
| 西文衬线 | Times New Roman、Georgia、Cambria、Palatino、Garamond。Georgia 用的是旧式数字，高低不齐，大数字和数据用 Times New Roman、Cambria 或无衬线 |
| 等宽 / 公式 / 展示 | Consolas、Courier New / Cambria Math / Impact、Arial Black |

像素风的 Press Start 2P、VT323，圆体 Nunito、Quicksand、OPPO Sans，网页常用的 Inter、HarmonyOS Sans、思源，书法类的隶书、华文行楷、华文新魏，都要目标机器装了才能用；没装就换安全字体（圆体换 Trebuchet MS 或 Verdana，书法换楷体或仿宋，书法只用在标题）。中文没有预装的手写体，风格要手写感标题时也用楷体。

**字号用 px，从正文起点推**（导出时 PowerPoint 的 pt = px × 0.75）：

| 画幅 | 正文起点 |
|---|---|
| PPT 16:9、4:3 | 近读 20、均衡 24、演讲 32 |
| 公众号头图 / 社交方图 / 小红书 | 26 / 31 / 48 |
| 横幅、竖屏 / A4 | 56 / 51 |

| 角色 | 相对正文 |
|---|---:|
| 封面标题、单焦点主视觉 | 2.5–5× |
| 章节标题 | 2–2.5× |
| 页标题、KPI 大数字 | 1.5–2× |
| 副标题 | 1.2–1.5× |
| 导语、小标题 | 1.1–1.4× |
| 正文 | 1× |
| 双语页的第二语言 | 0.75–0.9× |
| 注释 | 0.7–0.85× |
| 脚注、页码 | 0.5–0.65× |

- 起点只是起点，按内容和场合调；不要为了塞下内容悄悄把反复出现的字号缩小
- 先扫一遍逐页清单，把反复出现的角色都定一个全套统一的字号，取整成偶数，比如正文 24 → 标题 42、副标题 32、导语 30、注释 18、脚注 16
- 某个反复出现的角色真需要另一种字体（注释、页脚、数据、引语、代码），才单独给它定，一次性的点缀不定；代码、长网址这类角色用正文字号放不下时，也单独定一个字号，写明理由

## 七、图标 { #icons }

四选一，定的是基础风格，不是素材白名单：

| 选项 | 做法 | 适合 |
|---|---|---|
| A | Emoji | 轻松、好玩、社交媒体 |
| B | 内置图标库 | 反复出现的小语义标记，统一一种 SVG 风格 |
| C | 自带图标 | 用户提供、模板自带或导入的图标 |
| D | 不用基础图标 | 没有统一的通用图标风格 |

- 选 B 就只选一个库；描边类的定一个全套统一的线宽（1.5、2、3，默认 2）。PPT Master 自带四个风格库：几何实心、圆润实心、线性描边、双色层次
- 真实的公司、产品、服务、社交平台出现时，用它自己的标志（用户给的，或 PPT Master 带的 simple-icons），不管选了哪一项，也不算另选一个库
- AI 生成的插画式图标不是图标选项，归第八项的图片
- 每页具体用哪个图标是画页面时的事，规划只定库和一个够用的候选池

## 八、图片来源 { #images }

| 来源 | 什么时候用 |
|---|---|
| 不用图 | 没有任何图承担实际的沟通任务 |
| 用户提供 | 现有的图带着事实、品牌、产品或叙事上的权威性 |
| AI 生成 | 虚构或刻意风格化的场景、插画、背景、隐喻、艺术字等生成类处理 |
| 网络图片 | 真实存在、必须原样出现的对象，以及泛用的摄影氛围、背景、场景 |
| 先占位 | 图一定要有，但之后才提供 |

- **缺 key 不是不放图的理由**：没配生图接口或图库凭证，都不能因此选「不用图」或删掉计划中的网络图
- **先给图，再考虑不放**：用户明说不要图就不放；否则受众要认出、体验、比较或挑选一个真实的对象、地点、产品、场景时，计划用户提供或网络图片；虚构或风格化表达明显更好时，再加 AI 生成
- **每张图单独定来源**：有权威性的用用户提供的；真实存在、要原样出现的用网络图片；虚构、风格化比还原真实更重要的用 AI 生成；混用是常态。视觉风格和画风只管图长什么样，不决定来源 —— 一个具名的地点、建筑、产品、作品或人物，再插画风的 deck 里也还是网络图或用户提供；刻意不让它原样出现的，在交付时说明原因
- **艺术字**：封面金句、章节词、地名、产品名、菜名、展品名、年份、大数字、引语这类稳定的展示文字，用材质、立体、手绘或插画处理比普通文字效果更好时，可以做成图；不因长短、行数挑拣，也不为了像 logo 删字。做成图的标题旁边保留一个可编辑的原生标题，需要能搜索、能选中、能进大纲的地方都要有
- AI 配图怎么写 prompt，见[生成配图](image-generator.md)

## 九、逐页清单 { #roster }

每页写这几样：

- **标题**：金字塔模式写成断言（结论本身），不写成话题
- **核心信息**和**受众看完这页的变化**：封面、章节页、结尾页也要写；推进不了任何东西的页，合并、重写或删掉
- **关系**：这页有哪些内容单元，素材里说明了它们之间的哪种关系 —— 顺序、连接、从属、归类、对比、重叠，或者没有。只写关系，不写用什么图形画
- **内容**：每条论断、事实、关系和限定语都在，只是措辞可以留给画页面时定
- **构图建议**（可选）：一句平常话，比如一个焦点论断、对等比较、主证据加结论、并列序列、核心加四周的力量、宽幅画面加解释；不写尺寸和坐标，画页面的一方可以改
- **数据和图**：由数值、类别、时间、权重决定几何的画成图表；行头 × 列头的事实做成表格；用到的图片写清来源和用途；演示数据标明是示例
- **节奏标签**：锚点（封面、章节、目录、结尾）、密集（信息量大，常态）、留白（低密度的停顿）三选一，用来打破千篇一律的卡片网格

排完整体再看一遍：

- 相邻页和每一章的走向：章节入口要明显重新起头；连续几页同密度、同类资源、同种关系，要是有意为之的小段落；每一章按模式的推进方式走（需要时是框架 → 解释或证据 → 判断或行动）；最后一段先把目标落地，再用真正的结尾收束
- 留白页要是真的停顿、能单独成立，不加凑数的页
- **封面必须有冲击力**：从素材里最强的论断、隐喻、数字、时刻或冲突里挑一个具体的钩子，可以配一句构图建议；默认不用内容页那种卡片网格、目录或等分栏，除非内容、用户或模板说明那样最清楚
- **结尾**：真有结论、行动号召或最后要带走的那句话，才做结尾页，写清那句话；不做空洞的「谢谢」页、只有联系方式的页、或封面的重复；没有结论就不硬造一页。社交平台上一张张单独转发的轮播图，每张都要有自己的标题和出处
- **跨页母题**：页面和资源都定了之后，如果某个元素能承载身份或含义 —— 标题或角落的装饰、一个方向性轮廓、一个开口、一组线阵、一个超大数字 —— 推荐它，写清它在各页之间负责什么连续性；画页面的一方可以不用
- **相邻页的连续性**：一个反复出现的人物、一个变成图表的数字、一个前进的进度标记、一个变成章节标志的封面元素，写一句「这页的 X 接上一页的 Y」，之后做动画能直接接上
- **演讲备注**：默认写；用户给了定稿讲稿的，按场景切分，措辞和顺序不动，不抄进页面正文
