你当前的工作区就是本 wiki 的仓库。这一轮只分诊，不建文件、不改文件：交出一份交接 prompt，我改好了交给下一个 agent 照做。

## 先看来源

看到能分诊为止：README、目录结构，有 `SKILL.md` 先读它。只判断它该进哪、有多重，不讲解、不拆设计，那是下一个 skill 的事。记下体量和更新频率：文件数、代码量、最近几个版本隔多久。

## 分诊：两条线分开判 { #tree }

不是在几个板块里挑一个。**文章线**写给人读，收它讲清了什么问题；**skill 线**写给 AI 读，收 agent 能照着做的执行方式。两条线各判各的，一个来源可以两边都收，也可以只收一边。来源不算数：自己做的、别人做的一样判。

### 文章线：它讲清了什么问题 { #article-line }

```text
讲清了几个问题，是什么把它们收在一起？
│
├─ 一个问题加解决方案：一篇帖子、一篇论文 ──→ 文章，照 docs/skills/wiki-guide/index.md 写
├─ 为交付同一个东西，互相牵连的一组问题 ───→ 项目，照 docs/skills/project-research/index.md 的表挑粗讲、细讲或写书
├─ 一个领域的一批问题，为了学会 ───────────→ 笔记，按领域进 notes/ 的分类
│   └─ 视频、图文帖 ───────────────────────→ 照 docs/skills/video-note/index.md
└─ 同一类小问题，一个问题对应一件成品 ─────→ Gallery，照写作规范六问第 1 问
    ├─ 有上游仓库、直接能用的效果 ──────────→ 极简收：标题、demo、一句仓库地址
    ├─ 别人的图、版式、配色、视频 ──────────→ 原样收
    ├─ 没有仓库、要自己复刻的网页风格 ──────→ 照 docs/gallery/web/frontend-styles/index.md 的「收录格式」
    └─ 只存链接的整站 ─────────────────────→ 收藏夹 docs/bookmarks/websites.md 加一行
```

对上几支时这样判，还分不开就把候选都摆给我：

- 一个问题还是一组互相牵连的问题：一个是文章，一组是项目；出自一个项目、只讲一个通用做法的还是文章
- 有没有要交付的东西：有是项目，只为学会是笔记
- 拿去学能迁移的技巧，还是挑一件照着做出来：前者笔记，后者 Gallery
- 要讲理由才说得清，还是拿去就能照做：前者文章，后者 Gallery 里的一条

### skill 线：agent 能照着做什么 { #skill-line }

```text
有没有 agent 能照着做的执行方式？
│
├─ 来源本身是 skill、插件、提示词合集 ──────→ 收纳，照 docs/skills/wiki-guide/skill.md
├─ 教程、视频、文章线讲清的做法 ────────────→ 照着做一遍，提炼成守则加脚本，新写或并进已有的 skill
├─ 经中转接一家 API ────────────────────────→ docs/skills/agent-io/index.md 加一个能力
└─ skill 要按编号查的参数：风格、画风、版型 ─→ 放进 Gallery，skill 按编号查
```

- 守则进 skill，参数进 Gallery：一段 prompt、一个色号、一种版式是 Gallery 的一条，一套怎么做是 skill
- 已有 skill 管得了的，并进去，不另起一个

### 两条线怎么接 { #link }

- 文章线链到 skill 线，skill 不链回文章；Gallery 和 skill 互链 —— 活例：`docs/gallery/images/collected/gallery-pulp-posters.md` 的样片和 `docs/skills/pulp-poster.md` 的守则，`docs/gallery/images/ppt-master/index.md` 的风格库和 `docs/skills/ppt-master/index.md`
- 维护不是第三条线：收进来的 skill、Gallery 条目、细讲的项目，从哪来、改了什么由收它的 skill 写进维护记录，两条线都收的写在一处

## 哪些问我 { #ask }

| 要定的 | 谁定 | 我没说时 |
|---|---|---|
| 两条线各收不收 | 我 | 两条都给推荐：收的写落哪、为什么，不收的也说一句为什么 |
| 每条线落哪 | 只对上一支你定；对上几支，问我 | 给推荐和理由 |
| 收多深 | 我 | 最浅：项目用粗讲，脚本重、更新快的 skill 只收离开脚本也能用的知识 |
| 侧重哪块、最想知道什么 | 我 | 你看完列两三个候选，问我挑 |
| 会不会真的用：部署、接进自己的项目 | 我 | 当不用 |
| 下一个 skill 里的空 | 能从来源定的你填，属于我判断的问我 | 照它的默认值 |
| 板块里的位置、文件路径 | 你 | 写进交接，我看交接时改 |

- 一次问完，每题带推荐和一句理由，我答「对」或者改一句就行
- 这一轮只问上表几件；下一个 skill 读透来源才问得了的，比如细讲的 baseline 和功能线、写书的目录，留给它自己盘问。交接里定了的，它不再问
- 一条线对上几支的，把候选都摆出来，别自己挑一支往下写
- 下一个 skill 多半是一段带填空的 prompt，源文件里是 `<input>`、`<select>` 这些标签，`data-when` 包着的是按某个空取舍的段落。粗讲、细讲、写书里「要不要收纳进本 wiki」这个开关，走到这里一律是「是」

## 交出什么 { #handoff }

两段，先给我看的，后给下一个 agent 的：

1. **给我看的**：要问的几题，每题带推荐；再用几句话说为什么这么分 —— 每条线收不收、为什么进这个板块、为什么用这个 skill、为什么收这么深、哪些不收。理由只给我看，不进交接，下一个 agent 照做用不上
2. **交接 prompt**：放进一个 `text` 代码块，问题按推荐先答好写进去，我改完原样贴给下一个 agent。它没看过这次对话，所以写全：
    - 你当前的工作区就是本 wiki 的仓库，先读 `docs/skills/wiki-guide/index.md`，再读下一个 skill
    - 来源：地址，一句话说它是什么
    - 两条线都收的分两节写，各写：用哪个 skill（仓库里的路径）、收到哪（落地路径）、收多深和侧重什么、下一个 skill 里的空（「空名：值」）
    - 两边怎么互链，维护记录写在哪
    - 这次特有的收什么、不收什么；skill 和写作规范里写过的不重复

我说「照这个做」，就在这次对话里按交接做。
