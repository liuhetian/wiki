# 提示词卡牌（对话类）

[prompt-cards.cyanfish.site](https://prompt-cards.cyanfish.site/) 是一个游戏王卡牌风格的提示词图鉴，内置 27 张卡。这里只收其中 17 张对话类卡。另外 10 张生图配方与词素带着效果图，按分类放进了 [Gallery](../../../gallery/index.md)。卡的原文照录在 `reference/` 的三页里，来源与版本见 [MIRROR](MIRROR.md)。

- [角色卡（persona）· 4 张](reference/persona.md) —— 架构先知、深度天赋挖掘机、人生设计师、毒舌审稿
- [流程卡（playbook）· 10 张](reference/playbook.md) —— 提示炼金、苏格拉底式提问、双层解释法、纵横分析法、事实核查、专家会诊、第一性原理、跨领域借解、双向钢人论证、根因追踪
- [约束卡（guard）· 3 张](reference/guard.md) —— 范围铁闸、人话翻译、实事求是

## 按场景挑卡

| 我现在想…… | 用这张 | 要准备什么 |
|---|---|---|
| 说不清自己到底卡在哪 | [苏格拉底式提问](reference/playbook.md#flow-socratic) | 发生了什么、你怎么理解、卡在哪 |
| 在两个选项之间做决定 | [双向钢人论证](reference/playbook.md#flow-steelman) | 两个选项、目标、约束 |
| 问题复杂，需要多个专业视角 | [专家会诊](reference/playbook.md#flow-expert-panel) | 已知事实、目标、约束 |
| 怀疑自己一直在修补表面问题 | [第一性原理](reference/playbook.md#flow-first-principles) | 问题本身 |
| 本行当的常规解法都失效了 | [跨领域借解](reference/playbook.md#flow-cross-domain) | 背景、当前做法、卡点 |
| 核查一个说法或一组数据 | [事实核查](reference/playbook.md#flow-fact-check) | 原话；模型必须能联网 |
| 深度研究一家公司、产品或技术 | [纵横分析法](reference/playbook.md#flow-cross-axis) | 研究对象；要用 deep research 类模式跑 |
| 学一个新概念 | [双层解释法](reference/playbook.md#flow-dual-explain) / [人话翻译](reference/guard.md#trap-plain) | 概念名；想要短答案用后者（200 字封顶） |
| 把模糊想法改写成 prompt | [提示炼金](reference/playbook.md#flow-refine) | 原始想法 |
| 让 AI 帮我定位 bug | [根因追踪](reference/playbook.md#flow-debug) | 症状描述 |
| 技术方案要先划清边界 | [架构先知](reference/persona.md#role-architect) + [范围铁闸](reference/guard.md#trap-scope) | 需求 |
| 让 AI 狠狠挑刺一篇草稿 | [毒舌审稿](reference/persona.md#role-critic) | 草稿全文 |
| 不许 AI 凭印象回答本机和仓库的现状 | [实事求是](reference/guard.md#trap-facts) | 放进 system prompt 或 `CLAUDE.md` |
| 职业方向和人生规划 | [深度天赋挖掘机](reference/persona.md#role-talent-miner) / [人生设计师](reference/persona.md#role-life-designer) | 大块时间；要多轮对话 |

用法都一样：整段复制，替换 `{{…}}` 或 `【…】` 里的占位，贴进对话框。约束卡是例外，它不是一次性的提问，应当放进 system prompt 或项目指令，整场对话都生效。

## 流程卡的共同骨架：先拆，再问，最后才答

10 张流程卡里，大部分都用了下面四个动作。自己写流程类 prompt 时可以照这个清单检查：

- **先拆成几类再作答** —— 苏格拉底式提问拆成「可验证的事实 / 对事实的解释 / 价值判断 / 目标」，事实核查拆成「事实 / 结论 / 价值判断」，第一性原理拆成「基本事实 / 未验证的假设 / 目标 / 约束」，纵横分析法要求「事实、推断和观点分开写」。拆完以后，模型没法再把猜测和事实混在一句话里。
- **明令推迟给答案** —— 「先不要给建议」「先别急着回答」「等我确认这个新问题以后，再给出你的判断」。模型默认会马上给答案，这句话就是专门压住这个倾向的。
- **一次只问一个问题** —— 苏格拉底式提问、双向钢人论证、专家会诊（信息不足时）、两张长角色卡都这么写。双向钢人论证更狠，只许问一个问题，而且必须是最可能改变结论的那个。
- **证据不足要明说** —— 「暂未核实」「还不能下结论」「尚未核实」分别出现在纵横分析法、根因追踪、实事求是里。这是给模型留一个合法的出口，免得它硬编一个听着很对的答案。

多数卡最后还会给一份编号的输出清单。这不算技巧，但清单本身就是这张卡的验收标准：少一项，就说明模型没按流程走。

## 占位符的写法不统一，说明来源不止一处

- **`{{idea}}` 式双花括号，或者干脆不留占位** —— 提示炼金、毒舌审稿、根因追踪、人话翻译用双花括号；架构先知、范围铁闸、实事求是没有占位。这 7 张都是短卡，五到十行，其中 5 张都写了一条「禁止……」。
- **`【填写……】` 式中文方括号** —— 苏格拉底式提问、双层解释法、纵横分析法、事实核查、专家会诊、第一性原理、跨领域借解、双向钢人论证这 8 张流程卡。卡长，结构都是「拆分 → 规则 → 最后请输出」，措辞像同一个作者写的一个系列。
- **`# Role：` 式 markdown 分节** —— 深度天赋挖掘机、人生设计师，分「角色 / 目标 / 核心理念 / 对话规则 / 输出 / 开始」六节，是中文社区里常见的 LangGPT 式结构化人设。

站点没有写任何来源和许可证（见 [MIRROR](MIRROR.md)），所以别把这 17 张都当成站长原创。这里照录是为了自己查着方便，要转发请自己追到原作者。

## 和本 wiki 已有 skill 的对照

- **苏格拉底式提问 vs [盘问我（grilling）](../grilling/index.md)** —— 两者都是一次一个问题、达成共识前不许动手，但盘问的方向相反。grilling 盘问的是**方案**：事实让 AI 自己查代码库，只把决策抛给我。苏格拉底盘问的是**困惑**：事实只能从我嘴里问出来，AI 能做的是逼我分清哪些是事实、哪些是我的解释。所以写代码之前用 grilling，想不清楚一件事的时候用苏格拉底。
- **实事求是 vs [CLAUDE.md 初始化模板](../claude-md-template/index.md)** —— 模板里的 Karpathy 第一条「不要假设」只说了态度。实事求是把它落成了可以检查的条款：文档只算线索，要用代码或命令交叉验证；装包命令必须匹配本机实际的安装方式。它补的正是模板没覆盖的「凭印象回答现状」这个坑，适合挑几条追加进项目的 `CLAUDE.md`。
- **范围铁闸 vs Karpathy「简洁优先」** —— 后者只是一句原则。范围铁闸要求先写「完成长什么样 + 最多 3 条要做 + 至少 3 条不做 + 1 个最大风险」，可以检查。「至少 3 条不做」是这张卡最值钱的一条：列「不做什么」比列「做什么」更能挡住过度设计。

## 用之前要知道的边界

- **事实核查、纵横分析法依赖联网** —— 模型不能搜索时，这两张卡只会产出一份格式漂亮的空话。纵横分析法还要求 1–3 万字，普通对话模式写不了这么长，得用 deep research 类模式。
- **两张长角色卡涉及心理话题，防护不对等** —— 人生设计师写了「察觉用户处于低谷或情绪脆弱时，跳过这一步」，深度天赋挖掘机没写，却会追问从小被批评的缺点、嫉妒过谁。给别人用之前，建议把人生设计师那条防护补进去。
- **两张长角色卡都要一万字左右的报告** —— 走完一遍要十来轮对话，别在赶时间的时候开。
- **架构先知的「给出 2 个可行方案」是硬数字** —— 问题只有一种合理解法时，模型会硬凑出第二个。碰到这种情况，直接告诉它可以只给一个。
