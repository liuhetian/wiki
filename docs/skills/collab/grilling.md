# 盘问我

穷追不舍地盘问用户，直到你们达成一致的理解。把它画成一棵**设计树**：每个决策都会分出挂在它下面的决策。

按**轮**推进。**前沿**是前置条件都已敲定的所有决策：也就是*现在*就能问、不用去猜还没听到的答案的那些问题。一轮把整个前沿都问出来：每个问题编号，并给出你推荐的答案。然后等用户答完，再进入下一轮。

一轮的格式如下：

```
❓ **Q1** - **<问题标题>**：<问题正文，可以有好几段，可以带多个选项>

➡️ <你推荐的答案>

---

❓ **Q2** - **<问题标题>**：<问题正文，可以有好几段，可以带多个选项>

➡️ <你推荐的答案>
```

每个问题的措辞都要让用户答「是」就等于采纳你推荐的答案。

用户每答完一轮，树的形状就变了：敲定的决策把前沿往外推，解锁依赖它们的问题。重新算出前沿，问下一轮。一个问题的答案如果取决于本轮另一个还没答的问题，它属于*之后*的轮次，不属于这一轮。

找*事实*是你的活，从来不是用户的。前沿上的问题需要从环境里取事实（文件系统、工具等）时，派一个子 agent 去查；凡是你自己能查到的，都别问用户。也别干等：一个还在跑的查找就是一个未敲定的前置条件，只有依赖它的下游问题要等子 agent 回报，前沿上其余的问题现在就问。*决策*归用户：每一个都拿去问用户，等用户回答。

前沿清空，会话才算结束：设计树的每条分支都走过，没有任何东西被默默假定。用户确认你们已经达成一致之前，不要据此行动。
