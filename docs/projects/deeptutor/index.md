# DeepTutor：把一句「当我的老师」拆成程序管的八件事

## 摘要 { #abstract }

DeepTutor 是港大数据智能实验室（HKUDS）的开源 AI 辅导平台：把你的教材、论文、视频建成知识库，在同一个 agent 运行时上做问答、出题、解题、深研、可视化、精通路径、沉浸阅读，再带一套三层记忆[^repo]。拿最简单的做法当 baseline —— 往聊天网页丢一个 PDF，再说一句「作为老师一节课一节课教会我」—— 它在长期学一本书时会撞上八类毛病：材料装不下也找不回页码、模型想问你一句只能猜、出题和研究一口气糊完、「学会了」由模型随口说、没法从头按章读、引用对不上原文、换个对话就不认识你、做过的题和该复习的事散在聊天里。DeepTutor 的回答是把这些从 prompt 里拿出来交给程序。设计重心是第四件：掌握分是最近几次作答的加权平均，只答过一两次时封顶 0.5 和 0.8；记忆型、程序型知识点要到 0.9 才放行，下一步学什么由一个不调模型的纯函数算出来，同一个目标没过门就一直返回它。

## 关键词 { #keywords }

AI 辅导（AI tutoring）· 智能辅导系统（intelligent tutoring system，ITS）· 个性化学习（personalized learning）· 精通学习（mastery learning）· 间隔重复（spaced repetition）· 知识追踪（knowledge tracing）· 学习者模型（learner model）· 检索增强生成（RAG）· agent 循环（agent loop）· 人在回路（human-in-the-loop）

## 引言 { #intro }

**领域是 AI 辅导**：不是一问一答，是长期陪一个人把一门学问学下来 —— 讲解、出题、判对错、决定下一步、隔几天回来复习。

- **软件形态**叫智能辅导系统，几十年前就有：按知识点建模学习者，答对答错都更新模型，再据此挑下一题。DeepTutor 把这套放到大模型上：讲解、出题、判概念题交给模型，什么时候算会、下一步学什么、几天后复习，交给程序
- **它自己的定位**是 agent-native 的学习工作区：一个运行时、一份会话上下文，十来种学习模式共用；同一个 `deeptutor` 命令既给人用，也给别的 agent 当工具调[^paper]

**baseline 是聊天网页加一个 PDF，再加一句「作为老师一节课一节课教会我」**。下面八条功能线，各从它在学一本书时撞上的一个具体毛病讲起，只写现状；每条线一篇细讲，每步贴源码模版和用 DeepTutor 自己的代码跑出来的效果。情境统一用一本《应用统计学》第 8 章「假设检验」：学习者叫林小雨，例 8.3 是灌装线抽检 25 瓶、均值 52.3、t = 2.80、双侧 p ≈ 0.0098。

每个界面配一个照上游前端源码做的仿真 demo，嵌在讲它的那一节：主题色、间距、文案都从源码搬，不是截图；不能点，自动把功能演一遍再循环，滚出屏幕就暂停，右下角可以重播。

### 一、知识库：教材建成带签名的索引 { #knowledge }

1. 一个库里混着扫描版 PDF、Markdown 讲义、Word 习题答案，一个解析器吃不下 → **解析引擎可换**：全局选一个，它不认的后缀自动换一个认的顶上；结果按文件哈希加引擎签名缓存
2. 向量检索和知识图谱各有所长，聊天页替你选了也不说 → **一个库绑一个引擎**：自带九种，检索模式按这次调用、库、引擎卡、内置默认逐级取
3. 换了 embedding 模型，旧索引的向量和新问题不在一个空间，检索悄悄变差 → **带签名的索引版本**：签名是 embedding 配置的哈希；重建开新目录，核验通过才发布；只读签名对得上的版本
4. 符号「α」「β」纯向量检索漏，换了说法的段落纯关键词漏 → **两路合并**：向量加 BM25，按名次做倒数排名融合
5. 调了切块、换了引擎，检索变好变坏说不清 → **拿题集打分**：`deeptutor kb eval` 算 Recall、Precision、nDCG、MRR、Hit、MAP

细讲：[知识库：教材建成带签名的索引，换了模型不悄悄顶替](knowledge.md) —— 换模型重建、中断重建时版本表怎么变，构造题集的六个指标

### 二、一轮对话：一个能暂停、能重放的循环 { #runtime }

1. 好好回答要先查第 248 页、再翻第 236 页，一次生成做不到 → **一轮是一个循环**：每圈调一次模型，调了工具就执行、把结果接回去再来，不调工具的那一圈收尾
2. 你只说「讲讲 p 值」，模型不知道你想听定义还是看例题，只能猜 → **ask_user 是一个工具**：模型交 1 到 4 道选择题，程序清洗参数后把这一轮停下，等你答完接着跑
3. 答到一半刷新页面，流就断了 → **事件编号、落库、按号重放**：一轮里的一切都是带序号的事件，总线留一份历史、同时写进数据库，重连时报上收到的最后一号，从下一号续上
4. 「换成出题模式」只是换一段 prompt，手里的工具没变 → **工具表是算出来的**：用户开关、挂了哪些资料、这一轮是什么能力，几样合起来现算挂哪些工具
5. 聊到第 30 轮，记忆、资料清单、工具结果把上下文撑满 → **规矩不动、事实换快照**：system prompt 的规矩一字不变，会变的部分作为快照跟在后面；超窗先剪旧的工具结果

细讲：[一轮对话：一个能暂停、能重放的循环](runtime.md) —— 断线按序号重连、ask_user 的参数清洗、四种轮次的工具表

### 三、学习模式流水线：出题、解题、深研、画图各有骨架 { #modes }

1. 「出 4 道题」一次吐完，两题考同一个点、正确答案不在选项里 → **出题分三段**：先查库和你答错过的题，再列每题的考点和题型，最后逐题生成、过格式检查
2. 解例 8.3 写到第三步忘了第二步算出的 t → **计划由模型写，进度由程序记**：交计划、标完成、重规划都是工具，重规划最多两次
3. 「帮我研究 p 值的常见误读」一口气写完，同一个误读换着说法写三遍 → **子主题排成队**：先问清题目、给大纲让你确认，再逐个子主题研究，中途追加的先去重
4. 画图给一段渲染不了的代码 → **只能经提交工具上画布**：图表配置和 SVG 交之前用插件校验，不过就把错因回给模型重交
5. 每种能力交的东西形状各异 → **同一个信封**：结果连同这一轮的用量走同一个函数发出

细讲：[学习模式流水线：出题、解题、深研、画图各有骨架](modes.md) —— 出题的格式检查、解题工具的进度行、研究队列的去重、图表校验器

### 四、精通路径：学没学会，由程序按作答记录判 { #mastery }

1. 课表只活在对话里，讲过的再讲、没懂的跳过 → **路线是一张表**：模型起草，程序规范化成模块和知识点，每个点四种类型之一
2. 有标准答案的计算和没有标准答案的解释用一把尺 → **两种门**：记忆型、程序型掌握分到 0.9 才过；概念型、设计型要用自己的话讲一遍，模型判过才过
3. 蒙对一题就算会，错一次就永远不算会 → **掌握分**：最近五次作答加权，只答一次封顶 0.5、两次封顶 0.8
4. 让模型判对错它会顺着你 → **判分不经模型的嘴**：答案键存在服务端，先精确比对，模型判定置信度不到 0.8 不算
5. 「下一课」是模型凭印象讲 → **下一步是算出来的**：先判没答的题，再复习到期的，再找第一个没过门的点
6. 学完不复习，三周后弃真取伪又分不清 → **复习按遗忘曲线排**：记得住的概率按 $e^{-t/S}$ 衰减，掉到目标那一刻排复习
7. 商量路线时它顺手出题，学习时它顺手改路线 → **模式管工具**：outline、study、review 三种模式各有能调的工具，调错了告诉模型先切模式

细讲：[精通路径：学没学会，由程序按作答记录判](mastery.md) —— 一条构造路径从头走到尾：每一步的掌握分和下一步、五天后先派复习

### 五、Book 引擎：先报价再开工，一页一页编 { #book }

1. 一次写完的第 3 节方向偏了，只能整本重来 → **先确认再生成**：提案、书脊、页面三步，每步等你点头
2. 一按确认就是十几分钟、几十次调用，不知道批准的是多大一件事 → **确认前先报价**：按章节类型的块模板算字数和时间
3. 后台编着、你又点了重新生成，几路各付一次钱 → **一页一页编，同一页只编一次**：每本书一个队列，同一页正在编就加入它
4. 讲解、要点、测验混成一段，没法单独重做 → **块有类型**：一页由十几种类型的块组成，导出 Markdown 不丢东西
5. 讲义改了，书里引过旧说法的那章不知道自己过时 → **标出过期页**：存每份材料的内容哈希，再检查时按引用锚点找出受影响的页
6. 答错一次就永远「薄弱」，反复答对分数一直涨 → **进度从最近一次作答重算**

细讲：[Book 引擎：先报价再开工，一页一页编，教材改了标出过期页](book.md) —— 三档深度的报价、改了讲义后标出的过期页、导出的 Markdown

### 六、沉浸阅读与视频：带页码的对话，引文先核对再跳 { #reading }

1. PDF 塞进上下文是一团字，「第 12 页」是模型猜的 → **材料切成带定位号的单元**：PDF 一页、EPUB 一章、视频一段字幕
2. 向量检索的切块和页码对不上 → **检索结果自带定位号**：一份材料几百个单元，逐单元全文匹配，每条命中带着页码
3. 引文其实在另一页，或者是模型自己的转述 → **跳之前先核对引文**：模型给页码和逐字引文；在那页就跳过去高亮，在别页就改跳到真正那页，哪儿都找不到就只跳不亮
4. 「第 12 页」只是一串字 → **页码变成能点的链接**：前端把 `[p.12]` 改写成链接，点了就跳
5. 读到一半想问，要把段落复制回对话框 → **读到哪、选了什么，自动带进问题**
6. 视频没法问「第几分钟说的」 → **字幕切成段，按时刻引用**：cue 并成 20 到 90 秒的段，回答引 `[01:40]`

细讲：[沉浸阅读：带页码的对话，引文先核对再跳](reading.md) —— 三层匹配和引文核对的三种结果、24 条字幕并成 12 段

### 七、记忆：一份带脚注、改得了的 markdown { #memory }

1. 模型说「我记得你上次卡在 p 值上」，查不到从哪记的，也删不掉 → **三层是三种文件**：L1 按场景按天追加的事件，L2 每个场景一份 markdown，L3 跨场景的画像
2. 一条记忆三周后说不清从哪来 → **每条事实带脚注**：行尾脚注指回 L1 的证据
3. 让模型直接重写记忆文件，会丢条目、编来源 → **改记忆是一批受校验的操作**：加、改、删三种，整批校验，一条不合格整批作废
4. 一个月的对话丢给模型总结，会编出处 → **归并只能引看见的来源**：切块后每块只能引自己范围里的证据；你点了才跑，能撤回
5. 三层全塞进 prompt 会撑满上下文 → **只有 L3 回到对话里**
6. 几十个文件看不出哪条画像来自哪些对话 → **图谱从文件现拼**：L3 内环、L2 中环、L1 外环按场景分扇区

细讲：[记忆：一份带脚注、改得了的 markdown](memory.md) —— 旧格式读进来写成新格式再读写逐字不变、五批坏操作文档一字不动

### 八、学习空间：题库一张表，错题自己排进复习 { #space }

1. 各处出的题各存各的，拉不出「这周答错的题」 → **所有地方出的题进一张表**
2. 知道哪题错了，不知道今天该复习哪几题 → **答错的题自己排进复习**：题库表挂触发器，错题自动进复习表，间隔按 SM-2 排
3. 一门课的教材、知识库、书、伙伴散在各处 → **课程只挂引用**
4. 今天要做的几件事没地方看 → **看板**：待办、进行中、已完成三栏，卡片能关联对话
5. 下次打开是新对话，上次学到哪要重讲 → **学习日志每轮带进对话**：只带当前任务和上一次的小结

细讲：[学习空间：题库一张表，错题自己排进复习，日志每轮带上](space.md) —— 错题由触发器排进复习、SM-2 的间隔夹取、日志注入的内容

## 其余板块 { #platform }

八条线之外，DeepTutor 还有几块是平台件：让同一套学习能力接到更多地方、更多人手里。它们和「教」的关系不大，各讲一段。

### 伙伴：同一个大脑接进聊天软件 { #partners }

Partner 是挂在聊天软件上的学习伙伴。通道在 `deeptutor/partners/channels/` 下一个模块一个：微信、QQ、飞书、钉钉、企业微信、Telegram、Discord、Slack、Teams、邮件等 16 个，靠扫包发现，第三方通道走 entry point 接进来。消息进一个收发总线，`PartnerRunner` 拿它跑的正是[一轮对话的运行时](runtime.md)里那套 agent 循环，只把系统提示里的「你是 DeepTutor」换成伙伴的名字，人设写在伙伴工作区的 `SOUL.md` 里；知识库、skill、笔记本按发起人的权限整份拷进伙伴自己的工作区。聊天软件里弹不出问题卡，伙伴一调 `ask_user`，那个问题就直接作为这一轮的回复发出去。

### 子智能体：把本机的 Claude Code 叫来答一段 { #subagents }

`deeptutor/services/subagent/registry.py` 登记了 11 个后端：Claude Code、Codex、Grok CLI、Antigravity、Kimi、opencode、MiMo、Hermes（本地和远程两种）、OpenClaw、DeepSeek Harness。聊天进行到一半，可以把一段问题交给其中一个，拿回它的回答接着聊；它们过去的对话记录也能导进来当上下文。伙伴在这张表里也算一种后端，所以聊天里能「请教」自己的伙伴。

### 智能写作：选中一段让模型改 { #co-writer }

### 设置与就绪：配好了不等于能用 { #readiness }

### 多用户、沙箱、技能中心 { #more }

- **多用户是可选的**：`auth.json` 打开认证后，每人一个 `data/users/<uid>/`，JWT 登录，模型、工具、skill、知识库按授权分给每个人；不打开就是单用户
- **模型写的代码进沙箱跑**：一个 `exec` 工具管所有语言，后端按序挑：独立的 runner 容器，Linux 上有 bwrap 就用 bwrap，允许时退到受限子进程，都没有就不挂执行工具（`deeptutor/services/sandbox/config.py` 的 `build_backend`）
- **skill 从技能中心装，过一道门**：skill 用开放的 `SKILL.md` 格式，能从自家的 EduHub 和 ClawHub 装。导入先看注册站给的安全结论，解包时查路径穿越、拒绝软链接、只收白名单后缀，frontmatter 里的 `always` 一律去掉 —— 下载来的 skill 不能把自己塞进每一轮的系统提示；来源和版本记进 `.hub-lock.json`

## 局限 { #limits }

- **掌握分只是近期加权**：最近五次作答按 0.5 到 1.0 加权平均，再按次数封顶，没有题目难度、没有猜对的概率；代码注释自己说这是故意的简单版，要换成 IRT、BKT 只改一个函数
- **间隔复习不是校准过的 FSRS**：可提取率按指数遗忘算，稳定度的涨缩是手调的规则，注释原话「not a calibrated FSRS fit」
- **记忆归并要人点**：L1 到 L2、L2 到 L3 都要从界面或接口触发，不会自己跑；不点，画像就停在上次
- **硬门只管得了能判分的**：记忆型、程序型靠作答分数，概念型、设计型靠模型判你讲得对不对，后两者的门还是模型守的
- **平台件远多于教学件**：伙伴、子智能体、多用户、各家模型和检索引擎的接入占了大头，教学本身的代码只是一小块；读源码要先知道往哪看

## 结论：可以搬走的设计 { #takeaways }

- **学没学会交给程序算**：作答记录落库，掌握分按近期加权、按次数封顶，过门条件按知识点类型分；下一步由一个不调模型的纯函数从这些记录算出来，没过门就一直返回同一个目标
- **答案键不回模型手里**：出题时把答案存在服务端，作答先精确比对，模型判定只交结果和置信度，置信度不够不算
- **问用户做成一个工具**：模型调它就把这一轮停下，问题是结构化的选择题；没有前端时它自动答空，接到聊天软件里就把问题当回复发出去
- **事件带序号、留历史、写进库**：断线重连报上最后一号就能续上，进程重启也能从库里重放，一轮的过程本身就是可以回放的记录
- **工具表每轮现算**：用户开关、挂了哪些资料、这一轮是什么能力几样合起来决定挂什么；模式只在调用时检查，一轮里也能切
- **索引带着建它的 embedding 身份**：重建开新版本、核验通过才发布，读时只认签名一致的版本，换模型不会悄悄混用
- **引用带定位号，跳之前核对**：检索结果自带页码或时刻，模型给逐字引文，程序核对后决定跳哪页、亮不亮，并把正确页码回给模型
- **记忆是带脚注的 markdown，只能经受校验的操作改**：每条事实指回证据，模型只能引它看见的来源，整批不合格就整批作废
- **贵的生成先报价、一页只编一次**：按模板估字数和时间，确认后排队编，同一页的并发请求合并
