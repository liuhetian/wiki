# 板块怎么分：一根从通用到具体的轴，Skills 是它的背面

**板块按一根轴排，从通用到具体**：笔记、Gallery、文章、项目，越往上越具体，一个问题能留的方案越少。Skills 不占一层，是这根轴的背面，每一层都可以有一个给 AI 照着做的影子。轴外还有两样：收藏夹是外面进来的入口，维护是背后的记录。全站 AI 都读，区别只在读正面还是照背面做。

| 层（从通用到具体） | 板块 | 一个问题有几种方案 | 拍一部电影时是哪一步 |
|---|---|---|---|
| 1 | [笔记](../../notes/index.md) | 不对着某个问题，学会一门学问 | 色彩理论、镜头语言 |
| 2 | [Gallery](../../gallery/index.md) | 一个选择，很多选项并排，没有对错，看口味和需要 | 画风选吉卜力还是赛博朋克 |
| 3 | [文章](../../posts/index.md) | 一个通用问题，几种方案，讲各自适合什么、怎么选 | 人物一致性：角色卡有几种做法 |
| 4 | [项目](../index.md) | 一个具体的东西，每个问题只留它那一种方案 | 导演台控场景、并发生成、批量出片 |

| 不在轴上 | 是什么 |
|---|---|
| [Skills](../../skills/index.md) | 轴的背面：某一层的 AI 影子，只留一种做法，浓缩成守则加脚本 |
| [收藏夹](../../bookmarks/index.md) | 轴外的入口：外面的整个来源 —— 论坛、人、合集，什么层的东西都有；还有拿来就用的工具站。只存链接 |
| [维护](#maintenance) | 轴外的记录：skill、Gallery 收录和项目背后的事 |

## 一根轴：从通用到具体 { #axis }

往上每走一层，就多一些限制条件，一个问题能留的方案也越少：笔记不对着哪个问题；Gallery 里一个选择摆着很多选项；文章讲一个问题的几种方案；到了项目，每个问题只剩它自己那一种。

一层垫一层：项目是几个通用问题组合起来、各选一种方案再落到实现；文章讲理由时用到笔记里的理论，要挑画风、配色时翻 Gallery。引用往下走：项目链文章，文章链笔记和 Gallery。

### 笔记：一门学问 { #notes }

为了学会一门学问，读完能自己往下推。学问可以偏理论，比如[统计学](../../notes/statistics/index.md)；也可以很具体，比如数据结构配 [LeetCode 热题 100](../../notes/leetcode/index.md)。

笔记里可以用 git 冲突标记给自己出题：上半写问题，下半空着，答案空着就是提醒，写法见[提问块](../../skills/wiki-guide/course.md#conflict-syntax)。

### Gallery：通用到不用提问题 { #gallery }

现成的东西：一段 prompt、一个色号、一段版式描述、一个 demo、一个人设。它们看起来没提出问题，是因为太通用了 —— 「这页用什么配色」谁都懂，不用先定义，同一套配色给网站、给 PPT、给图片都能用。一个选择摆着很多选项，没有对错，看口味和需要，要用时来翻、来挑：[图片](../../gallery/images/index.md)里 GPT Image 2 的 163 条图配 prompt、[排版](../../gallery/layouts/index.md)里的 167 种版式都是这样。分类按东西的形态分，同一类里再按题材或需求分小节，同一小节里的几条才是互相替换的备选。

本站自己做的，成品和做法写在同一页：[花卉动态生长海报](../../gallery/video/flower-growth-poster.md)的五步拿去就能照做。

### 文章：一个通用问题 { #article }

先把问题定义清楚，再给几种方案和依据，讲各自适合什么情况、怎么选 —— 读完的人知道这个问题该怎么办，拿去用在哪个项目上都行。[上线前的三层验收](../../posts/release-acceptance.md)就是一篇：问题是 AI 项目自己想用例一定漏，方案是三层测试集，各层管什么、为什么。

文章里也可以贴代码，但只是示意，换一个项目照样成立：[骨架法](../../posts/ai-code-skeleton/index.md)贴的骨架文件出自一个礼包管理平台，讲的是任何全栈项目都能照着搭的写法。

同一个问题至少两个项目都解过，就可以提炼成一篇文章：把[梨园](../liyuan/index.md)、[酒馆](../sillytavern/index.md)的「聊久了」对照着写，两边的源码只当依据引过来，项目里那几页照样留着。选型也是文章：「OCR 用哪个」讲在什么情况下选哪个，候选仓库各自是一个项目，文章链过去。

论文笔记也是一篇文章，不另开板块。没答完的问题也写成文章，标在研；答完在原处补完，地址不变。

### 项目：一个具体的东西 { #project }

一个具体的东西 —— 自己做的软件、别人的仓库 —— 讲它解了哪些问题，每个问题只留它自己那一种方案。问题之间互相牵连，一个怎么解会牵制另一个，读者从项目里拿走的是整个东西怎么造。

讲多深都算项目，深浅在项目索引的钩子里标明：

- **概要一页**：它是什么、解决谁的什么问题、主路径怎么跑通，比如 [Teable](../teable/index.md)
- **粗讲一篇**：按主要功能讲清机制，展示具体 prompt、数据结构、文件或输入输出，比如 [wenai](../wenai/index.md)。四档要求见[调研项目](../../skills/project-research/index.md)
- **细讲一组**：每个问题落到它的源码、架构和实跑效果。[梨园](../liyuan/index.md)每条功能线都配源码模版和实跑效果，抽掉[状态](../liyuan/state.md)那页，[重来和回档](../liyuan/branch.md)就讲不通，因为每一轮的分支挂着一份场景快照；这个 wiki 也是项目，[对象存储部署](cos-deploy/index.md)讲到 `deploy.sh` 的每一步，[打码](age-mosaic.md)讲到浏览器里怎么解密还原

概要之后要粗讲或细讲，就在同一个目录里长，入口地址不变。只为这个项目写的操作手册、截图，跟着项目放：[Kindle 常显信息屏](../kindle-dashboard/index.md)的[越狱与显示通道实操](../kindle-dashboard/reference/jailbreak.md)只为把这块看板显示出来，不单独算 skill。

## Skills：轴的背面 { #skill }

Skills 不占一层，每一层都可以有一个影子：把这一层的东西浓缩成 AI 照着做的版本。正面讲为什么、讲有哪几种方案；影子只留一种做法，写成守则加脚本，很少讲原因。

| 正面 | 它的影子 |
|---|---|
| 项目：这个 wiki | [写作规范](../../skills/wiki-guide/index.md) |
| 项目：[动画网页 PPT](../animated-ppt/index.md) | [工程手册](../../skills/writing/deck.md) |
| Gallery：[信息图排版](../../gallery/layouts/infographics.md)、[经典主题色](../../gallery/colors/classic.md) | [配图规范](../../skills/wiki-guide/reference/infographic.md)，按编号去查 |
| Gallery：[旧刊物海报](../../gallery/images/collected/gallery-pulp-posters.md) | 同名 skill [旧刊物海报](../../skills/pulp-poster.md) |

文章同理：一篇讲 OCR 怎么选的文章，影子就是照选定的那个去调用的 skill。不是每层、每页都要有影子；也不是每个影子在站内都有本体 —— [PPT Master](../../skills/ppt-master/index.md) 这类从上游吸纳的，本体在外面的仓库，来龙去脉写在维护记录里。

影子集中放在 Skills 板块，不跟本体放一起：AI 从 Skills 索引一眼就能看全能干什么，顺着祖先索引读到影子时，也不用先把本体讲的原因读一遍。正面页单向挂一行指向自己的影子，skill 不链回来 —— 影子不需要知道本体为什么是这样。

## AI 读哪些 { #ai }

全站 AI 都读。正面它要接着做一个项目、改一个 skill 时去读来龙去脉，比如 CLAUDE.md 让它去[复制本页 Markdown 源](md-copy.md)那篇看复制按钮为什么这样做；干活时照的是背面的 skill。AI 干活不需要理由，但需要具体参数：Gallery 里被 skill 查的风格、画风、版型、主题色，每条正好就是一个参数 —— [配图规范](../../skills/wiki-guide/reference/infographic.md)就让 AI 从[信息图排版](../../gallery/layouts/infographics.md)里抄版式、从[经典主题色](../../gallery/colors/classic.md)里挑颜色。

## 轴外：收藏夹和维护 { #outside }

### 收藏夹：外面的入口 { #bookmarks }

外面的整个来源 —— 一个论坛、一个人、一个合集 —— 里面什么层的东西都有，放不进轴上哪一层：比如 linux.do 这样的论坛，有讲理论的帖子、有配色、有方案，也有项目。拿来就用的工具站没什么可写，也放这里。收藏夹只存链接加一句为什么收，按来源的形态分页；单篇帖子、文章不收，要么写成页面进轴，要么不留。

从里面拆出一样写成页面，它就按层进了轴：讲理论的帖子进笔记，一套好看的配色进 Gallery，讲方案的帖子进文章，一个仓库进项目。条目上记一笔「拆出过」链过去，看得出哪个来源产出多 —— [linux.do](../../bookmarks/community.md) 拆出过一个 Gallery 画风和两个 skill。

### 维护：背后的记录 { #maintenance }

维护不是一个问题加解决方案，是 skill、Gallery 收录和项目背后的记录 —— 从哪来、怎么选的、读的哪个 commit、实测过什么。它写给 AI 看：改一个 skill、重新吸纳上游、换接口之前，先读它的维护记录。页面里只写怎么用，页尾链过去，比如[生成、编辑图片](../../skills/agent-io/reference/image.md)和它的[维护记录](../../maintenance/image.md)。

## 边界怎么判 { #boundary }

- 笔记和文章，看读完拿走什么：学会一门学问、能自己往下推的是笔记；知道一个问题该怎么办的是文章
- Gallery 和文章，看要不要讲理由：挑一套配色不用讲理由，是 Gallery 里的一条；人物一致性有几种做法、各适合什么，要讲理由，是文章
- 文章和项目，看讲的是一个问题还是一个东西：一个问题、几种方案、换个项目照样成立的是文章，三层验收、骨架法都是；一个具体的东西、每个问题只留它那一种的是项目，梨园、Teable 都是，只是讲的深浅不同
- Gallery 和 Skills，看是一个参数还是一套守则：挑风格的样例在 [PPT 风格库](../../gallery/images/ppt-master/index.md)，做 PPT 的步骤是 [PPT Master](../../skills/ppt-master/index.md)
- 收藏夹和轴上各层，看是不是整个来源：一个论坛、一个人、一个合集，什么层都有，存链接在收藏夹；里面的一篇写成页面就按层进轴，不写成页面就不留
- 来源不算数：自己做的 Kindle 常显信息屏和别人做的梨园都是项目
- 收外面的东西不是选择题：正面给人和 AI 读，背面给 AI 照做，一个来源可以一次收进两边 —— 同一个仓库，要它的效果进 Gallery、要弄懂它进项目，是正面；要让 agent 能用进 Skills，是背面

具体放哪个目录、页面怎么写，照[写作规范](../../skills/wiki-guide/index.md#where)。
