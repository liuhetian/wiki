# 部署与日常维护

**没有机器，也没有进程可重启。** 页面、接口、文档站都在 EdgeOne Makers 上，「重启」就是重新部署；数据在平台的存储和 COS 里，部署不动数据。

## 部署在哪

| 部分 | 在哪 | 备注 |
|---|---|---|
| 页面、文档站（静态文件） | EdgeOne Makers 项目 `clip`，中国大陆加速 | 平台上不构建，传上去的是本地构建好的 `build/` |
| 接口、`/wiki/<页>.md`（边缘函数） | 同一个项目 | 一个函数包，一个入口，放在 `edge-functions/` 最顶层 |
| 元素数据 | EdgeOne Blob，存储名 `clipboard` | 对象布局写在 `src/server/repo/db.ts:1` |
| 文件（图片、附件、压缩包、地图缩略图） | 自己的 COS 桶，成都，私有 | 桶名在 `.env` 的 `CLIP_COS_BUCKET`；对象名 `file/<文件 id>` |
| 文档预览 | COS 数据万象，按次计费 | 桶的跨域规则要暴露 `X-Total-Page`，`npm run setup` 配 |
| 域名 `clip.liuhetian.life` | DNS 在同一个腾讯云账号的 DNSPod，证书是 EdgeOne 免费证书 | 都由 `npm run setup` 配 |
| 定时任务 | `edgeone.json:22`：每天 04:00（Asia/Shanghai）`POST /api/cron/cleanup` | 只推一批清理，剩下的靠页面打开时接着调 |
| 构建文档站的 Python 环境 | 兄弟目录 `../test-wiki`（或 `WIKI_ROOT` 指的地方） | 要在里面 `uv sync` 过；没有它 `npm test` 和 `npm run build` 都过不了 |

## 密钥放在哪

值一律不进仓库、不进文档。

| 密钥 | 放在哪 | 谁在用 |
|---|---|---|
| 腾讯云主账号密钥 | 本机 `.env`（`COS_SECRET_ID`、`COS_SECRET_KEY`） | 只有本机脚本：建项目、绑域名、配桶的跨域规则、部署、读项目的环境变量 |
| 只管这个桶的子账号 `clip` 的密钥 | 本机 `.env`（`CLIP_COS_*`）→ 项目环境变量（`COS_*`） | 线上边缘函数 |
| 共用密码、AI 的密码、名字映射 | 本机 `.env`（可选）→ 项目环境变量 | 线上边缘函数；`.env` 里没写时，`smoke`、`backup`、`wipe` 用主账号密钥到项目里取（`scripts/lib/site.ts:16`） |
| `COOKIE_SECRET` | **只在项目环境变量里**，建项目时随机生成（`scripts/setup.ts:36`） | 签登录 cookie；本机没有副本，项目删了重建就换新的，所有设备重新登录 |
| 各人的 `密码#名字` | 各自 iPhone 的快捷指令里 | 快捷指令 |

`.env` 的字段表在 `README.md`「命令」一节。

## 命令

**除了 `npm test` 和本地构建，其余命令都连线上；没有测试环境，线上只有一套数据。**

| 命令 | 做什么 | 碰线上数据吗 |
|---|---|---|
| `npm test`、`npm run typecheck` | 内存版存储上跑接口和共用逻辑 | 不碰 |
| `./deploy.sh` | 只在本地把 `docs/` 构建到 `site/` | 不碰 |
| `npm run dev` | 本地页面，**`/api` 代理到线上**（`vite.config.ts:11`） | 碰：在本地页面上做的操作改的是真实数据 |
| `npm run deploy` | 类型检查 → 测试 → 构建 → 上传 `build/` | 换代码，不动数据 |
| `npm run smoke` | 线上冒烟 | 写：在第一块白板上建几个测试元素、跑完彻底删掉，并把当天的清理跑完（`scripts/smoke.ts:150`） |
| `npm run backup` | 导出所有白板和元素到 `backups/` | 读；读白板会顺手把到期的挪进废纸篓，和打开页面一样 |
| `npm run wipe -- --yes` | 清库：所有元素和文件删掉，白板列表保留 | **删光，找不回来** |
| `npm run setup` | 建项目、写环境变量、配桶的跨域规则、绑域名和证书；做过的步骤跳过 | 改配置，不动数据 |

## 部署

```bash
npm run deploy    # 用工作树构建，没提交的改动也会上线
npm run smoke     # 生效要几十秒，之后跑
```

- 构建顺序固定：页面（vite，会清空 `build/dist`）→ 文档站 → 边缘函数
- 部署失败时脚本打印构建日志的地址（`scripts/deploy.ts:23`）
- 部署期间和之后都没有要迁移的状态；函数是无状态的，登录 cookie 不受影响
- 从零开始的顺序是 `setup → deploy → setup`：平台要求项目先部署过一次才能绑域名

## 改密码、加人

1. 改本机 `.env` 的 `SITE_PASSWORD`、`AI_PASSWORD`、`NAMES`、`WEB_NAMES`
2. `npm run setup` 把改了的写进项目环境变量（`scripts/setup.ts:21`）

- **改共用密码，所有设备要重新登录**：cookie 的签名密钥里混着它（`src/server/auth.ts:28`）。每个人快捷指令里的密码也要跟着改
- 改 AI 的密码不影响人
- 从 `NAMES` 里去掉一个名字，这个人的 cookie 和快捷指令立即失效；他编辑过的元素角落显示成英文键

<这里可以补充：改完项目环境变量后要不要重新部署才生效>

## 只能在控制台做的

- 强制 HTTPS、HSTS：EdgeOne 控制台 → 项目 → 域名管理 → 配置 HTTPS。代码和 SDK 改不了
- 看边缘函数的日志。函数里记的日志有两种前缀：`[defer]`（响应发出后的后台任务失败）、`[chat-zip]`（聊天记录压缩包拆不开，退回成普通文件卡片）

## 报错对应什么

没有告警。页面调接口遇到的 5xx 和网络不通会自动报到「故障」白板，在设置里打开「显示故障白板」就能看到；AI 读白板「故障」也行。下面是接口和页面上会看到的现象。

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 接口回 500「站点配置缺失」 | 项目环境变量缺 `SITE_PASSWORD`、`COOKIE_SECRET` 或 `NAMES`（`src/server/app.ts:33`） | `npm run setup` |
| 接口回 500「服务出错：COS 配置缺失」 | 项目环境变量缺 `COS_*`（`src/server/edge.ts:15`） | `npm run setup` |
| 任何接口偶尔回 545，响应体是 `Error return from script`；页面上是「请求失败（545）」，或者打开页面被要求重新登录 | 函数冷启动超时被平台掐掉 | 看故障白板上 545 多不多。多了先看函数包是不是变大了（`npm run build:edge` 打印大小和最大的几项，超过 350 KB 构建就失败），见[开发 · 平台的坑](dev.md#platform) |
| 读白板偶尔回 504 | 存储个别请求变慢 | 看故障白板上是不是只落在读白板的接口上；页面下一次同步会再读 |
| 新建、挪动回 409「这块白板满了」 | 白板到了 50 个 | 清理或换一块；这是[需求](requirements.md)定的上限 |
| `/wiki/<页>.md` 回 404「没有这页文档」 | 这页没加进函数包 | 见[开发 · 改文档](dev.md#wiki) |
| 文档页样式全乱 | 访问的是不带斜杠的 `/wiki/x`，又缺 301 | 同上 |
| 文档页上的实时数据显示「加载失败」 | 没登录；`.md` 是没带 `X-Password` | 正常行为 |
| 所有人突然要重新登录 | 共用密码改了，或 `COOKIE_SECRET` 换了 | 正常行为 |
| 故障白板上一直在长新便利贴 | 某个接口在持续出错，便利贴上一行一次，写着时间、接口、状态码 | 按状态码对上面几行；故障白板满 50 张会自己删最早的 |
| 到期的东西还留在白板上、废纸篓超过 50 个 | 清理是分批的，还没轮到 | 打开页面会接着清；也可以反复 `POST /api/cron/cleanup` 到返回 `done: true`，这个接口不用登录（`src/server/routes/auth.ts:25`） |

## 备份和清库

- **`npm run backup` 只备元素数据**，写到 `backups/backup-<时间戳>.json`（不进 git）。文件本体留在 COS，不在备份里
- 任何一步失败就不写文件，不会留下不完整的备份
- **数据格式变了就清库，不做兼容**（[需求](requirements.md)「技术与数据」）：先 `npm run backup`，再 `npm run wipe -- --yes`。清库走的是接口：各白板的元素进废纸篓 → 清空废纸篓 → 把清理跑完，删掉没人引用的文件
- 清理的进度记在存储的 `cleanup/state.json`，一轮做完自己删掉

## 时间

- 定时任务按 Asia/Shanghai
- 数据里的时间都是毫秒时间戳，不带时区
- 文件的临时地址按 UTC 的整天取整（`src/server/storage/files.ts:28`）：北京时间每天 08:00 换一批地址，有效两天
