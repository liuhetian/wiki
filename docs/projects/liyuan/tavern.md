# 酒馆的预设被拆开发放，卡前端靠垫片照跑

网页版 ChatGPT 只认一段 system prompt。酒馆（SillyTavern）是角色扮演圈的老牌前端，生态里攒下了大量角色卡、预设和世界书——它们本质上也是「拼成一段 prompt、生成一次」的写法。梨园要让这些资产导入就能用，难点不在解析格式，在于它们是为一次生成写的，搬进 agent 循环会和梨园自己的机制打架。

## 四样酒馆资产 { #terms }

- **角色卡**：一个 PNG 或 JSON，装人设和开场白，常常还内嵌世界书、美化正则（把模型输出里的标签渲染成 HTML 皮肤）和页面脚本。作者抽查五张真卡，四张的人设字段是空的，正文都写在世界书里（`docs/CARD-ANATOMY.md:9`）[^repo]
- **预设**：几十到两百多个提示词块，带开关和顺序，酒馆每轮按开关用宏重新拼成 prompt
- **世界书**：一条条设定，蓝灯条目常驻，绿灯条目在关键词命中时才进 prompt
- **MVU**：酒馆的一个插件。卡要求模型每轮末尾输出 `<UpdateVariable>` 加 JSON Patch，插件据此改一棵变量树，状态栏脚本读这棵树重画

## 预设为什么不能原样拼进去 { #why }

`docs/PLAN-RECTIFY.md:13` 的定性：预设是酒馆唯一可编程槽里「用散文写的装配程序」，为「无状态 / 无工具 / 每轮重发 / 一次生成」的旧环境而写——梨园每造一个真机制，预设里就多一层违禁品。几个典型：

- **思考地板**：「思考必须≥3500 tokens」「铁律自检（生成前必须执行）逐句扫描输出文本」——梨园本来就有原生思考和工具循环
- **末尾预填**：一块 assistant 角色的 `hashlib follow the ⋙ request：OUTPUT <think_fox~>` 被摆到生成点前，provider 把正文判成思维链切走，有一拍正文只剩一个字「你」（`f5d3d13`）。现在末尾的预填块整块丢弃
- **插件协议**：要求每轮输出 `<UpdateVariable>`，和稿纸「只写剧情」互斥，首拍 31% 的思考花在纠结听谁的（`src/protocol-detect.ts:5`）

9/12 做过一组对照（`docs/PLAN-PRESET-HARNESS-STRIP.md:103`）：同卡、同输入、同模型，带整份预设的思考 69,697 字，剥离后 6,216 字，差 11.2 倍；整份那组的思考里 `injection` 出现 25 次——模型把历史之后的预设段判成了恶意注入。

## 默认的快速处理：给每段贴标签，再分流 { #declare }

1. **导入**：原 JSON 落盘，一个字不改
2. **触发**：装载、拨开关、保存、换卡都会重新转译，缺省走「声明」机制（`server/rest.ts:1201`）
3. **编译**：按酒馆的顺序走一遍，关着的块跳过，`setvar / getvar` 照常求值，末尾预填块丢弃
4. **声明**：声明过、指纹没变的段直接复用；缺的交给旁路模型，每段带一个段头 `⟦编号｜角色｜位置｜块名⟧`，要它返回 `[{"id":1,"station":"…"}]`。规则里两条兜底（`src/preset-declare.ts:116`）：「破限与身份类内容一律 identity，不做取舍」「拿不准的分段一律 writing（保守保留）」
5. **分流**（`src/preset-declare.ts:26`）：

    | 标签 | 内容 | 去向 |
    |---|---|---|
    | `identity` | 身份、破限 | 卡级 `APPEND_SYSTEM.md` |
    | `writing` | 写作规则 | 卡档案 `AGENTS.md` |
    | `thinking` / `draft` / `output` / `memory` | 预设自己模拟的思考、草稿、输出格式、记账 | 停用条目，梨园原生机制接管 |
    | `wrapper` | 材料包装 | 跳过 |

6. **落盘**：每块写成卡文件里一条「块名（预设）」条目，停用的整段包进 HTML 注释、送模时剥掉，用户在条目视图里随时能拨开。声明结果存成 `assets/presets/.liyuan/预设声明-<名>.json`，所有卡共用一份

另一种「深度处理」让模型把全文重写成身份和写作规则两条，丢掉的段列账，要几分钟。快速处理是贴标签、原文照搬，三十秒级。这就是铁律三说的「让读得懂卡的模型声明一次，声明落成数据，harness 死板执行数据」——错了也错在一份看得见、改得动的文件上。

## 卡前端：iframe 加一层模拟酒馆的垫片 { #cardfront }

- **显示管线**（`src/postprocess.ts:474`）：先跑作者的美化正则（预设的在前、卡的在后，和酒馆链序一致），再处理剩下的标签。正则按作者标的位置拆成显示侧和送模侧，作者「不想让模型看」的块真的不送模
- **HTML 进 iframe**：带 `<style>` 的美化正则包成整页 HTML 进 iframe，同时剥掉 script；带 `on*=` 事件的整条不接——修 CSS 不顺手给 JS 权限（`src/cardfront.ts`）
- **页面脚本**（悬浮球这类）跑在一个 0×0 的宿主 iframe 里，同源读父页的脚本清单，用 `textContent` 建 script 执行，避开字面量 `</script>` 截断
- **垫片**（`web/src/tavernShim.ts`）：完整 jQuery、lodash 子集、变量读写、事件、toastr、MVU 空壳；卡调 `generate` 只是把文字当一条用户发言发出去。故意不做的：聊天、消息作用域的变量写入一律拒绝，`getChatMessages` 永远返回空，预设带的脚本不跑。注入垫片时踩过一个坑：jQuery 源码里的 `$1` 被 `String.replace` 当成替换模式吃掉，事件委托全部失效（`f04e0d7`）
- **MVU**：主模型不再输出 `<UpdateVariable>`。变量初值取世界书的 `[initvar]`，没有就取 Zod schema 的默认值；场记每拍顺手出一份 `mvu_patch`，前端用 postMessage 把变量树推进 iframe。状态栏占位只补在最新一条消息上（`src/mvu.ts`）——拿当前的树去画旧消息等于撒谎
- **宏**：`{{random}}` 按参数钉死，同参数恒得同值（`src/preset-macro.ts:88`）——每拍重摇会让 system 开头的字节每拍不同，prompt 前缀缓存全砸

## 世界书分三层，开思考只给标题 { #lorebook }

- **蓝灯**：常驻。卡有档案就镜像成「（世界书·书名）」条目，没有就进 system 的世界设定段
- **绿灯**：每拍扫最近 4 条剧情，最多命中 3 条；另附一份全部绿灯标题的【设定集索引】
- **工具**：`lorebook_search` 等 10 个，模型自己查

命中的绿灯只给标题、不给正文，来自 8/23 的一次实弹（`f5d3d13`）：模型三次动念要查「怀瑾」，都被注入劝退——「The 设定集索引 doesn't list 怀瑾 → So 怀瑾 is new - I can create him」。改成只给标题后，同卡同输入的工具调用从 0 次变成 4 次，思考少了 51%。第二天 `8cbc401` 补了一条：关思考的模型不会主动调工具，这一档退回直接给正文。

## 谁管什么 { #split }

- **程序**：编译预设、正则分侧、MVU 初值、关键词扫描；插件协议条目在导入时判一次，写成判定文件，运行时只执行文件（`d2619dc`）
- **模型**：每段预设归哪类，场记顺手改 MVU 变量，要不要查世界书
- **用户**：拨条目开关，选快速还是深度处理
