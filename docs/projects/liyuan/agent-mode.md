# 写小说时正文是文件，沙箱只是一个钩子

在网页版 ChatGPT 里写小说，正文就是它的回复——想改第三章的某一句，只能让它重写一遍、自己再复制回去。梨园的 agent 模式学 coding agent：正文是磁盘上一章一个 `.md` 文件，模型和用户在讨论区商量，结论落成对文件的改动，每轮结束程序存一个检查点。同一套「模型能动文件」的能力也给了改卡的工作模式，那边的边界只靠一个钩子，出过事。

## agent 模式：讨论在对话里，正文在文件里 { #agent-mode }

1. **新建时选定**：新建项目默认是扮演，选 agent 后就是这个子项目的属性，建好不能切（`src/stage/engine.ts:624`）[^repo]。可以挑一条开场白落成 `正文/000-开场.md`
2. **换一份身份**：扮演的 `APPEND_SYSTEM.md` 退场，换成 `AGENT_APPEND_SYSTEM.md`，开头一句定调：

    > 用户是导演，不是故事里的角色；你们之间的每一条消息都是讨论，永远不是正文。

3. **正文不进上下文**：每轮随附的项目状态块只有前情提要、世界状态、名录和【正文目录】——文件名、字数、最后改动时间。要看前文，模型自己去读
4. **改稿用 pi 原生工具**：`read / grep / edit / write` 是 pi 原版，梨园没再包一层；可以改任何一章的任何一句，一轮可以碰多个文件
5. **轮末检查点**（`src/stage/story-history.ts`）：每个 `.md` 按 sha256 存进 `历史/对象/`，同内容不重存；整份清单和上一条比，变了就往 `检查点.jsonl` 追加一行，记时间、本轮用户原话的前 60 字、文件清单和改了哪些。改名靠「同一个哈希在旧清单消失、在新清单出现」认出来。文件头写得直白：「这是 git 的 blob＋tree，没有 git 的分支/合并/远端」
6. **新章才记账**：只对新增的章跑[场记](scribe.md)，修改和改名不触发；之后按章刷新前情，再压缩讨论
7. **两种恢复**：只把 `正文/` 恢复到某个检查点、讨论不动；或者文件和对话一起回到那一轮之前。前端的「撤销本轮」就是后者

- **自己切换**：扮演工具清单里常驻一个 `conversation_mode`。模型判断用户要改卡，就自己切进工作模式：会话树记一条切换，下一次请求换掉工具和 system（`setTurnSystemPrompt` 是梨园给 pi 加的接口）。触发切换的那条请求被追溯归入维护，不进剧情、场记和记忆
- **改卡有工程**（`src/card-authoring.ts`）：把卡展开到 `创作/`，原卡字节存快照，公开格式的每个槽位——人设字段、开场白、世界书条目、正则、脚本——各成一个文件。写回只改和原值不同的槽位，没声明的 JSON、插件元数据、PNG 图像沿用原包；脚本先 `node --check` 查语法，不执行；原卡被别处改过就先要求 rebase
- **沙箱是 `tool_call` 钩子里的一个纯函数**（`src/sandbox.ts:209`）：卡目录内随便读写；公共的世界书库、预设库可读，写要申请；同卡别的子项目一律拒绝；会话和检查点目录不许原生写入；其余都要申请
- **申请靠选择卡**：钩子是 async 的，agent 循环停在那里等用户点「允许一次 / 本会话允许 / 永久允许（本卡）/ 拒绝」。授权单位是目录不是单个文件；本会话的授权存进会话树、随分支重放，永久的写进 `卡.json`
- **没有 OS 级隔离**：`docs/PLAN-SANDBOX.md:100` 认下代价——「批了 bash 就是批了整台机器的 shell」

## 60 多本世界书被删之后补的三刀 { #incident }

仓库里只有事故摘要：`src/asset-vault.ts:4` 写「agent 越权写全局世界书、又用底层脚本 `os.remove` 硬删了 60+ 本」，实际形态是 `python cleanup.py`。完整经过在作者本机的记忆文件里，没进仓库，确切日期也查不到；修复 10/16 进了 `111e7c5`。根因（`docs/PLAN-AGENT-BACK-TO-PI.md:8`）：四道门只覆盖梨园自己发行的工具，bash 是并行通道，`卡.json` 里的 bash 授权是一个布尔值，批一次之后再不过问。

- **命令黑名单**：`BASH_DENYLIST.txt` 用户可见可改，写法同 Claude Code 的 `Bash(...)` 规则，拦删根、`mkfs`、`dd` 写设备、fork 炸弹。`src/bash-denylist.ts` 自承「防手滑，不防蓄意绕过」——`$(echo rm) -rf /` 拦不到，脚本内部更拦不到，这次的 `python cleanup.py` 本身就不在其中
- **免问前缀**：bash 授权从一个布尔改成前缀列表，逐段匹配，防 `cd x && 任意命令` 被 `cd` 一把带走
- **资产快照**：`src/asset-vault.ts` 给世界书、预设、人设、技能库存内容寻址快照，启动、每 10 分钟、每次写操作之后各存一次，保留 50 个；经 API 的删除改进回收站。它自称「本机的安全网，不是备份」，`cards/` 下的工作空间不在保护范围

这一刀也让作者改了口。9/12 的 `docs/PLAN-SANDBOX.md:48` 写的是「不做『危险命令识别』正则」；10/15 重新解释铁律三：黑名单枚举的是「OS 命令身份」，不是第三方措辞，而且名单是用户能改的数据。

## 谁管什么 { #split }

- **程序**：检查点和恢复、新章触发场记、沙箱判定、资产快照
- **模型**：写不写、改哪章，什么时候切进工作模式，改卡改成什么样
- **用户**：越界申请拍板，选恢复方式，编辑黑名单和免问前缀
