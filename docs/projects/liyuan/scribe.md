# 记账不归主演，归收笔后的第二个模型

网页版 ChatGPT 没有账本：谁拿着怀表、现在几点、谁已经离场，全靠模型从聊天记录里回忆——聊长了就忘，重新生成一次还可能把废弃的那版当真。梨园把这些事实记成一本账：由收笔后另起的一次模型调用来记，存在 pi 的会话树上。账本跟着分支走，回滚和 swipe 不需要任何同步逻辑。

## 一拍的账是怎么记上的 { #flow }

1. **开演读账**：`stateFromBranch` 从当前分支往回找最近一条 `rp-state` 条目（`src/stage/assemble.ts:246`），渲染成【世界状态】【登场名录】放进末条 user 消息，system 里写明「以状态为准」。主演手上只有只读的 `world_state_get`，没有任何写账工具
2. **收笔才记**：本拍有正文、没被中断，才进入记账（`src/stage/engine.ts:1277`）
3. **场记旁路**：另起一次独立调用。配了旁路模型就用它（可以选便宜的），没配就用剧情模型；默认关思考；最多 2048 token——注释记着 1024 实测会截断出半截 JSON（`engine.ts:1634`）。这一拍要等场记记完才算结束
4. **场记只做一件事**：读【当前账本】和【本轮对话】，吐 JSON（`src/scribe.ts:94`）。prompt 开头是「你是一场角色扮演的场记……只做一件事：输出 JSON，更新需要记账的持久变化」，要点里专门写了一句：

    > 否定性事件也要记账（赠礼被拒→物品仍在原主处；承诺被收回→记入 flags）

    按 prompt 的字段规则，一份 patch 大致长这样（示意，不是实测输出）：

    ```json
    {"patch": {
      "time": "第二天清晨",
      "characters": {"明月": {"affinity": 7, "at": "书房"}},
      "inventory": ["黄铜怀表（旅人持有）"]
    }}
    ```

5. **程序合并**（`src/state.ts:88` 的 `applyPatch`）：时间、地点整体替换；角色按字段合并，好感取整、夹在 ±100；传 `null` 删除；物品和剧情线必须给完整清单；未知顶层字段拒收；人名的大小写变体先归一。登场名录只增不改，记每个名字首次登场的剧内时间
6. **落进会话树**：确认分支没变，把整份账本作为一条 `rp-state` 追加进会话树（`src/stage/scribe-run.ts:88`），磁盘上的 json 只是缓存。用户在界面上手改账本，也是追加一条新的 `rp-state`

## 账本跟着分支走，回滚不用同步 { #branch }

总原则写在 `docs/PLAN-RP-HARNESS.md:92`：**世界 = f(分支)**。账本、前情摘要、面板都从当前分支现算，磁盘文件降级为缓存。

- **swipe**：树指针移回最后一条用户消息再生成，新回复成为同级分支。`server/main.ts:1135` 的注释说清了为什么不用写恢复代码：

    > 废弃分支上的场记快照天然不在新分支上，账本不会泄漏（8/02 A 雷的结构性解法）

- **存档和回档**：存档是一条 `rp-save` 条目，排在场记之后，保证紧跟当拍账本；回档就是用 pi 的 `navigateTree` 跳回那个节点。`planNewSave`（`src/worldline.ts:180`）看上一个存档之后有没有不在当前分支上的存档，有就分出一条新世界线
- **叶守卫**：场记和压缩在旁路调用前后各读一次当前叶，不一致就整份丢弃（`scribe-run.ts:88`、`src/stage/compact.ts:274`）——场记还在跑时用户切了分支，迟到的账不会记错地方
- **向量记忆也按分支隔离**（`a888b47`）：动机写在 `src/memory/service.ts:55`，「13 次重roll 中第 5、10 拍入库，第 11 拍起开始写『承接上一拍』」——被废弃的那几拍混进了召回。现在入库带节点 id，召回按当前分支的节点过滤。缺口是压缩归档的条目不带节点 id，对所有分支可见；向量记忆默认关闭

## 剧情压缩也自己做 { #compact }

- **触发**：每拍场记之后判断一次——没被摘要覆盖的拍数达到「保留 6 拍 + 周期 30 拍」，且能裁的正文不少于 2000 字（`src/stage/compact.ts:41`）；周期填 0 关闭
- **切点**：倒数第 6 条用户消息之前的全部交给旁路模型，写五节摘要：前情提要、人物、承诺与伏笔、事实账、当前场景（`src/scribe.ts:283`）。承诺与伏笔一节要求「宁多勿漏——漏掉一条，后续剧情就永远丢失它」，当前场景一节警告「写成更早的场景会导致剧情倒退」。上一份摘要整份并进来，所以分支上只有最后一份生效
- **落地**：分支没变 → 被裁的原文先归档进向量库 → 写一条 `rp-summary`，记下覆盖到哪条。组装时被覆盖的部分直接不进上下文，换成【前情提要】；树只追加，原文还在
- **pi 自带的 compact 被直接取消**（`.liyuan/extensions/roleplay.ts:1279`）。理由在 `compact.ts:8`：

    > 旧路径压的是 pi 的 AgentSession 消息副本，看不全引擎写进树的东西……于是长局压不动。压缩权跟着上下文权走——谁装配，谁压缩。

    更早的理由在首个提交里：pi 默认的摘要是写代码用的模板，会把陈旧的时间、场景当成关键上下文，压缩后剧情场景回退

## 谁管什么 { #split }

- **程序**：什么时候记、什么时候压，合并规则、好感夹值、名录只增，切点，叶守卫，按分支过滤
- **模型**：patch 里写什么，摘要怎么写；主演只读账，不写账
- **用户**：在界面上手改账本，存档，切世界线
