# 铁律是写给 AI 助手的：作者怎么用 Claude 开发梨园

一般人让 AI 写代码，是提需求、看结果、不满意再提。梨园的作者把 AI 当成一个需要管住手的同事：仓库根的 `CLAUDE.md` 不写项目介绍，写的是禁止 AI 打补丁的铁律；AI 先只读、写问题清单，用户说「动手」才改；判断演出好坏的主要证据，是模型自己的思考记录。

## 一次改动从发现到提交 { #loop }

拿 9/23 凌晨那次「正文写进讨论区」走一遍（经过见 [agent 模式](agent-mode.md#rewrite)）[^repo]：

1. **用户实弹**：用户自己玩，发现 agent 模式下模型不写文件，把 1628 字正文输出在了讨论区
2. **AI 查会话记录**：坐实原因是扮演的全局追加整份进了 agent 轮，500 字的 agent 说明拗不过它
3. **写进文档**：现象和原因记进 `docs/PLAN-AGENT-CODING.md:171` 的状态节
4. **用户定案**：「架构不动，`AGENT.md` 是多余的——它的定位就是全局追加那一格」
5. **AI 动手**：按铁律换槽、不加句子；在隔离实例上同卡同模型复测，讨论轮零正文、写作轮落文件；commit `6920250` 带 Claude 署名

用户管方向、管否决、管实际玩；AI 管读代码、读记录、写文档、实现和测试。规矩写在仓库里，换一个会话、换一个 AI 都一样生效。

## 立规矩：防的是 AI 最顺手的修法 { #rules }

`AGENTS.md` 开头写明「本文件是任何 AI 助手（Claude Code / opencode / 其他）进入本仓库的**第一读**」，第一条：

> **禁止直接动手改代码**，除非用户明确说「开始/动手」。

`CLAUDE.md` 是 8/10 立的四条铁律（[原文](harness.md#iron-law)）：禁止堆叠提示词，判据是 diff 让送模文案变长；禁止新增注入点；禁止识别器、名单、特判，现存名单只许收缩；动手前答出三问——问题的全集是什么、现有机制里谁该负责、换一张没见过的卡会怎样。违律方案默认否决，用户的定案是「已记录的缺陷等机制解，好过多一层堆叠」。

「堆叠」长什么样，git 历史里看得到。8/09 凌晨 03:58 到上午 10:40，十来个提交一路是：每段写完即修的轮次卡、行首 `###` 判违规当场逼修、比喻正则加排除名单、轮次上限 12 提到 20。8/10 18:24:06 最后一个补丁 `622c96f` 还在往状态栏名单里补认 `stateN`，43 秒后 `d1be353` 立了铁律。推断：这些正是 AI 面对一个具体症状时最顺手的修法——再加一句话、再加一个特判。之后的计划文档都带一节「铁律自检」（`docs/PLAN-SANDBOX.md:43`）。

## 读模型的思考记录来调演出 { #thinking }

梨园跑在本机，每拍的完整思考都存在 pi 的会话文件里。不少设计决定直接由思考记录推动：

- `src/draft.ts:4`：「25k 字 thinking 里正文出现 2 遍」——改一处就得在脑内把全稿重誊一遍，于是有了稿纸工具
- 演段轮思考塌成 28 字的报标题，促成了 8 月的门禁（见[分权](harness.md#august)）
- 默认预设让 39%–47% 的思考耗在跟它谈判边界上，促成了删预设
- 模型「看着索引直接下结论」，促成了世界书只给标题（见[酒馆兼容](tavern.md#lorebook)）

读记录本身也立了规程。`docs/READING-THINKING.md` 开头是一次事故：

> 曾把**下午 17:27/17:29 的旧会话生成**当成「刚刚跑的两次」，把 11k 字英文思考误报为用户当场所见——用户当场否认「最多 1K」。

根因是按文件修改时间取最新，而旧会话会被切模型之类的记录碰到最新时间。规程于是要求：用每行自带的时间戳换算成北京时间，去对用户说的时刻；同一个父节点下的多条回复是 swipe，不是多拍；汇报时先报时间核对，思考长度逐段报。

## 文档按用途分开，用户原话单独标 { #docs }

- **FINDINGS 只记问题**：「本档只记问题，不给方案、不动代码」（`docs/FINDINGS-PI-RETURN.md:7`），用户的约束是「我们这个窗口只找问题」
- **PLAN 切成刀**：每刀写内容、落点、验收，commit 标题直接写「刀 N」；`docs/PI-RETURN-KNIFE1~3.md` 每刀一份落地记录，带验证表和「计划假设的修正」
- **实弹**：真模型、真卡，在隔离实例上跑；8 月的 commit 常在括号里附测试数，如「（577 绿）」
- **用户原话不改写**：「用户定案（原话大意，不得改写）」（`docs/PLAN-AGENT-MODE.md:7`）、「参照物（用户 2026-09-22 定，不得改写）」
- **被否决的建议记在案**（`docs/FINDINGS-PI-RETURN.md:320`）：

    > ⛔ 我（Claude）本窗口给过的错误建议，别再提：我曾建议「预设进 `SYSTEM.md` 那格、替换基座」……**用户当场否决**

- **诊断错了也记**：第二次回归 pi 时，AI 原先对 system 基座的诊断在文档里留着「实测更正」块，那一刀评估后关闭

## Claude 署名的提交集中在 9 月 { #commits }

仓库从 7/13 的「Liyuan 1.0.0 — initial commit」开始，之前的历史不在库里。278 个提交里 44 个带 Claude 署名：Fable 5 有 35 个，Opus 4.8 有 6 个，Fable 5.1 有 3 个。

| 月份 | 署名 / 全部 | 集中在 |
|---|---|---|
| 7 月 | 0 / 53 | |
| 8 月 | 5 / 93 | 8/15 预设双管线、状态栏渲染退场 |
