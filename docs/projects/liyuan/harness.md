# harness 越管越差，作者把权一层层还给模型

网页版 ChatGPT 的 system prompt 是一段死文字——说完就管不着了。梨园的 harness 手里握着多得多的东西：每一轮往模型眼前塞什么、给哪些工具、什么条件下才算写完。8 月作者把这些权力用到了头，模型越演越僵；之后两个月做的事，是把权一层层还回去。这是梨园设计心思花得最多的地方，代码量却不显——拆掉的比留下的多。

## 现在模型每拍看到的，只有数据块和工具 { #now }

用户发一句，`server/main.ts:3214` 调 `performTurn`，进入 `src/stage/engine.ts` 的 `#turn`。一拍按这个顺序走：

1. **system 每拍现拼**，分两层。底下是 pi 的基座：`SYSTEM.md` 只有一句英文，告诉模型「你脚下的工作目录是一张卡」。上面是梨园段（`src/stage/assemble.ts:294` 起）：全局 `APPEND_SYSTEM.md`（41 行扮演定义）→ 卡级 `APPEND_SYSTEM.md`（酒馆预设转译后落在这）→ 卡的 `AGENTS.md` → 用户扮演的身份 → 常驻世界书 → 消息流约定
2. **历史不原样回放**：从 pi 的会话树重建，往拍只留定稿正文，最早的一段换成【前情提要】
3. **末条 user 消息 = 数据块 + 用户原话**：数据块是【世界状态】【登场名录】【活跃面板】【相关设定】【设定集索引】等，必须排在原话前面——`engine.ts:1007` 的注释记着 8/03 实测：数据块压在提问之后，模型会把提问读成历史里的旧话，既不检索也不正面回应
4. **约 35 个工具**：稿纸 `draft_write / append / edit / search / seal`，改上一拍的 `previous_draft_edit`，`ask`，世界书 10 个，记忆 6 个，面板、世界线、切换模式。一拍最多 20 轮（`src/stage/tools.ts:29`），到顶撤掉工具
5. **怎么演全归模型**：查不查、列不列计划、写多长、何时 `ask`、何时收笔。它不调工具直接输出，引擎把文字代收成 `draft_write` 并自动收笔（`engine.ts:1412`）；它写了稿又没调 `draft_seal`，这一拍就算没写完，只提示「稿件已保存，本拍尚未收笔」，场记和压缩都不跑（`engine.ts:1268`）

扮演定义里管得最紧的一句，管的是「什么叫写完」，不是「怎么写」：

> 一拍的结束条件是**正文已经交付**——不是「计划已列」，也不是「工具已调」。

和网页版 ChatGPT 比，差别落在五处：system 按文件现拼，历史从会话树投影，一拍是多轮工具循环而不是生成一次，产出是能回头改的工件，拍后还有第二个模型记账（见[场记](scribe.md)）。

## 8 月：门禁一道道加上去，模型越演越僵 { #august }

<div class="zx-timeline" markdown>

### 2026-08-08 · 分轮演出和硬门禁 {: data-kind="加" }

`ad8cc72` 把一拍拆成「规划 → 逐段演 → 收笔」，每一轮注入一张轮次卡，告诉模型这一轮该想什么。当晚实弹，演段轮的思考塌成报标题——「开始演第一段」28 字，第 2、3 段之间零思考直接连发。改了三次措辞，记录写「四问措辞完全没生效」。作者的判断（`docs/PLAN-ROUND-FLOW.md:289`）：

> 注入卡是「说给模型听」的弱约束……卡只在下一轮 stream 前注入，**永远追不上它的手速**。

于是「对齐 opencode 硬件级控制」，加上同轮连发门禁和零思考门禁。

### 2026-08-09 · 一夜补丁 {: data-kind="加" }

验收器在正文里数比喻：「像 / 仿佛 / 如同」超过段数的五分之一就记违规，没修完就拦住续写和收笔，只放行 `draft_edit`。「摄像机」的「像」被数了进去，报告只给次数不给位置，模型找不到该改哪，连修 9 轮。当天的修法（`89f922a`）是再加一张排除名单 `(?<![摄录图画头塑雕肖遗想偶佛镜成显])像(?![素机片册章])`，外加「同一批违规连修 3 轮未消就自动放行」——又一张名单，又一道安全阀。

同一夜还补了行首 `###` 判违规（`231d63b`）、轮次上限 12 提到 20（`5058d15`）。当天的走查记下七张轮次卡、四道门禁、四层状态栏提醒，批注是「宁多勿少」。

### 2026-08-10 · 立铁律 {: data-kind="拆" }

导火索是一句「每拍在正文之后按同样的块结构输出」，模型照做，把状态栏写进了稿件。最后一个补丁 `622c96f` 还在往状态栏名单里补认 `stateN`，紧接着 `d1be353` 在仓库根的 `CLAUDE.md` 立了四条铁律（[原文](#iron-law)）：

> 用各种情况的堆叠去处理问题，完全扼杀了 agent 的灵活性。

判据都是机械的：diff 让送模文案变长了、新增了向模型塞话的地方、往名单里添了行——都算违律。配套的修改契约 `docs/PLAN-RECTIFY.md` 第一条判据是「harness 源码里不再有一句扮演」，并定性「修复是伪命题」：落笔之后只送事实，不送评价。

### 2026-08-11 · 五注入，和一次当天回滚 {: data-kind="拆" }

`8a24e30` 执行死亡清单：删验收器、删修复链，七张卡收成规划、进度、判定、记账、谢幕五个注入。同日 `9a6b793` 加了「开拍强制通读全部 skill」，commit 写「相信模型」；当晚 `8e88c22` 整体回滚，理由只有一句「效果越来越差，回到保存版本」。

### 2026-08-23 · 模型手里只剩 ask {: data-kind="拆" }

`c466cd1` 把稿纸六件套、路标工具、`world_state_update` 全部撤出模型视野，记账整体交给场记（`f5eb270`），进度、判定、谢幕注入随之删除。`aa5be40` 让 skill 回到标准的按需读取，commit 里记着用户原话：

> 让他回归最本初的模样，就是标标准准的 agent 的工具，对梨园与 Claude Code 一般无二那种
>
> 模型调用与否看缘分，功能保留着就行

## 9 月以后：连生成循环都交还 pi { #pi }

到 9 月初，梨园 v1.5.4 已经「能玩、体验超过酒馆」，作者却不满意。`docs/FINDINGS-PI-RETURN.md:30` 记下 9/05 的定调：为了兼容预设把前面搭的东西都拆了，「越来越像第二个酒馆」，「现在的梨园不能再修修补补了」。当时的结构是梨园的 `StageEngine` 自己跑一套 `#agentLoop`，pi 只拿来存会话树，pi 的钩子一个都没用。

<div class="zx-timeline" markdown>

### 2026-09-08 · 回归 pi {: data-kind="拆" }

`1a3142d` 把生成循环交还 pi 的 `session.prompt()`，梨园改成 pi extension（`.liyuan/extensions/roleplay.ts`）挂在 `before_agent_start`、`context`、`tool_call`、`agent_end` 等钩子上；稿纸工具带着版本号回来，没有门禁。

同日 `9985258` 删了默认预设：其中一句「用户主权」的硬边界，让同卡同输入两拍各有 47%、39% 的思考耗在跟它谈判上；删掉后工具调用从 0 次变成 6 次。`2e52067` 再把扮演定义从 `SYSTEM.md` 挪进用户可改的 `APPEND_SYSTEM.md`——用户定性，写在 `SYSTEM.md` 里是「harness 替用户做了『沉浸还是全局』的选择」。

### 2026-10-15 · 第二次回归 {: data-kind="拆" }

60 多本世界书被 agent 用脚本删掉之后定的 `docs/PLAN-AGENT-BACK-TO-PI.md`，根因写的是「门设在表达层，效果发生在效果层」，落地在 `111e7c5`（见[沙箱](agent-mode.md#incident)）。其中「把 system 换回 pi 内建基座」那一刀评估后关闭：原诊断错了，实测收益为零，每拍还要多约 2200 字符。这一轮只动了 agent 和工作模式，扮演拍没动。

</div>

## 铁律之后还留着的张力 { #tension }

铁律管住了新增，没清完存量：

- `<content>` 标签硬编码去重（`src/stage/engine.ts:591`），`5aa31a3` 在 8/14 加的，晚于铁律
- 格式尾巴合并号称不认名字，判断仍靠冻结的 `FOLD_NAME_RE`、`STRIP_NAME_RE`（`src/postprocess.ts:81`）；具体预设的标签名 `w2g`、`catsay` 写死在 `HISTORY_STRIP_BUILTIN`（`src/postprocess.ts:101`）
- 写入门禁用正则匹配用户原话（`src/tools/gate.ts:52`），词表里没有「改 / 修改」，源码注明「已记漏网，不修」——补词就违反铁律三。门禁只在 `creationMode` 为 `ask` 时生效，代码缺省不拦，随包的配置样例写的却是 `ask`
- `ask` 的工具描述里仍写着触发判据（`src/stage/tools.ts:154`），铁律允许把用法写进工具说明书，但仍是 harness 写的话
- 【语言纠正】注入还留着「这是硬性要求，立即纠正」（`src/stage/assemble.ts:544`）

## 谁管什么 { #split }

- **程序**：拼 system 和数据块、扫关键词、工具结果去重、直出代收、第 20 轮撤工具、收笔后调场记、到点压缩
- **模型**：查不查、列不列计划、写多长、何时 `ask`、何时收笔，以及场记账本里写什么
- **用户**：改 `APPEND_SYSTEM.md` 和卡的 `AGENTS.md`，在 `ask` 的岔口拍板
