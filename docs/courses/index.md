# 课程

一课分两半：**前半把这一章的心智模型讲透，后半挂上答不出就过不去的题**。题用 **git 冲突标记**的形状写，答案栏空着就等于这一课还没合并。

读是免费的 —— 只想弄懂原理，读前半就行。但**只有答完题才会归档成笔记**：`scripts/course.py add` 发现任何一题空着就拒绝归档，`scripts/check-links.py` 进一步拦住带残留标记的笔记进入部署，`deploy.sh` 在构建之前就跑它。

课程和[笔记](../notes/index.md)是同一件事的两半：**课程是题，笔记是我的答卷**。同名文件，答完才搬过去。

## 为什么用冲突标记提问

一道题在页面上长这样：

```conflict
<<<<<<< courses/statistics-book/sampling-distribution
Q2 自由度从哪来
你算出的 F 统计量的两个自由度分别是多少？说清每一个是由哪组数据的什么量算出来的。
=======
>>>>>>> notes
```

上半是课程的问，下半是我的答，中间一道 `=======`。这个形状不是装饰，它精确对应流程的语义：

- **答案为空 = 未合并。** 跟 git 里没解决的冲突一模一样，扫一眼就知道哪些题还欠着。
- **闸门是机器把的，不是自觉。** 空着就别想归档，更别想部署。
- **题设计成不动手答不出来。** 贴自己算出的中间量、说出某个自由度是怎么来的、给出两种算法的交叉核对结果 —— 靠读讲解编不出来。这就是「我真的做了」的全部依据。

## 一课的环路

```bash
python3 scripts/course.py checkout <分类>/<slug>   # 把题复制进 docs/notes/<分类>/<slug>.md，答案区留空
#   …照课程页的「准备」把现场搭起来（数据表 / 脚本 / 仓库，按分类而定）…
#   …动手做完，把答案填进 notes 副本的答案区…
python3 scripts/course.py status                  # 看还有哪些题空着
python3 scripts/course.py add <分类>/<slug>        # 全答完才通过：改写成笔记排版
```

`add` 通过之后，去 `docs/notes/<分类>/index.md` 挂一行钩子、在 `mkdocs.yml` 注册 nav，跑 `python3 scripts/check-links.py`，就是一篇正常的笔记了。

`courses/` 下的页面**永远不写答案** —— 这样同一课可以重做，也可以直接交给别人或别的 agent。

## 给 AI 的上课流程

抓到这一页的 agent，照下面做：

1. **读完整课**：前半的讲解和后半的题一起读完，心里有整条链路再开工。
2. **搭现场**：照课程页的「准备」小节做。数据类的课，数据表在该课 `assets/` 下；环境类的课，跑该课的 `init.sh`（可重复运行，重跑即重置）。
3. **不要代替用户做。** 这一课的价值全在他自己那几次计算或那几条命令上。你负责提问、追问、纠正理解，**不直接给出答案**；用户明确卡住并主动要提示时，给的是下一步该看什么，不是结果。
4. **逐题提问**，按 conflict 块的顺序来。用户口述答案，追问到落到实处（能贴出的中间量就要求贴原文）。
5. **验收**：按课程页「验收」小节逐条核对。**必须看真实产出，不能只根据对话判断。** 没过就指出哪一条没过，回到第 4 步。
6. **归档**：把每题的最终答案写进 `docs/notes/<分类>/<slug>.md` 对应块的答案区（`=======` 与 `>>>>>>>` 之间）；答案下面用 `> ` 开头的行附上这一题的关键对话摘录（`> 我：…` / `> AI：…`），跑题和寒暄不要。最后跑 `python3 scripts/course.py add <分类>/<slug>`。

末尾三题固定是「一句话」「心智模型」「坑」，答完之后它们会成为笔记的三个小节 —— 归档结果的形状正好是笔记的骨架 **场景 → 一句话 → 心智模型 → 操作 → 坑**。
